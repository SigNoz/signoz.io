[Python logging](/guides/logging-in-python/) is essential for gathering critical insights about your application's behaviour and efficient debugging. The `logging` module provides multiple features, including the ability to adjust [logging levels](/blog/logging-levels/) dynamically during runtime. This guide shows how to set the logging level from the command line in Python, making your debugging workflow more flexible and efficient.

## Understanding Python Logging Levels

Python logging levels control message severity and visibility, allowing you to categorize and filter log messages effectively.

1. `DEBUG` - Used for getting detailed diagnostic information. Debug-level logging is used during development and debugging.
2. `INFO` - General information confirming the program is working as expected.
3. `WARNING` - Indicates something unexpected occurred. This is the default logging level in Python.
4. `ERROR` - A serious issue that didn't stop the program but needs attention.
5. `CRITICAL` - A severe error indicating the program may be unable to continue running.

## Quick Guide: How to Set Logging Level from Command Line

When running Python scripts in development or production, you often need to configure the logging levels without editing code. Command-line arguments solve this problem by using Python's `argparse` module to dynamically set and adjust the Python log level.

```python:pythonSetLogLevel.py
import argparse
import logging

# Initialize the ArgumentParser object
parser = argparse.ArgumentParser(description="Set the logging level via command line")

# Add a command-line argument to control the log level
parser.add_argument('--log', default='WARNING', help='Set the logging level (DEBUG, INFO, WARNING, ERROR, CRITICAL)')

# Parse the command-line arguments
args = parser.parse_args()

# Configure the logging level based on the parsed argument
logging.basicConfig(level=args.log.upper(), format='%(levelname)s: %(message)s')

# Example logging statements
logging.debug('This is a debug message')    # Will only be logged if level is DEBUG
logging.info('This is an info message')     # Will only be logged if level is INFO or lower
logging.warning('This is a warning message')# Will always be logged by default
```

Explanation:

- ArgumentParser Object: Handles the command-line arguments passed to set log level.
- Logging Argument: The `--log` flag accepts a Python logging level as input with a default value of `WARNING`.
- Configure Logging Level: The `logging.basicConfig()` function sets the logging level based on user input, ensuring messages at that level or higher are logged.


### Common Python Logging Level Arguments

These command-line arguments control Python logging levels for flexible verbosity management:

- `--log=DEBUG` (or `-l DEBUG`): Sets the log level to DEBUG—the most verbose Python logging level with full diagnostic details.
- `--verbose` (or `-v`): Increases verbosity, typically setting logging level to INFO to show more detail.
- `--quiet` (or `-q`): Decreases verbosity, setting logging level to ERROR or CRITICAL, suppressing less severe messages.

These arguments help you adjust the log level flexibly during script execution.

Example:
This example demonstrates multiple ways to set the logging level from the command line:

```python:pythonSetLogLevel.py
import argparse
import logging

# Function to parse command-line arguments
def parse_args():
    parser = argparse.ArgumentParser(description="A script demonstrating logging control.")

    # Adding the --log argument to set a specific logging level
    parser.add_argument('--log', '-l', default='WARNING', help='Set the Python logging level (DEBUG, INFO, WARNING, ERROR, CRITICAL)')

    # Adding the --verbose argument to increase verbosity
    parser.add_argument('--verbose', '-v', action='count', default=0, help='Increase verbosity level')

    # Adding the --quiet argument to decrease verbosity
    parser.add_argument('--quiet', '-q', action='store_true', help='Suppress non-error messages')

    return parser.parse_args()

# Function to configure logging level based on parsed arguments
def configure_logging(args):
    if args.quiet:
        log_level = logging.ERROR  # Set logging to only show errors and critical issues
    elif args.verbose > 0:
        # Increase verbosity based on how many times --verbose (-v) is used
        log_level = max(logging.DEBUG, logging.WARNING - args.verbose * 10)
    else:
        log_level = getattr(logging, args.log.upper(), logging.WARNING)  # Set logging level based on --log argument

    logging.basicConfig(level=log_level, format='%(levelname)s: %(message)s')

# Main function
def main():
    args = parse_args()
    configure_logging(args)

    # Example log messages at different levels
    logging.debug("This is a debug message")
    logging.info("This is an info message")
    logging.warning("This is a warning message")
    logging.error("This is an error message")
    logging.critical("This is a critical message")

if __name__ == "__main__":
    main()
```

### Best Practices for Command-Line Logging Control

When implementing command-line logging level control, follow these practices for robust scripts:

- Use Default Values: Set a sensible default logging level like `WARNING`, to prevent excessive output.
- Clear Help Messages: Provide helpful descriptions for logging-related arguments to guide users.
- Gracefully Handle Invalid Inputs: Ensure your script handles invalid log level inputs without crashing.
- Combine with Other Options: Integrate logging arguments with other command-line options for a better user experience.

Here's how to incorporate these practices when you set the logging level:

```python:pythonSetLogLevel.py
import argparse
import logging

# Function to validate and return the log level
def valid_log_level(level):
    try:
        return logging.getLevelName(level.upper())
    except ValueError:
        raise argparse.ArgumentTypeError(f"Invalid log level: {level}")

# Initialize ArgumentParser
parser = argparse.ArgumentParser(description='Your script description')

# Add logging-related arguments
parser.add_argument('--log', type=valid_log_level, default='WARNING',
                    help='Set the logging level (DEBUG, INFO, WARNING, ERROR, CRITICAL)')
parser.add_argument('--verbose', '-v', action='count', default=0,
                    help='Increase verbosity (can be used multiple times)')
parser.add_argument('--quiet', '-q', action='store_true',
                    help='Suppress all output except errors')

# Parse arguments
args = parser.parse_args()

# Determine logging level based on parsed arguments
if args.quiet:
    log_level = logging.ERROR
elif args.verbose:
    log_level = max(logging.DEBUG, logging.WARNING - args.verbose * 10)
else:
    log_level = args.log

# Configure logging
logging.basicConfig(level=log_level, format='%(levelname)s: %(message)s')

# Your application code here
```

Explanation:

- `valid_log_level` Function: Validates and normalizes the log-level input to ensure it matches one of the predefined levels.
- Command-Line Arguments: The `--log` flag sets the logging level. `--verbose` increases verbosity, and `--quiet` suppresses non-error output.
- Dynamic Log Level Adjustment: The script dynamically adjusts the logging level in the Python application based on user input, offering a flexible and intuitive logging experience.

### Example Usage

- Increase Verbosity: In command-line applications, verbosity refers to the amount of information the script outputs during execution. ## Advanced Techniques for Flexible Logging Control

As applications expand, you may need more advanced logging control. Consider these techniques for enhanced flexibility:

### 1. Using Environment Variables with Command-Line Arguments

Combine environment variables with command-line args to set default logging levels that users can override:

```python
import os

# Set log level from environment variable or fallback to default
log_level = os.environ.get('LOG_LEVEL', 'WARNING')
parser.add_argument('--log', default=log_level, help='Set the logging level')
```

### 2. Implementing Log Level Aliases

Create shortcuts or aliases for logging levels to simplify command-line usage:

```python
def parse_log_level(level):
    aliases = {'d': 'DEBUG', 'i': 'INFO', 'w': 'WARNING', 'e': 'ERROR', 'c': 'CRITICAL'}
    return aliases.get(level.lower(), level.upper())

# Add argument with aliases
parser.add_argument('--log', type=parse_log_level, default='WARNING', help='Set the logging level')
```

### 3. Creating Custom Log Levels

Beyond standard logging levels (DEBUG through CRITICAL), create custom severity levels. Python's logging module comes with five predefined log levels: `DEBUG` (10), `INFO` (20), `WARNING` (30), `ERROR` (40), and `CRITICAL` (50). The numeric values indicate severity, with lower values indicating more detailed information. You can define custom log levels for specific needs, such as a `VERBOSE` level between `DEBUG` and `INFO`:

```python
# Add a custom logging level
logging.addLevelName(15, 'VERBOSE')
# 15 is chosen as it fits between 10 and 20
logging.VERBOSE = 15
logging.verbose = lambda msg, *args, kwargs: logging.log(logging.VERBOSE, msg, *args, kwargs)

# Example usage
logging.verbose('This is a verbose message')
```

The number `15` logically fits between `DEBUG` (10) and `INFO` (20). This placement allows `VERBOSE` messages to display when the log level is set to `VERBOSE` or lower, without overwhelming output with `DEBUG` level details.

### 4. Applying Different Log Levels to Different Modules

Configure different logging levels for various application parts for granular control:

```python
# Set root logger level
root_logger = logging.getLogger()
root_logger.setLevel(args.log)

# Set a specific logging level for a module
module_logger = logging.getLogger('my_module')
module_logger.setLevel(logging.DEBUG)
```

## Debugging with Dynamic Log Levels

Change Python logging levels dynamically at runtime for powerful debugging. Enable debug mode without restarting by adjusting log verbosity based on specific conditions:

```python
import logging

def change_log_level(new_level):
    # Dynamically change the log level
    logging.getLogger().setLevel(new_level)

# Initial log level
logging.info("This won't be displayed initially")

# Change log level during runtime
change_log_level(logging.DEBUG)
logging.debug("This will be displayed after changing the log level")
```

This technique complements command-line approaches, allowing you to adjust logging levels at startup and during execution.

### Tips for Effective Debugging

- Strategic Logging: Use appropriate logging levels to isolate issues. `DEBUG` for development, `INFO` for production monitoring.
- Performance Considerations: Be mindful of performance—excessive logging, especially at lower levels like `DEBUG`, can slow down your application.
- Security: Always avoid logging sensitive information, particularly at verbose levels, to protect user data.

## FAQs

### How do I set a default logging level in Python?

To set a default logging level, use the `logging.basicConfig()` function at the start of your script. This configures the root logger and ensures all log messages at or above the specified level are captured.

```python
import logging

logging.basicConfig(level=logging.WARNING)
```

### Can I dynamically change the logging level at runtime?

Yes, you can dynamically change the logging level at runtime using the `setLevel()` method on a logger. This works alongside command-line configuration and allows you to adjust log verbosity without restarting your application.

```python
import logging

logging.getLogger().setLevel(logging.DEBUG)
```

### What's the difference between using `argparse` and `sys.argv` for logging arguments?

While both `argparse` and `sys.argv` handle command-line arguments, `argparse` offers significant advantages. It provides a robust and user-friendly interface, automatic help message generation, type conversion handling, and input validation. Prefer `argparse` for better user experience and code maintainability.

```python
import argparse

parser = argparse.ArgumentParser()
parser.add_argument('--log', default='WARNING', help='Set the logging level')
args = parser.parse_args()
```

### How can I set different logging levels for different modules?

Create separate loggers for each module and set their logging levels independently. This allows you to control log verbosity per module, which is especially useful in larger applications.

```python
import logging

# Logger for module1
logger1 = logging.getLogger('module1')
logger1.setLevel(logging.INFO)

# Logger for module2
logger2 = logging.getLogger('module2')
logger2.setLevel(logging.DEBUG)
```

In this example, `module1` logs messages at the INFO level and above, while `module2` logs more detailed messages at the DEBUG level and above.
