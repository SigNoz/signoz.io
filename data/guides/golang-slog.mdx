Golang logging is the record of events that occur in an application, providing critical insights into its behaviour, performance, and potential problems. In Golang, the built-in log package helps monitor and debug applications.

However, for more advanced logging needs, Golang offers slog, a powerful [structured logging](/blog/structured-logs/) solution. Compared to the standard log package (log vs. slog), Golang slog provides better data organization and analysis capabilities. This guide will explore features such as Golang log levels and child loggers, along with best practices for using Golang slog to implement structured logging in Golang applications.

## Prerequisites

- <a href="https://go.dev/doc/install" rel="noopener noreferrer nofollow" target="_blank">Golang Installed in your system</a>
- Familiarity with Golang logging and basic Golang structured logging concepts

## Quick Guide: How to use Golang slog for Structured Logging?

### What is slog?

Golang slog is a logging package introduced in version `1.21` of Golang. Compared to traditional Golang logging approaches (log vs slog), it brings Golang structured logging capabilities into your application, enhancing the way logs are recorded and analyzed.

### Basic Usage

To implement Golang slog in your application for structured Golang logging, import the `log/slog` package.

```go:main.go
package main

import (
    "log/slog"
)

func main() {
    slog.Info("SigNoz", "Message", "Golang slog is best for structured logging")
}
```

The above code demonstrates Golang slog basic usage. This Golang structured logging approach generates log entries with timestamps, severity levels, and key-value attributes.

- Timestamps
- Message
- Severity Level
- Key-Value paired attributes

Output of the above code:

```bash:Output
2024/06/23 01:33:42 INFO SigNoz Message="Golang slog is best for structured logging"
```

Syntax of the output:

```bash
Timestamps Severity-Level Message Key=Value
```

### What is Golang Structured Logging?

Golang structured logging is a technique where data is formatted for easy searching and processing. When comparing log vs slog, the key difference is that Golang slog provides native structured logging support. JSON is the standard format for Golang structured logging. It is best practice to provide structured logging using a logging framework integrated with a [log management](/log-management/) system that supports custom fields.

### Why Use Golang Structured Logging?

Golang structured logging offers several advantages over traditional text-based logging:

- Ease of Searching and Filtering: Golang structured logging with key-value pairs makes Golang logging more efficient for troubleshooting and analysis.
- Better Integration: Structured logs are machine-readable, making it easier to integrate with log management systems and [log analysis tools](/comparisons/log-analysis-tools/).
- Improved Analytics: With structured logs, you can perform more sophisticated analytics, enabling better insights into your application's behaviour and performance.

Example of structured logging:

```json
{
  "time": "2024-06-25T03:02:16.291247+05:30",
  "level": "INFO",
  "msg": "slog Groups",
  "Usage": {
    "Item1": "random string",
    "Item2": 453666601985459141,
    "Item3": 7914595825068479671
  }
}
```

The above structured logging output, when converted into text-based logging, looks like the example below:

```bash:Output
2024-06-25T03:02:16.291247+05:30 - INFO - slog Groups - Item1: random string, Item2: 453666601985459141, Item3: 7914595825068479671
```

Let's dive deep into the slog libraries and explore the advanced features of Golang slog.

## Important Components in slog

To effectively use Golang slog in production for logging, it's essential to understand its three main components: `Logger`, `Records`, and `Handlers`.

- Loggers: A logger is the primary interface for Golang slog operations. When implementing Golang logging with slog, it provides various methods (such as `Info()` and `Error()`) for reporting events. When you log an event, you use these methods provided by the logger.
- Records: When a logger method is called, it creates a record. A record's sole purpose is to store the data required to generate a log entry.
- Handlers: Handlers are responsible for processing log records, generating the final log output, and determining the log destination (such as a file or console). slog includes two built-in handlers: `TextHandler` and `JSONHandler`.

We will discuss more on this in the latter part of the article.

## Golang slog Levels: Managing Log Severity

In Golang slog, log levels determine which messages are emitted. Understanding them is critical for effective debug logging in production. These levels help determine which logs are emitted based on their importance, which can be critical in both development and production environments. Here's a breakdown of the typical Golang log levels provided by slog, which are similar to those in many other logging libraries:

- Debug: Golang debug logging provides detailed diagnostic information. Use it to diagnose complex issues during development. Debug logging is usually enabled only in development settings.
Use Case: Diagnosing a complex issue by logging detailed information about the application's state.
- Info: Provides general information about the application's operations, offering insights into its normal functioning. Essential for standard Golang logging operations.
Use Case: Logging the successful completion of an operation or regular status updates.
- Warn: Indicates that something unexpected happened or there might be a potential issue (e.g., 'disk space low'). The application continues to work as expected.
Use Case: Alerting about deprecated API usage or low disk space warnings.
- Error: Represents serious issues where the application has encountered a problem and cannot perform some functions. These Golang log levels help categorize issues by severity in your Golang logging strategy.
Use Case: Logging errors that prevent a function from executing properly, such as database connection failures.

Slog is designed to be modular and extensible, allowing users to create custom levels as needed. [Logging levels]((/blog/logging-levels/)) help control log output based on the severity of the information, which is especially useful in production environments to avoid log flooding while maintaining clear and informative logs.

You can see below is an example that demonstrates how to use these logging levels in a Golang application:

```go:main.go
package main

import (
    "log/slog"
    "os"
)

func main() {
    // Create a new logger with a JSON handler
    logger := slog.New(slog.NewJSONHandler(os.Stderr, nil))
    slog.SetDefault(logger)

    slog.Debug("Debug Level", "Detailed information for debugging")
    slog.Info("Info Level", "General operational information")
    slog.Warn("Warn Level", "Potential issue detected")
    slog.Error("Error Level", "A serious issue occurred")
}
```

## Creating Logger with Handler

Golang slog provides two handler types for structured logging: `TextHandler` and `JSONHandler`. These handlers determine the format and destination of the log output.

### TextHandler

`TextHandler` enables Golang structured logging in a human-readable text format. This Golang logging approach is useful during development. You can create a new logger using `TextHandler` with the following code:

```go:main.go
package main

import (
    "log/slog"
    "os"
)

func main() {
    // Create a logger with TextHandler
    logger := slog.New(slog.NewTextHandler(os.Stderr, nil))
    logger.Info("TextHandler Example", "Content", "Logging in text format")
}
```

The `New` keyword creates a Golang slog Logger instance for structured logging with a nil context. The output of logs received using `TextHandler` is in a `key=value` sequence, making it more structured and easier to understand.

Example Output:

```bash:Output
time=2024-06-23T01:33:13.531+05:30 level=INFO msg=SigNoz Content="Golang slog is best for structured logging"
```

In the output above, `TextHandler` maps the keys (time, level, msg, Content) to their respective values.

### JSONHandler

`JSONHandler` enables Golang structured logging as JSON objects, making Golang logging machine-readable. You can create a new logger using `JSONHandler` with the following code:

```go:main.go
package main

import (
    "log/slog"
    "os"
)

func main() {
    // Create a logger with JSONHandler
    logger := slog.New(slog.NewJSONHandler(os.Stderr, nil))
    logger.Info("JSONHandler Example", "Content", "Logging in JSON format")
}
```

Example Output:

```json:Output
{
  "time": "2024-06-23T01:32:14.715901+05:30",
  "level": "INFO",
  "msg": "SigNoz",
  "Content": "Golang slog is best for structured logging"
}
```

This Golang slog handler is ideal for logging in production, where log management systems process structured logs. When considering log vs slog for production, Golang slog's JSON output provides better tooling integration. It is frequently used in production settings where logs are gathered and analysed by platforms such as [SigNoz](https://signoz.io/), [Splunk](/blog/splunk-alternatives/), the ELK stack, and others.

## Setting Default Logger in slog

Each method in Golang's slog package provides a top-level function for simplified Golang logging that uses the default logger. Let's try to understand this with an example:

`slog.Info()` is called by the top-level function by a default logger. The default handler formats the log record's message, time, level, and attributes as a string and passes it to the log package.

The `SetDefault` function configures the default Golang slog logger for all Golang log levels (`INFO`, `DEBUG`, `WARN`, `ERROR`). It establishes a new default logger that these levels will utilize for logging operations.

Using the code below, we will set a default logger using the SetDefault function:

```go:main.go
package main

import (
 "log/slog"
 "os"
)

func main() {
 logger := slog.New(slog.NewJSONHandler(os.Stderr, nil))
 slog.SetDefault(logger)

 slog.Info("SigNoz", "Content", "Golang slog is best for structured logging")
 slog.Warn("Article", "Read", "Till the end")
}
```

```json:Output
{

   "level":"INFO",
   "msg":"SigNoz",
   "Content":"Golang slog is best for structured logging"
}{
   "time":"2024-06-23T01:30:03.174464+05:30",
   "level":"WARN",
   "msg":"Article",
   "Read":"Till the end"
}
```

## slog Customization

Further customization can be done in the slog logging components to produce log output in the desired format. This helps in customizing the logs output to make it suitable for a specific use case and more flexible:

### Levels

In Golang logging, you should log messages at specific Golang log levels. Golang debug logging is typically enabled only during development, while `INFO` and above run in production. A typical setup involves logging messages at the `INFO` or higher tier and delaying debug logging until necessary. To configure Golang log levels dynamically in your Golang slog, you can use the `HandlerOptions` type as shown in the code below:

```go:main.go
package main

import (
 "log/slog"
 "os"
)

func main() {
 logger := slog.New(slog.NewJSONHandler(os.Stderr,
        &slog.HandlerOptions{Level: slog.LevelDebug}))
 slog.SetDefault(logger)

 slog.Info("SigNoz", "Content", "Golang slog is best for structured logging")
 slog.Warn("Article", "Read", "Till the end")
 slog.Debug("Debug Level", "Working", "True")
}
```

```json:Output
{
   "time":"2024-06-23T02:22:18.587372+05:30",
   "level":"INFO",
   "msg":"SigNoz",
   "Content":"Golang slog is best for structured logging"
}{
   "time":"2024-06-23T02:22:18.587867+05:30",
   "level":"WARN",
   "msg":"Article",
   "Read":"Till the end"
}{
   "time":"2024-06-23T02:22:18.587874+05:30",
   "level":"DEBUG",
   "msg":"Debug Level",
   "Working":"True"
}
```

The above level-setting method keeps the handler at that level for the duration of its existence. You must use the `LevelVar` type, as shown below, if you want dynamic variation in the minimum level:

```go:main.go
package main

import (
 "log/slog"
 "os"
)

func main() {
 var logLevel = new(slog.LevelVar)

 logger := slog.NewJSONHandler(os.Stderr,
        &slog.HandlerOptions{Level: logLevel})
 slog.SetDefault(slog.New(logger))

 logLevel.Set(slog.LevelDebug)

 slog.Info("SigNoz", "Content", "Golang slog is best for structured logging")
 slog.Warn("Article", "Read", "Till the end")
 slog.Debug("Debug Level", "Working", "True")
}
```

### Child Logger

A child logger extends Golang slog functionality for contextual structured logging. It is a derived logger that inherits configuration from a parent logger while potentially adding its own specific settings or contextual information. Creating child loggers is a common practice in structured logging, which enhances log management and debugging by embedding additional, relevant data directly into log messages.

Benefits of using a child logger

- Automatic inclusion of contextual information in Golang logging operations specific to different parts of an application.
- Reduces redundancy in log entries.
- Enhances traceability.
- Allows logs to be segmented according to their source or nature.
- Facilitates easier filtering and searching based on embedded context, such as module names or version numbers.

The code below demonstrates how you can implement a child logger in your Golang application:

```go:main.go
package main

import (
 "log/slog"
 "os"
 "runtime/debug"
)

func main() {
 handler := slog.NewJSONHandler(os.Stderr, &slog.HandlerOptions{
  Level: new(slog.LevelVar),
 })

 logger := slog.New(handler)

 buildInfo, _ := debug.ReadBuildInfo()

 child := logger.With(
  slog.Group("program_info",
   slog.Int("pid", os.Getpid()),
   slog.String("go_version", buildInfo.GoVersion),
  ),
 )

 child.Info("SigNoz", "Content", "Golang slog is best for structured logging")
 child.Warn("Article", "Read", "Till the end")
 child.Debug("Debug Level", "Working", "True")
}
```

```json:Output
      "pid":8252,

   },
   "Content":"Golang slog is best for structured logging"
}{
```

### Groups

Golang's slog becomes more manageable with structured logging using groups. The slog group's function helps us overcome complexity by allowing us to group related Golang logging attributes under a single unit. `TextHandler` uses a dot to divide the group and attribute names, with the group name serving as the key. On the other hand, `JSONHandler` handles each group as a distinct JSON object.

slog also enables multi-attribute grouping, but the results vary depending on the Handler used. We may group relevant fields together under a single key, choose a group name, and then stack the characteristics that make sense for that group:

```go:main.go
package main

import (
 "log/slog"
 "math/rand"
 "os"
)

func main() {
 var logLevel = new(slog.LevelVar)

 logger := slog.NewJSONHandler(os.Stderr,
        &slog.HandlerOptions{Level: logLevel})
 slog.SetDefault(slog.New(logger))

 logLevel.Set(slog.LevelDebug)

 slog.Info("slog Groups",
  slog.Group("Usage",
   slog.String("Item1", "random string"),
   slog.Int("Item2", rand.Int()),
   slog.Int("Item3", rand.Int()),
  ),
 )
}
```

### Context Integration

Golang slog allows the integration of function context into log statements. This capability is particularly useful as it enables handlers to understand the circumstances surrounding each log event.

Both `Logger.Log` and `Logger.LogAttrs` methods accept a context as their initial argument, aligning with their respective top-level function. Although the use of context is not mandatory for the top-level functions and convenience methods on `Logger` (such as `Info`), there are specific versions of these functions that incorporate context when needed.

For Example:

```go:main.go
package main

import (
 "context"
 "log/slog"
 "math/rand"
 "os"
)

func main() {
 var logLevel = new(slog.LevelVar)

 logger := slog.NewJSONHandler(os.Stderr,
        &slog.HandlerOptions{Level: logLevel})
 slog.SetDefault(slog.New(logger))

 logLevel.Set(slog.LevelDebug)
 ctx := context.WithValue(context.Background(), "serial_id", "1")

 slog.InfoContext(ctx, "slog Groups",
  slog.Group("Usage",
   slog.String("Item1", "random string"),
   slog.Int("Item2", rand.Int()),
   slog.Int("Item3", rand.Int()),
  ),
 )
}
```

The `ctx` variable receives a `serial_id`, which is then supplied to the `InfoContext` function. Nevertheless, the serial_id field is absent from the log when the program is executed:

### Step 2: Building a Sample Application

```go:main.go
package main

import (
 "context"
 "fmt"
 "log/slog"
 "net/http"
 "os"
)

func main() {
 logFile, err := os.OpenFile("application.log", os.O_APPEND|os.O_CREATE|os.O_WRONLY, 0644)
 if err != nil {
  panic(err)
 }
 defer logFile.Close()

 var logLevel = new(slog.LevelVar)

 logger := slog.NewJSONHandler(logFile, &slog.HandlerOptions{Level: logLevel})
 slog.SetDefault(slog.New(logger))

 logLevel.Set(slog.LevelDebug)

 http.HandleFunc("/", handleIndex)
 http.HandleFunc("/log", handleLog)
 http.HandleFunc("/data", handleData)
 http.HandleFunc("/error", handleError)

 fmt.Println("Server starting on <http://localhost:8080>")
 if err := http.ListenAndServe(":8080", nil); err != nil {
  panic(err)
 }
}

func handleIndex(w http.ResponseWriter, r *http.Request) {
 ctx := context.Background()
 slog.InfoContext(ctx, "Accessing index page", slog.String("method", r.Method))
 fmt.Fprintln(w, "Welcome to the Go Application!")
}

func handleLog(w http.ResponseWriter, r *http.Request) {
 ctx := context.WithValue(r.Context(), "serial_id", "1")
 switch r.Method {
 case "GET":
  slog.InfoContext(ctx, "Handled GET request on /log",
   slog.Group("Request Info",
    slog.String("Method", "GET"),
    slog.String("Path", r.URL.Path),
   ),
  )
  fmt.Fprintln(w, "Received a GET request at /log.")
 case "POST":
  slog.InfoContext(ctx, "Handled POST request on /log",
   slog.Group("Request Info",
    slog.String("Method", "POST"),
    slog.String("Path", r.URL.Path),
   ),
  )
  fmt.Fprintln(w, "Received a POST request at /log.")
 default:
  http.Error(w, "Unsupported HTTP method", http.StatusMethodNotAllowed)
 }
}

func handleData(w http.ResponseWriter, r *http.Request) {
 ctx := context.WithValue(r.Context(), "request_id", fmt.Sprintf("%d", os.Getpid()))
 slog.InfoContext(ctx, "Data endpoint hit",
  slog.String("method", r.Method),
  slog.String("endpoint", "/data"),
 )
 fmt.Fprintln(w, "This is the data endpoint. Method used:", r.Method)
}

func handleError(w http.ResponseWriter, r *http.Request) {
 ctx := context.WithValue(r.Context(), "error_id", "error123")
 slog.ErrorContext(ctx, "Error endpoint accessed",
  slog.String("method", r.Method),
  slog.String("endpoint", "/error"),
 )
 http.Error(w, "You have reached the error endpoint", http.StatusInternalServerError)
}
```

The code above demonstrates Golang's slog in an HTTP server, with proper log levels and debug logging enabled. This Golang structured logging approach provides production-ready logging. The server has several routes (`/`, `/log`, `/data`, `/error`), each handled by a different handler function that simulates various server operations. These functions log relevant information using slog, illustrating how to incorporate contextual logging in a real-world application. For example, the `handleLog` function logs different messages based on the `HTTP` method (GET or POST), and the `handleError` function simulates [error logging](/guides/error-log/) when the error endpoint is accessed.

The server is set to listen on port 8080, and the application will panic and shut down if it encounters an error starting the server. This example provides a practical illustration of integrating logging into a web service, which can help monitor the application's behaviour and troubleshoot issues.

## Advantages of using Golang slog over Traditional Logging

- **Structured Logging:** Golang slog supports Golang structured logging, making logs easier to parse. When comparing log vs slog, Golang's slog wins for modern Golang logging needs. This is especially helpful for contemporary logging systems that compile and examine log information. Key-value pairs represent log data. As a result, logs are more straightforward to search, process, and analyze than unstructured logs that contain free-form text. Because structured logs are machine-readable, integrating them with log analysis tools is made simpler.
- **Contextual Logging:** Golang slog enables rich contextual logging with request/user IDs. This Golang structured logging capability improves troubleshooting in complex systems.
