Python's logging system is a reliable tool for tracking errors, recording events, and debugging your code. The default logging formatter controls how your log messages look, and understanding Python's default logging format is one of the first steps toward writing better logs. Once you know how the default log formatter works, you can decide when to use it and when to build something more detailed.

## Understanding Python's Logging System

The logging module is a built-in Python library that gives you a structured way to create log messages in your applications. Unlike `print()` statements, it supports logging levels, multiple output destinations, and configurable formatting.

The module has four main components:

- Loggers: The entry points for logging in your application. Each logger captures messages and routes them to one or more handlers.
- Handlers: These determine where log messages end up. `StreamHandler` sends output to the console, `FileHandler` writes to a file. A single logger can have multiple handlers pointing at different destinations.
- Formatters: A log formatter controls the layout and content of each message. Every handler can have its own formatter.
- Levels: In Python, the default [logging level](/blog/logging-levels/) is `WARNING`, which means that `DEBUG` and `INFO` messages are silently dropped unless you explicitly lower the threshold. The five standard levels are `DEBUG`, `INFO`, `WARNING`, `ERROR`, and `CRITICAL`. They let you filter noise and focus on what matters.

## What is a Logging Formatter in Python?

A logging formatter defines the structure of every log line your application produces. It acts as a template that organizes:

1. Timestamps - the exact moment the event happened.
2. Log Level - severity indicators like `DEBUG`, `INFO`, or `WARNING`.
3. Message Content - the text of the log message itself.

Log Formatters work with handlers in a way that handlers select the destination for the log (such as a file or the console), while formatters set the log format. You can adjust your logging configuration to meet your requirements thanks to this division.

### Example of a Simple Python Logging Formatter

Let’s see how a basic log formatter works:

```python:main.py
import logging

# Set up a basic logger
logger = logging.getLogger(__name__)
logger.setLevel(logging.INFO)

# Create a handler to output logs to the console
console_handler = logging.StreamHandler()

# Define a basic formatter
formatter = logging.Formatter('%(asctime)s - %(levelname)s - %(message)s')

# Add the formatter to the handler
console_handler.setFormatter(formatter)

# Add the handler to the logger
logger.addHandler(console_handler)

# Log a simple message
logger.info("This is a sample log message.")
```

```bash:Output
2024-09-06 21:40:30,395 - INFO - This is a sample log message.
```

Explanation:

- `%(asctime)s`: Inserts the timestamp when the log message is recorded.
- `%(levelname)s`: Displays the log level (`INFO`, `DEBUG`, etc.).
- `%(message)s`: Outputs the actual log message.

## Python's Default Logging Formatter Explained

The Python logging default format is minimal by design. If you don't assign a specific format string, Python falls back to:

```python
"%(message)s"
```

This default format string outputs only the message content. It works fine for throwaway scripts, but it strips away the context you need for anything more involved.

### Breakdown of the Default Format String

- `%`: Marks the start of a placeholder, telling Python to substitute a value.
- `(message)`: Refers to the log message content itself.
- `s`: Specifies that the placeholder should be formatted as a string.

This standard log format is efficient when only the message matters. In practice, though, most applications need more: a timestamp to know when something happened, a log level to know how serious it was, and a source to know where it came from.

## Default Formatter Behaviour in Different Scenarios

The behaviour of the Python logging default format changes depending on how you configure the module. Here are the key scenarios:

### 1. Using `logging.basicConfig()`

The `logging.basicConfig()` function provides a simple way to configure logging with minimal code. If you don’t specify any formatting options, it applies a default format with more information than the bare `"%(message)s"` format. Specifically, it adds the log level and the logger name.

Example:

```python:main.py
import logging

logging.basicConfig()  # Configuring logging with default settings
logging.warning("This is a warning")
```

```bash:Output
WARNING:root:This is a warning
```

Explanation:

- `WARNING`: The log level, indicating severity.
- `root`: The default logger name. Since we didn't create a named logger, Python falls back to `root`.
- `This is a warning`: The actual message.

The Python logging basicConfig format uses the pattern `%(levelname)s:%(name)s:%(message)s` when you don't pass an explicit `format` argument.

### 2. Using StreamHandler

When you manually create a `StreamHandler` without attaching a formatter, Python uses the most minimal format possible:

```python:main.py
import logging
import sys

handler = logging.StreamHandler(sys.stdout)  # Output logs to stdout
logger = logging.getLogger()
logger.addHandler(handler)

logger.warning("This is a warning")
```

```bash:Output
This is a warning
```

Explanation: In this case, only the log message is output without any additional context, such as the log level or logger name. This is the bare-bones logging format where Python defaults to `"%(message)s"`.

### 3. Behaviour Across Python Versions

Python's default logging behaviour has stayed consistent across recent versions. The standard log format hasn't changed, but a few quality-of-life improvements have been added over time.

**Python 3.8** added support for f-string formatting in log messages:

```python
# Python 3.8+ (Supports f-strings in log messages)
import logging

name = "Aadyaa"
logging.basicConfig(level=logging.INFO)
logging.info(f"User {name} has logged in.")
```

**Python 3.9** improved handling of dictionaries within log messages:

```python
# Python 3.9+
user_info = {"name": "Aadyaa", "action": "login"}
logging.info("User details: %(name)s has %(action)s", user_info)
```

Across all these versions, the default formatter remains `'%(message)s'` when no log formatter is explicitly set.

## Why You Might Want to Customize the Formatter

The default formatter works for small scripts, but it falls short once your application handles real traffic. Without timestamps, module names, or severity indicators, you are left guessing when something went wrong and where.

Customizing the logging formatter can provide the following benefits:

1. Better Debugging: Timestamps and severity levels let you pinpoint exactly when and how a problem occurred.
2. Detailed Log Tracking: Adding module or function names helps trace issues across a large codebase.
3. Easier Maintenance: Well-formatted logs let teams diagnose production issues faster.

## How to Customize Python's Logging Formatter

While the Python logging default formatter handles the basics, most real applications need a Python logging custom formatter with richer context. Adding timestamps, log levels, and module names makes your logs far more useful for troubleshooting.

Example:

```python:main.py
import logging

# Create a custom formatter with multiple log fields
formatter = logging.Formatter('%(asctime)s - %(name)s - %(levelname)s - %(message)s')

# Create a StreamHandler and set the custom formatter
handler = logging.StreamHandler()
handler.setFormatter(formatter)

# Create a logger, attach the handler to it
logger = logging.getLogger(__name__)
logger.addHandler(handler)

# Log a warning message
logger.warning("This is a warning message")
```

```bash:Output
2024-09-06 21:41:44,815 - __main__ - WARNING - This is a warning message
```

Explanation:

- `%(asctime)s`: Inserts the timestamp (e.g., "2024-09-06 21:41:44,815").
- `%(name)s`: The logger name - `__main__` here since we used `__name__`.
- `%(levelname)s`: The log level, `WARNING` in this case.
- `%(message)s`: The message text itself.

## Advanced Logging Formatter Techniques

As your logging requirements evolve, you may need to use advanced formatting approaches. Python's logging module offers numerous techniques to increase the capability of its formatters.

### 1. Using `LogRecord` Attributes

`LogRecord` classes in Python's logging system store precise information about each log entry. You can use attributes in your formatter to include more specific information, such as the filename, line number, or function name from which the log was generated.

Example of how to include the filename and line number in your log output:

```python:main.py
import logging

formatter = logging.Formatter('%(asctime)s - %(filename)s:%(lineno)d - %(levelname)s - %(message)s')

handler = logging.StreamHandler()
handler.setFormatter(formatter)

logger = logging.getLogger(__name__)
logger.addHandler(handler)

logger.error("This is an error message")
```

```bash:Output
2024-09-06 21:42:22,170 - test.py:11 - ERROR - This is an error message
```

Explanation:

- `%(filename)s`: It inserts the name of the file where the log was generated.
- `%(lineno)d`: It adds the line number in the code where the log was triggered.

### 2. Creating Custom Formatter Classes

You can create your own `Formatter` class by subclassing `logging.Formatter` for even more control over how logs are formatted. This allows you to customize log formatting based on specific conditions, such as the log level or message content.

For example, you might want to mark error logs with a special prefix to make them stand out:

```python:main.py
import logging

# Create a custom formatter class
class CustomFormatter(logging.Formatter):
    def format(self, record):
        # Add "URGENT:" prefix to error-level logs
        if record.levelno == logging.ERROR:
            record.msg = f"URGENT: {record.msg}"
        return super().format(record)

# Apply the custom formatter
formatter = CustomFormatter('%(asctime)s - %(levelname)s - %(message)s')
handler = logging.StreamHandler()
handler.setFormatter(formatter)

logger = logging.getLogger(__name__)
logger.addHandler(handler)

logger.error("This is an error")
```

```bash:Output
2024-09-06 21:42:42,931 - ERROR - URGENT: This is an error
```

### 3. Handling Multi-Line Log Messages

Some log messages may span numerous lines, particularly when logging stack traces or complex data. Custom formatters can be created to handle multi-line messages gracefully while keeping them easy to read.

```python:main.py
import logging

# Create a custom formatter with multi-line message support
formatter = logging.Formatter('%(asctime)s - %(levelname)s\n%(message)s\n')

# Create and configure a handler
handler = logging.StreamHandler()
handler.setFormatter(formatter)

# Create a logger and set the logging level to INFO
logger = logging.getLogger(__name__)
logger.setLevel(logging.INFO)
logger.addHandler(handler)

# Use the logger
logger.info("This is a multi-line log message\nLine 2 of the message")
```

```bash:Output
2024-09-06 21:44:22,653 - INFO
This is a multi-line log message
Line 2 of the message
```

Explanation: This style of logging isolates log metadata (timestamp and log level) from message content, making multi-line logs easier to read visually.

### 4. Formatting for Different Destinations

In some cases, you might want to send logs to multiple destinations (for example, a file and the console) and format them differently for each. For example, you may want more thorough logs written to a file, but console logs can be more concise.

```python:main.py
import logging

# Create formatters: simpler for console, detailed for file
console_formatter = logging.Formatter('%(levelname)s: %(message)s')
file_formatter = logging.Formatter('%(asctime)s - %(name)s - %(levelname)s - %(message)s')

# Set up console handler and assign the console formatter
console_handler = logging.StreamHandler()
console_handler.setFormatter(console_formatter)

# Set up file handler and assign the file formatter
file_handler = logging.FileHandler('app.log')
file_handler.setFormatter(file_formatter)

# Create a logger and set its level to INFO
logger = logging.getLogger(__name__)
logger.setLevel(logging.INFO)

# Add both handlers to the logger
logger.addHandler(console_handler)
logger.addHandler(file_handler)

# Log an INFO message that will be output to both console and file
logger.info("This log goes to both console and file")
```

Explanation: The console output will be basic and clear. However, the log saved to the file will include more detailed information, such as timestamps and logger names.

Output (on the console):

```bash:Output
INFO: This log goes to both console and file
```

Output (in the `app.log` file):

```text:Output
2024-09-06 21:47:19,616 - __main__ - INFO - This log goes to both console and file
```

The console gets a clean, readable format. The file captures timestamps, the logger name, and the level.

## FAQs

### How do I change the default logging format in Python?

Use `logging.basicConfig()` with a custom format string:

```python
import logging
logging.basicConfig(format='%(asctime)s - %(levelname)s - %(message)s', level=logging.INFO)
```

This overrides Python's default logging format and applies your custom pattern to all subsequent log calls.

### Can I use multiple formatters in the same Python application?

Yes. Attach a different Python logging formatter to each handler. For example, one formatter for console output and another for file output.

### What is the distinction between a formatter and a handler in Python logging?

A Formatter specifies how the log message is organized (for example, whether it contains timestamps or log levels). A Handler, on the other hand, controls where the log message is sent (e.g., console, file, or an external service such as SigNoz).

### How can I add timestamps to my log messages?

Include the `%(asctime)s` attribute in your format string:

```python
formatter = logging.Formatter('%(asctime)s - %(levelname)s - %(message)s')
```

### How do I log exceptions in Python?

Use `logger.exception()` inside an `except` block. It logs the message at `ERROR` level and automatically appends the full traceback:

```python
import logging

logger = logging.getLogger(__name__)

try:
    1 / 0
except ZeroDivisionError:
    logger.exception("An error occurred")
```

### Why the Default Logging Formatter Is Minimal

By default, the built-in default logging formatter is meant to be lightweight. It makes it quick and simple to start logging messages in small applications or scripts because it enables basic logging without any additional configuration. However, it allows for customisation, so developers may simply improve their logs when apps get more complicated.
