You can investigate logs in plain English through Noz, the assistant inside SigNoz Cloud, when it is enabled for your workspace. If you prefer your own assistant, connect it through the SigNoz MCP server so it can query logs already collected in SigNoz Cloud.

## Choose where to ask

With [Noz](https://signoz.io/docs/ai/noz/), open **Noz** in your workspace and enter a question in **Ask anything**. This route works inside SigNoz Cloud, so you do not need a separate assistant or MCP configuration. Your services must already [send their logs](https://signoz.io/docs/logs-management/send-logs-to-signoz/) to the workspace.

For an external assistant, the [SigNoz MCP server](https://signoz.io/docs/ai/signoz-mcp-server/) provides tools to search your logs. Model Context Protocol (MCP) lets a compatible assistant call those tools. Connect your client to the hosted server for your SigNoz Cloud region and authenticate with your workspace URL and a [service account](https://signoz.io/docs/manage/administrator-guide/iam/service-accounts/) API key. For a read-only investigation, use a read-only role because MCP also exposes tools that can change resources. The setup guide covers compatible clients and the separate Self-Hosted SigNoz setup.

## Ask about one failure

For example, we created logs for an example checkout service called `checkout-plain-english`, including successful payments and payment failures. Its timeout records have ERROR severity and the message **Payment timeout**. After sending these example logs to SigNoz Cloud, we gave Noz the service name and a fixed time range, then asked it to find the timeouts.

We added `event.id` to identify each example log. In your question, request an identifier already present in your logs, or omit that part.

```text
Show ERROR logs whose message contains "Payment timeout".
Return timestamps, messages, event.id values and the exact query or tool filters used.
```

Noz returned two matching records with their timestamps, messages and event IDs, as shown below.

You can start with a question like this without writing query syntax. Give Noz or your connected assistant the service name, failure symptom and time range, and ask for the records behind its answer.

## Check the records behind the answer

We checked Noz's result in [Logs Explorer](https://signoz.io/docs/userguide/logs_query_builder/) using the same service, time range, severity and message filters. The two records matched Noz's timestamps and messages, and a separate count query also returned two.

For your investigation, open a matching log and compare its timestamp and message with the assistant's answer. A timeout message shows what the application recorded; it does not establish why the payment timed out. If no records match, check collection, the stored service name and the time range. An assistant cannot retrieve logs that were never collected or are no longer retained.

See [natural-language log exploration](https://signoz.io/docs/ai/use-cases/natural-language-log-exploration/) for more questions.
