You can investigate an incident in [SigNoz Cloud](https://signoz.io/log-management/) by collecting application and cloud logs, then comparing records from the same time and resources in [Logs Explorer](https://signoz.io/docs/userguide/logs_query_builder/). If your application logs the provider request ID and the cloud record contains it too, that ID can help you find the corresponding call.

## Follow one failed upload

For example, a checkout service saves an order receipt in Amazon S3 after accepting payment. If S3 rejects the upload, the checkout can return a server error even though payment succeeded. We wrote example application and AWS CloudTrail-format records to show how to investigate this failure.

In Logs Explorer, find the checkout error and note the request IDs and available resource details. Search for the application request ID and the AWS request ID across both sources, then order the results by time. In our example, four records show the payment being accepted, an `AccessDenied` response, the application's upload error and its HTTP 500 response.

Compare details such as the account, region, bucket and object before treating records as related. In this example, the matching records narrow the investigation to the rejected upload, but `AccessDenied` alone does not identify the permission or policy responsible.

If an ID is missing, use the available resource details and time to find candidates. A close timestamp alone does not establish a connection. Check that fields used to filter by account or environment exist in both sources and use matching values. Remove service or severity filters if they exclude a relevant cloud record. Also allow for differences between event and arrival times; CloudTrail's <a href="https://docs.aws.amazon.com/awscloudtrail/latest/userguide/cloudtrail-event-reference-record-contents.html" target="_blank" rel="noopener noreferrer nofollow">`eventTime`</a> records when AWS completed the request.

The investigation covers logs that SigNoz Cloud received and still retains. For setup, see the [application log collection methods](https://signoz.io/docs/logs-management/send-logs/collection-methods/). For AWS, enable the required events, <a href="https://docs.aws.amazon.com/awscloudtrail/latest/userguide/send-cloudtrail-events-to-cloudwatch-logs.html" target="_blank" rel="noopener noreferrer nofollow">send them to CloudWatch Logs</a>, and follow the [CloudWatch collection guide](https://signoz.io/docs/userguide/send-cloudwatch-logs-to-signoz/). AWS does not enable <a href="https://docs.aws.amazon.com/awscloudtrail/latest/userguide/logging-data-events-with-cloudtrail.html" target="_blank" rel="noopener noreferrer nofollow">S3 data events</a> by default.
