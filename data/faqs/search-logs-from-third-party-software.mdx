Yes. An OpenTelemetry Collector can read the application's existing log files and send them to SigNoz Cloud without changes to the application, as long as it has access to those files. Once the logs arrive, you can search their text or extract values such as response status into fields for more precise filtering.

The Collector uses its `filelog` receiver to read the files. The [file collection guide](https://signoz.io/docs/userguide/collect_logs_from_file/) explains how to set it up, including file access and container mounts.

## Find a failed request

For example, take a reporting application whose web server writes a log for each request. When a request to `/report` receives an HTTP `503` response, the log records that the service was unavailable.

To find these failures by status, you can use a regular expression (regex) parser to match the log text and extract the status into a separate field while keeping the original message. In this example, the Collector labels the logs `third-party-web-example`, so you can narrow the search to this application. In [Logs Explorer](https://signoz.io/docs/userguide/logs_query_builder/), filtering for that service and status `503` finds the failed request.

You can extract fields like the status in the Collector before it sends the logs, or use [Logs Pipelines](https://signoz.io/docs/logs-pipelines/introduction/) in SigNoz Cloud to process them before storage. The [regex parser guide](https://signoz.io/docs/logs-pipelines/guides/regex-parser/) shows how to extract fields from text logs. If your application writes JSON logs instead, the [JSON parser guide](https://signoz.io/docs/logs-pipelines/guides/json/) shows how to extract values into attributes you can filter.
