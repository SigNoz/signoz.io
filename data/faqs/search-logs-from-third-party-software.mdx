Yes. If an OpenTelemetry Collector can read the application's existing log files, it can send them to SigNoz Cloud without changes to the application. You can search the log text in Logs Explorer and extract fields when you want to filter by a value such as a response status.

The Collector's `filelog` receiver reads the files and forwards their records. The [file collection guide](https://signoz.io/docs/userguide/collect_logs_from_file/) explains how to set it up, including file access and container mounts.

## Find a failed request

For example, take a reporting application whose web server writes a log for each request. When a request to `/report` fails because the service is unavailable, its log records an HTTP `503` response.

A regular expression parser can extract the status from the text while keeping the original message. In [Logs Explorer](https://signoz.io/docs/userguide/logs_query_builder/), filtering for the service `third-party-web-example` and status `503` finds the failed request.

You can parse logs in the Collector before export or use [Logs Pipelines](https://signoz.io/docs/logs-pipelines/introduction/) in SigNoz Cloud to extract fields before storage. For text logs, see the [regex parser guide](https://signoz.io/docs/logs-pipelines/guides/regex-parser/). For JSON logs, use the [JSON parser](https://signoz.io/docs/logs-pipelines/guides/json/) to extract fields as attributes that you can filter.
