In SigNoz Cloud, search the customer’s user ID in Logs Explorer, then use the request ID from a failed log to find the other records for that request. This works when your application records both IDs and the relevant logs have been collected and retained.

## Find the failed request

For example, a customer reports that a payment failed. The checkout service records the customer’s ID as `user.id`, the request ID as `request.id`, and error details inside `logerror.stack`. Search for the customer’s ID in Logs Explorer and set the time range around the reported failure. The field names in your logs may differ from this example.

The results include successful and failed requests. Open a failure near the reported time and inspect its nested error. In this example, the stack contains `MongooseError`, so adding that error text to the filter narrows the results to one failed payment.

The screenshots show field paths from this example workspace. If your JSON fields are not available as filters, use the [JSON parsing guide](https://signoz.io/docs/logs-pipelines/guides/json/) to extract them into log attributes, then select the fields stored in your logs.

## Follow the request ID

Open the failed record and copy its request ID. Unlike the user ID, which can appear in many requests, this ID helps you isolate the individual payment.

<Figure
  src="/img/faqs/find-failed-requests-with-user-ids-and-json/copy-request-id.webp"
  alt="The failed payment record shows its request ID."
  caption="Copy the request ID from the failed payment record."
  width={768}
  height={480}
  themeInvert={false}
/>

Search for that request ID, remove error or service filters that could hide related records, and widen the time range to cover the whole request. Order the results by timestamp. In this example, seven collected records show the checkout, payment attempts, and final HTTP 500 response.

<Figure
  src="/img/faqs/find-failed-requests-with-user-ids-and-json/request-trail.webp"
  alt="A request ID filter returns seven checkout and payment records in timestamp order."
  caption="The request ID brings together the collected records for the failed payment."
  width={1226}
  height={465}
  themeInvert={false}
/>

The trail contains only logs SigNoz Cloud collected and still retains. If records are missing, check the time range, collection, retention, and whether the application recorded the IDs. Records with the same timestamp do not establish the order in which events caused one another.

You can download the results from Logs Explorer. Compare the number of exported records with the query count because the export has a row limit. For larger results, see the [Logs API pagination guide](https://signoz.io/docs/logs-management/logs-api/search-logs/).

## Ask an agent

You can also ask an agent connected to [SigNoz MCP](https://signoz.io/docs/ai/signoz-mcp-server/) to investigate the customer ID, find the request ID, and retrieve the related logs. Use a separate [service account](https://signoz.io/docs/manage/administrator-guide/iam/service-accounts/) with only the read access needed for the investigation; an ingestion key does not provide query access. Check the agent’s filters, time range, and returned records before relying on its conclusion.

If Noz is available in your workspace, its [customer log triage guide](https://signoz.io/docs/ai/use-cases/noz-triage-customer-issue/) also explains how to investigate using a recorded user or tenant ID.
