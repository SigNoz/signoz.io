An error log’s `trace_id` link opens the matching request trace in SigNoz when both the log and trace are available there. The shared ID takes you from the error message to the recorded calls behind that failure.

## Follow the request into its trace

For example, take a checkout service called `checkout-api` that calls `payment-service` to charge a card. Both services send traces to SigNoz and pass tracing information between them, so their operations share the request’s trace ID. When the payment times out, checkout logs **Checkout returned 500 after payment timeout**.

Open that error log in **Logs Explorer** and select its **Trace ID** link. The ID connects the log to the request, even when many requests use the same service at the same time.

![The checkout error log shows its service, severity, clickable trace ID, and span ID.](/img/faqs/follow-failed-requests-across-logs-and-traces/error-log-trace-link.webp)

The trace shows the checkout operation, its call to the payment service, and the failed payment operation. Each recorded operation is a **span**. The log’s `span_id` identifies the operation that wrote it; the trace link opens the wider request.

![The matching trace shows three connected spans across checkout-api and payment-service.](/img/faqs/follow-failed-requests-across-logs-and-traces/matching-request-trace.webp)

You can then select the failed payment span and open its **Logs** tab to read logs for the same trace. Select **Payment provider timed out** to open that error in **Logs Explorer**, where its `span_id` matches the payment operation.

![Logs Explorer shows the payment error opened from the span’s Logs tab, with the payment span ID and shared trace ID.](/img/faqs/follow-failed-requests-across-logs-and-traces/payment-error-from-trace.webp)

Use the [logs and traces correlation guide](https://signoz.io/docs/traces-management/guides/correlate-traces-and-logs/) for your language to configure your logging library to record the current request’s trace ID. This workflow uses logs and traces collected in SigNoz; it does not join records kept only in separate tools.

## If the trace does not open

If the log has no trace ID link, check whether the ID is stored in its message or a custom attribute. For incoming logs, the [Trace Parser](https://signoz.io/docs/logs-pipelines/guides/trace/) can map an existing ID into the standard trace field. It cannot recover an ID that was never recorded.

If the ID is present, search the same `trace_id` in [Traces Explorer](https://signoz.io/docs/userguide/traces/) with a time range that includes the request. Use **List View** with **All Spans** to check for collected spans.

If no trace is available, check whether your application sent it. Sampling rules can keep only some request traces and exclude the one you need. Also check your [trace retention period](https://signoz.io/docs/userguide/retention-period/). A log can keep its trace ID after the trace is no longer available; the ID alone cannot recreate that trace.
