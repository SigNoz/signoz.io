Ingestion limits put hard caps on the telemetry that each ingestion key accepts, whatever your applications send. This feature is available in SigNoz Cloud and Self-Hosted Enterprise.

Use limits mainly for non-production environments. A limit stops a misconfigured dev or staging service before it runs up a large bill.

## How to Set a Limit

You set limits per signal on each ingestion key. SigNoz Cloud has no limit for the whole workspace and no limit in dollars. The full step-by-step procedure is in the ingestion keys documentation:

**[Add Limits to an Ingestion Key](https://signoz.io/docs/ingestion/signoz-cloud/keys/#add-limits-to-a-key)**

In summary:

1. Go to **Settings > Identity & Access > Ingestion**.
2. Click the arrow at the left of the ingestion key to expand it.
3. In the **LIMITS** section, click **+ Limits** next to the signal (logs, traces, or metrics).
4. Turn on **Daily limit**, **Per Second limit**, or both, enter the values, and click **Save**.

Limits reset daily. After a key hits its limit, SigNoz drops new data for that signal until midnight UTC.

<Admonition type="warning">
  SigNoz does not buffer or retry data that a limit drops, so that data is lost. Apply limits only
  to environments where you can accept data loss, such as Dev or Staging.
</Admonition>
