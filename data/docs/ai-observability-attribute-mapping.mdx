**Attribute Mapping** is the settings tab of [AI Observability](https://signoz.io/docs/ai-observability/) where you tell SigNoz how to read LLM data from spans that do not follow the <a href="https://opentelemetry.io/docs/specs/semconv/gen-ai/" target="_blank" rel="noopener noreferrer nofollow">OpenTelemetry GenAI semantic conventions</a>. A mapping copies the value of a source attribute to a target attribute, for example a GenAI attribute such as `gen_ai.usage.input_tokens`. With the target attributes set, the AI Observability panels can show data for your spans.

Use this page to add mappings, group them by condition, and test them against a sample span before you save.

<Admonition type="info">
AI Observability is available to every user and carries a **Beta** label in the side navigation. Any user can view mappings. Only Admins can add, edit, or delete them. For prerequisites, see the [AI Observability overview](https://signoz.io/docs/ai-observability/#prerequisites).
</Admonition>

## Open Attribute Mapping

1. In the side navigation, open the **More** menu and select **AI Observability**.
2. In the tab bar at the top, select **Attribute Mapping**.

The page has two tabs. **Attribute Mappings** shows the mapping table. **Test** runs a sample span through your mappings.

## How groups and mappings work

A group holds a set of mappings and the conditions that decide which spans the group runs on. A mapping names one target attribute and one or more source attributes. For each span, SigNoz writes the value of the first source attribute that exists on the span to the target attribute.

The **Attribute Mappings** tab shows each group as a row that you can expand. The group row shows the group name, the number of conditions, and an **Enabled** switch. To see the condition keys, hold the pointer over the condition count. When you expand a group, you see its mappings in these columns:

| Column | What it shows |
| --- | --- |
| **Target** | The attribute that the mapping writes, and whether it is a span attribute or a resource attribute. |
| **Sources** | The source attributes, in priority order. |
| **Actions** | An **Enabled** switch, and a menu (⋮) to edit or delete the mapping. |

## Add a group

1. On the **Attribute Mappings** tab, select **Add a new group**.
2. In **Group Name**, type a name for the group.
3. Set the conditions for the group:
   - In **Condition · span attribute keys**, add the span attribute keys that select spans for this group.
   - In **Condition · resource keys**, add the resource keys that select spans for this group.

   The group runs on a span when the span has a key from either list. If you leave both lists empty, the group runs on every span.
4. Select **Create group**.

To edit a group later, open the menu (⋮) on the group row and select **Edit**.

## Add a mapping

1. Expand the group and select **Add mapping**.
2. In **Target attribute**, type the attribute to write, for example `gen_ai.usage.input_tokens`. You cannot change the target attribute after you create the mapping.
3. In **Write target to**, select **Span attribute** or **Resource**.
4. In **Source attributes**, add the attribute that your instrumentation sends. To add a fallback, select **Add another source**. SigNoz tries the sources from top to bottom. To change the order, drag a source.
5. Select **Create mapping**.

## Save your changes

SigNoz does not apply a new group, a new mapping, or an edit until you save it. When you have unsaved changes, the tab bar shows **Unsaved changes** and two buttons:

- Select **Save changes** to apply all the changes.
- Select **Discard** to remove all the changes, and then select **Discard changes** to confirm.

SigNoz applies mappings when it receives a span. A saved mapping changes new spans only. Spans that SigNoz already stored do not change.

## Test your mappings

Before you save, use the **Test** tab to make sure that a span gets the target attributes that you expect. The test uses your current groups and mappings, including unsaved changes.

1. Paste a span as JSON into the editor. The span can have `attributes` and `resource` objects, or it can be one attributes object.
2. Select **Run Test**.
3. In the result panel, look at **Resulting attributes** and **Resulting resource**. A badge shows each attribute that a mapping populated, remapped, or moved out.

The test sends only the `attributes` and `resource` objects. It removes other top-level keys, such as `name`, `spanId`, or `kind`. You can paste a full span export without changes. To restore the sample span, select **Reset to Default Span**.
