Logs Management in SigNoz lets you collect, search, and analyze logs from any source — applications, infrastructure, and cloud services. Built on OpenTelemetry, it gives you a unified model for logs alongside traces and metrics so you can correlate signals without switching tools.

## Key capabilities

- **Flexible ingestion**: Collect logs from files, stdout, FluentBit, FluentD, Logstash, OpenTelemetry SDKs, HTTP endpoints, and cloud services.
- **Log Explorer with query builder**: Search and filter logs using a visual Query Builder with aggregations, grouping, and multi-query support. Switch between List, Time Series, and Table views, or stream live logs in real time.
- **Quick filters**: Filter logs instantly by common attributes — service name, severity, trace ID — without writing a query.
- **Log Pipelines**: Parse, transform, and enrich logs before they reach storage using a functional pipeline builder. Remove PII, normalize fields, or drop unwanted records at ingestion time.
- **Unified context**: Correlate logs with traces and metrics for faster root-cause analysis.

## Key product capabilities

### Log Explorer

The Log Explorer is the primary interface for working with logs in SigNoz:

- **Query Builder** — filter by any attribute with operators like `=`, `!=`, `contains`, `exists`; aggregate by count, sum, or rate; group by service, host, or custom fields
- **Quick filters** — one-click sidebar filters for severity level, service name, and other common log attributes
- **Views** — switch between List (raw log lines), Time Series (count over time), and Table (aggregated results)
- **Fields** — browse indexed attributes and resource fields; promote custom attributes to fast-search columns
- **Live tail** — stream incoming logs in real time for active debugging sessions

### Logs Pipelines

Logs Pipelines let you process logs between collection and storage:

- **Parse** — extract structured fields from unstructured log bodies using grok, regex, or JSON processors
- **Transform** — rename, copy, or delete attributes; convert types; add computed fields
- **Filter** — drop log records matching specific conditions before they are stored, reducing ingestion costs
- **Enrich** — add resource attributes or static metadata to logs at pipeline time
