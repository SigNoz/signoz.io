## Prerequisites

- Node.js version 14 or higher
- An instance of SigNoz (either [Cloud](https://signoz.io/teams/) or [Self-Hosted](https://signoz.io/docs/install/self-host/))
- A Node.js application that uses the Bunyan logger

## Send logs to SigNoz

There are two ways to send logs from your Node.js application to SigNoz:

- **Direct to SigNoz Cloud (recommended for beginners):** no extra installs beyond the SDK; you only need the region endpoint and ingestion key.
- **Optional: Install a local OTel Collector binary on the VM:** it listens at `http://localhost:4318`, forwards telemetry to SigNoz, and does not require an ingestion key from the app. Install it with the [OTel Collector binary guide](https://signoz.io/docs/tutorial/opentelemetry-binary-usage-in-virtual-machine/).

<Tabs>
<TabItem value="automatic" label="No Code Auto-Instrumentation (recommended)" default>

Auto-instrumentation automatically captures:

- **Bunyan logs** with trace correlation
- **HTTP requests** (incoming and outgoing)

### Step 2: Run the application

You can use the `NODE_OPTIONS` environment variable to auto-instrument your application.

```bash
export OTEL_EXPORTER_OTLP_ENDPOINT="https://ingest.<region>.signoz.cloud:443"
export OTEL_NODE_RESOURCE_DETECTORS="env,host,os"
export OTEL_SERVICE_NAME="<service_name>"
export OTEL_EXPORTER_OTLP_HEADERS="signoz-ingestion-key=<your-ingestion-key>"
export NODE_OPTIONS="--require @opentelemetry/auto-instrumentations-node/register"
node index.js # Replace with your entry file
```

- Replace `<service_name>` with your service name.
- Replace `<region>` with your SigNoz Cloud [region](https://signoz.io/docs/ingestion/signoz-cloud/overview/#endpoint).
- Replace `<your-ingestion-key>` with your [ingestion key](https://signoz.io/docs/ingestion/signoz-cloud/keys/).

If you prefer sending telemetry to local OTel Collector, replace the `OTEL_EXPORTER_OTLP_ENDPOINT` with `http://localhost:4318` and skip the ingestion key:

```bash
export OTEL_EXPORTER_OTLP_ENDPOINT="http://localhost:4318"
# Do not set OTEL_EXPORTER_OTLP_HEADERS when using the local collector
```

#### Note

By default, auto-instrumentation collects traces and metrics. If you want to collect only logs, you can disable traces and metrics by setting the following environment variables:

```bash
export OTEL_TRACES_EXPORTER="none"
export OTEL_METRICS_EXPORTER="none"
```

### Step 2: Configure OpenTelemetry SDK

Create a file named `logging-instrumentation.js` or `logging-instrumentation.ts` in your project root.

<Tabs>
<TabItem value="vm" label="VM" default>

Use this configuration if you are sending logs directly to SigNoz Cloud or a local OTel Collector on a VM.

<Tabs>
<TabItem value="javascript" label="JavaScript" default>

```javascript:logging-instrumentation.js
const { NodeSDK } = require("@opentelemetry/sdk-node");
const { OTLPLogExporter } = require("@opentelemetry/exporter-logs-otlp-http");
const {
  BunyanInstrumentation,
} = require("@opentelemetry/instrumentation-bunyan");
const { resourceFromAttributes } = require("@opentelemetry/resources");
const { ATTR_SERVICE_NAME } = require("@opentelemetry/semantic-conventions");
const { BatchLogRecordProcessor } = require("@opentelemetry/sdk-logs");

// Configure the OTLP log exporter
const logExporter = new OTLPLogExporter({
  url: "https://ingest.<region>.signoz.cloud:443/v1/logs", // Replace <region> with your SigNoz region
  headers: {
    "signoz-ingestion-key": "<SIGNOZ_INGESTION_KEY>", // Replace <SIGNOZ_INGESTION_KEY> with your SigNoz ingestion key
  },
});

// If using a local OTel Collector (VM), use:
// url: "http://localhost:4318/v1/logs",
// headers: {},

// Initialize the OpenTelemetry SDK
const sdk = new NodeSDK({
  resource: resourceFromAttributes({
    [ATTR_SERVICE_NAME]: "nodejs-bunyan-logger",
  }),
  logRecordProcessor: new BatchLogRecordProcessor(logExporter),
  instrumentations: [
    new BunyanInstrumentation({
      // configure the instrumentation
    }),
  ],
});

sdk.start();

// Graceful shutdown
process.on("SIGTERM", () => {
  sdk
    .shutdown()
    .then(() => console.log("OpenTelemetry SDK shut down successfully"))
    .catch((error) => console.error("Error shutting down SDK", error))
    .finally(() => process.exit(0));
});

module.exports = sdk;
```

</TabItem>

Replace the placeholders:

- `<region>`: Your SigNoz Cloud [region](https://signoz.io/docs/ingestion/signoz-cloud/overview/#endpoint).

### Step 3: Initialize OpenTelemetry SDK

Import the instrumentation at the very top of your main application file (e.g., `index.js` or `index.ts`).

<Tabs>
<TabItem value="javascript" label="JavaScript" default>

```javascript:index.js
require("./logging-instrumentation"); // Must be imported first

const bunyan = require("bunyan");
const express = require("express");

// Create your Bunyan logger as usual
const logger = bunyan.createLogger({
  name: "express-app",
  level: "info",
});

// Your application code
const app = express();

app.get("/", (req, res) => {
  logger.info({ path: req.path, method: req.method }, "Request received");
  res.send("Hello World!");
});

app.get("/error-log", (req, res) => {
  logger.error(
    { path: req.path, method: req.method },
    "Error log endpoint hit",
  );
  res.status(500).send("Error log endpoint");
});

app.listen(3000, () => {
  logger.info("Server listening on port 3000");
});
```

</TabItem>

### Step 4: Log Correlation (Optional)

Bunyan logs created within a tracing span are automatically enriched with span and trace IDs, enabling [correlation](https://signoz.io/docs/traces-management/guides/correlate-traces-and-logs/). The added fields are:

- `trace_id`
- `span_id`
- `trace_flags`

You can use `tracer.startActiveSpan` to correlate logs with traces. Here is an example:

<Tabs>
<TabItem value="javascript" label="JavaScript" default>

```javascript:index.js
---
const api = require('@opentelemetry/api')

const tracer = api.trace.getTracer('example')
tracer.startActiveSpan('process-order', (span) => {
  logger.info({ orderId: '12345' }, 'Processing order')
  // Log record will include: trace_id, span_id, trace_flags

  span.end()
})
```

</TabItem>
<TabItem value="typescript" label="TypeScript">

```typescript:index.ts
---

  // Log record will include: trace_id, span_id, trace_flags
```

## Troubleshooting

</ToggleHeading>

#### Why do I see "404 Not Found" errors?

This usually happens if the endpoint URL is incorrect. Ensure your URL ends with `/v1/logs`.

- Cloud: `https://ingest.<region>.signoz.cloud:443/v1/logs`
- Self-Hosted: `http://localhost:4318/v1/logs`

#### Why are my logs not appearing in SigNoz?

- Check if the application started successfully and is actually generating logs.
- Verify your `<region>` and `<SIGNOZ_INGESTION_KEY>` are correct.
