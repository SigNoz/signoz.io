## Overview

The OpenTelemetry Collector's filter processor lets you drop logs before they reach SigNoz — by severity level, body content, resource attributes, or log attributes. Use this to eliminate noise, cut storage costs, and stay within budget without changing your application code.

:::info Prerequisites
- [OpenTelemetry Collector](https://signoz.io/docs/opentelemetry-collection-agents/get-started/) installed and receiving logs
- Access to your `config.yaml` file
:::

## Steps

### Step 1: Choose your filter recipe

Pick the processor block that matches what you want to drop and add it to the `processors` section of your `config.yaml`.

#### Drop by severity text (log level)

```yaml
processors:
  filter/drop_by_level:
    logs:
      log_record:
        - 'IsMatch(severity_text, "(?i)\b(DEBUG)\b")'
```

#### Drop by body regex

```yaml
processors:
  filter/drop_by_body:
    logs:
      log_record:
        - 'IsMatch(body, ".*password.*")'
```

#### Drop by resource attribute — exact match

```yaml
processors:
  filter/drop_by_resource:
    logs:
      log_record:
        - resource.attributes["k8s.pod.name"] == "test-pod"
```

#### Drop by resource attribute — regex

```yaml
processors:
  filter/drop_by_resource_regex:
    logs:
      log_record:
        - IsMatch(resource.attributes["k8s.pod.name"], "test-pod-.*")
```

#### Drop by log attribute — exact match

```yaml
processors:
  filter/drop_by_attribute:
    logs:
      log_record:
        - attributes["user_agent.name"] == "Safari"
```

#### Drop by log attribute — regex

```yaml
processors:
  filter/drop_by_attribute_regex:
    logs:
      log_record:
        - IsMatch(attributes["http.method"], "GET|POST")
```

#### Kubernetes: exclude or include by namespace, pod, or container

For Kubernetes environments, configure log exclusion and inclusion directly in the k8s-infra chart — no custom processor required. See the [Kubernetes pod logs guide](https://signoz.io/docs/userguide/collect_kubernetes_pod_logs/#excludeincludefilter-logs-collection) for detailed examples.

### Step 2: Add the processor to your logs pipeline

Open the `service.pipelines.logs` section in `config.yaml` and add the processor name. The order matters — place it before `batch`:

```yaml
service:
  pipelines:
    logs:
      receivers: [otlp]
      processors: [filter/drop_by_level, batch]
      exporters: [otlp]
```

Replace `filter/drop_by_level` with the name you defined in Step 1. You can chain multiple filters:

```yaml
processors: [filter/drop_by_level, filter/drop_by_body, batch]
```

### Step 3: Restart the collector

Apply your changes by restarting the OpenTelemetry Collector.

## Limit Log Body Size

To cap log body length rather than drop entire records, use the transform processor with `truncate_all`:

```yaml
processors:
  transform/truncate_logs:
    log_statements:
      - context: log
        statements:
          - truncate_all(body, 4096)
```

Add it to your pipeline:

```yaml
service:
  pipelines:
    logs:
      receivers: [otlp]
      processors: [transform/truncate_logs, batch]
      exporters: [otlp]
```

Adjust the character limit to suit your needs.

## Verify

After restarting the collector, generate a log that matches your filter condition and confirm it does **not** appear in **Logs → Logs Explorer** in SigNoz.
