<Admonition type="warning">

With v0.112.0, the standalone `signoz-schema-migrator` is deprecated. Telemetry Store migrations (ClickHouse schema migrations) are now built into `signoz-otel-collector` via `migrate` commands.

Key changes:
- The `signoz/signoz-schema-migrator` is replaced by `signoz/signoz-otel-collector`.
- A new `telemetrystore-migrator` service replaces both `schema-migrator-sync` and `schema-migrator-async`. This is a one-time change.
- A new `bootstrap` step is required before `sync` and `async` migrations.
</Admonition>

## Upgrade Instructions

<Tabs>
<TabItem value="docker-standalone" label="Docker Standalone" default>

<Admonition type="info">
If you are using the default Docker Compose files, no changes are required. Follow the [standard upgrade guide](https://signoz.io/docs/operate/migration/upgrade-standard/#docker-standalone).
</Admonition>

If you have customized your `docker-compose.yaml`, make the following changes before upgrading:

### Step 1: Remove signoz-schema-migrator and references

Remove the `schema-migrator-sync` and `schema-migrator-async` service definitions from your `docker-compose.yaml`:

```yaml:docker-compose.yaml
# REMOVE these services
  schema-migrator-sync:
    ...
  schema-migrator-async:
    ...
```

Also remove the `schema-migrator-sync` reference from the `x-db-depend` anchor at the top of the file:

```diff:docker-compose.yaml
x-db-depend: &db-depend
  !!merge <<: *common
  depends_on:
    clickhouse:
      condition: service_healthy
-    schema-migrator-sync:
-      condition: service_completed_successfully
```

### Step 2: Add the new telemetrystore-migrator service

Add the following `telemetrystore-migrator` service definition to your `docker-compose.yaml`. This single service replaces both `schema-migrator-sync` and `schema-migrator-async`:

```yaml:docker-compose.yaml
  telemetrystore-migrator:
    !!merge <<: *common
    image: signoz/signoz-otel-collector:v0.142.0
    container_name: telemetrystore-migrator
    command:
    - -c
    - |
      /signoz-otel-collector migrate bootstrap --clickhouse-dsn tcp://clickhouse:9000 &&
      /signoz-otel-collector migrate sync up --clickhouse-dsn tcp://clickhouse:9000 &&
      /signoz-otel-collector migrate async up --clickhouse-dsn tcp://clickhouse:9000
    depends_on:
      clickhouse:
        condition: service_healthy
    entrypoint:
    - /bin/sh
    restart: on-failure
```

### Step 3: Update service dependencies

Update the `signoz` service to depend on `telemetrystore-migrator`:

```yaml:docker-compose.yaml {4-5}
  signoz:
    !!merge <<: *db-depend
    ...
    depends_on:
      telemetrystore-migrator:
        condition: service_completed_successfully
```

If your `otel-collector` service previously referenced `schema-migrator-sync`, remove that reference:

```diff:docker-compose.yaml
  otel-collector:
    ...
    depends_on:
-      schema-migrator-sync:
-        condition: service_completed_successfully
      signoz:
        condition: service_healthy
```

### Step 4: Apply the changes

Follow the [standard upgrade guide](https://signoz.io/docs/operate/migration/upgrade-standard/#docker-standalone) to pull the latest changes and restart the stack.

### Step 5: Validate migrations

```bash
docker ps -a --filter "name=telemetrystore-migrator"
```

The container should show status `Exited (0)`.

If you have custom overrides under `schemaMigrator.*` in your values file, make the following changes before upgrading:

### Step 1: Update Helm values

Rename the `schemaMigrator` block to `telemetryStoreMigrator` in your `values.yaml`:

From:

```yaml
schemaMigrator:
  ...
```

To:

```yaml
telemetryStoreMigrator:
  ...
```

The following values have moved within the block:

| Existing Helm value | Updated Helm value |
| --- | --- |
| `schemaMigrator.initContainers.init.image.*` | `telemetryStoreMigrator.image.*` |
| `schemaMigrator.initContainers.init.resources` | `telemetryStoreMigrator.resources` |

The following values have been removed with no replacement:

- `schemaMigrator.args`
- `schemaMigrator.initContainers.init.enabled`
- `schemaMigrator.initContainers.init.command.*`
- `schemaMigrator.initContainers.chReady.*`
- `schemaMigrator.initContainers.wait.*`

A new `telemetryStoreMigrator.timeout` value is available to control migration timeout.

### Step 2: Apply the changes

Follow the [standard upgrade guide](https://signoz.io/docs/operate/migration/upgrade-standard/#kubernetes-deployment) to upgrade the Helm release.

### Validate migrations

Check that the `telemetrystore-migrator` job completed successfully:

```bash
kubectl get jobs -n <namespace> | grep telemetrystore-migrator
```

Replace `<namespace>` with the namespace of your SigNoz deployment.

The job should show `1/1` completions. If it failed, check the logs:

```bash
kubectl logs -n <namespace> job/<job-name> --tail=100
```

Replace `<job-name>` with the job name from the output above.

Replace `<your-clickhouse-password>` with your ClickHouse password. If no password is set, use `tcp://localhost:9000` without the `?password=` parameter.

Follow the [standard upgrade guide](https://signoz.io/docs/operate/migration/upgrade-standard/#linux-binary-installation) to download and restart with the new binary.

Each migration command prints its progress to stdout. Verify that all three commands completed without errors before proceeding.

## Command Reference

The `signoz-otel-collector migrate` command has the following subcommands:

| Command | Description |
| --- | --- |
| `migrate bootstrap` | Creates the migration tracking tables in ClickHouse. Must run before any other migrate command. |
| `migrate sync up` | Runs sync (schema) migrations. These mutate the store schema and must complete before the application starts. |
| `migrate sync check` | Checks the status of sync migrations from the migration tracking table. |
| `migrate async up` | Runs async (data) migrations. These include background data migrations that do not block the application. |
| `migrate async check` | Checks the status of async migrations from the migration tracking table. |
| `migrate ready` | Checks if the store is ready to run migrations. |

### Global flags

These flags apply to all `migrate` subcommands:

| Flag | Description |
| --- | --- |
| `--clickhouse-dsn` | DSN for the ClickHouse connection |
| `--clickhouse-cluster` | Name of the ClickHouse cluster |
| `--clickhouse-replication` | Whether replication is enabled in the ClickHouse cluster |

Each subcommand also accepts a `--timeout` flag to control the operation timeout.

### Commands mapping

| `signoz-schema-migrator` | `signoz-otel-collector` |
| --- | --- |
| _(no equivalent)_ | `signoz-otel-collector migrate bootstrap --clickhouse-dsn <dsn>` |
| `signoz-schema-migrator sync --dsn=<dsn> --up=` | `signoz-otel-collector migrate sync up --clickhouse-dsn <dsn>` |
| `signoz-schema-migrator async --dsn=<dsn> --up=` | `signoz-otel-collector migrate async up --clickhouse-dsn <dsn>` |

## Troubleshooting
</ToggleHeading>

### telemetrystore-migrator exits with a non-zero code

**Symptoms**: The `telemetrystore-migrator` container exits with a non-zero exit code and the `signoz` service does not start.

**Likely causes**:
- ClickHouse is not reachable or not healthy yet.
- The ClickHouse DSN is incorrect.

**Resolution**:
1. Check the migrator logs for the specific error:
   ```bash
   # Docker Standalone
   docker logs telemetrystore-migrator

   # Docker Swarm
   docker service logs signoz_telemetrystore-migrator
   ```
2. Verify ClickHouse is healthy:
   ```bash
   curl -s http://localhost:8123/ping
   ```
   Expected response: `Ok.`
3. If the issue persists, the service has `restart: on-failure` set and will retry automatically. Check logs again after a retry.

### signoz service fails to start after upgrade

**Symptoms**: The `signoz` container is stuck in a restart loop or fails health checks after upgrading.

**Likely causes**:
- The `telemetrystore-migrator` service has not completed successfully.
- `signoz-schema-migrator` service definitions were not fully removed.

**Resolution**:
1. Verify the migrator completed:
   ```bash
   docker ps -a --filter "name=telemetrystore-migrator"
   ```
   The container should show `Exited (0)`.
2. Review your `docker-compose.yaml` and confirm there are no remaining references to `schema-migrator-sync`, `schema-migrator-async`, or `schema-migrator`.
3. Re-run `docker compose up -d` to restart the stack.

</details>
