SigNoz v0.131.0 requires ClickHouse 25.12.5. This guide upgrades a Foundry-managed and self-managed self-hosted SigNoz

<Admonition type="warning">
  <strong>ClickHouse 25.12.5 is required for SigNoz v0.131.0 and later.</strong> v0.131.0 ships a
  `signoz-otel-collector` newer than 0.144.5, which does not run on ClickHouse older than 25.12.5.
  `forge` and `cast` fail if the ingester is newer than 0.144.5 while ClickHouse is older than
  25.12.5.
</Admonition>

## Back up first

ClickHouse upgrades its on-disk format in place on first start, and downgrades are not guaranteed. Snapshot your data before upgrading: the Docker volume, the Kubernetes PersistentVolumes, or `/var/lib/clickhouse` (binary). If the upgrade goes wrong, restore that snapshot, point `casting.yaml` back at the old version, re-forge, and re-apply.

## Upgrade

Upgrade `foundryctl` to pick up the new defaults, or pin the images in `casting.yaml`:

```yaml
apiVersion: v1alpha1
kind: Installation
metadata:
  name: signoz
spec:
  deployment:
    flavor: compose
    mode: docker
  telemetrystore:
    spec:
      image: clickhouse/clickhouse-server:25.12.5
  telemetrykeeper:
    spec:
      image: clickhouse/clickhouse-keeper:25.12.5
  signoz:
    spec:
      image: signoz/signoz:v0.131.0
```

Drop the `telemetrykeeper` block if your keeper `kind` is `zookeeper`. Then re-forge and re-apply with the command for your platform:

<Tabs entityName="deployment">
<TabItem value="docker-compose" label="Docker Compose" default>

```bash
foundryctl forge -f casting.yaml
cd pours/deployment && docker compose up -d
```

Or run `foundryctl cast -f casting.yaml` to forge and apply in one step.

</TabItem>
<TabItem value="docker-swarm" label="Docker Swarm">

```bash
foundryctl forge -f casting.yaml
docker stack deploy -c pours/deployment/compose.yaml signoz
```

</TabItem>
<TabItem value="kubernetes-helm" label="Kubernetes (Helm)">

```bash
foundryctl forge -f casting.yaml
helm upgrade signoz signoz/signoz -f pours/deployment/values.yaml -n signoz
```

</TabItem>
<TabItem value="kubernetes-kustomize" label="Kubernetes (Kustomize)">

```bash
foundryctl forge -f casting.yaml
kubectl apply -k pours/deployment/
kubectl get pods -n signoz -w
```

</TabItem>
<TabItem value="systemd" label="systemd / binary">

ClickHouse runs from the host `clickhouse` binary here, not an image, so install the new binary first (see [ClickHouse install](https://clickhouse.com/docs/install)), then restart the units:

```bash
sudo systemctl restart signoz-telemetrystore-clickhouse-0-0
sudo systemctl restart signoz-telemetrykeeper-clickhousekeeper-0
```

</TabItem>
<TabItem value="standalone" label="Standalone">

The standalone image bundles every component, so there is nothing to rebuild. Pull the image published for this release and recreate the container with the same flags and volumes:

```bash
docker pull signoz/signoz-standalone:latest
```

</TabItem>
</Tabs>

## Verify

1. Pods and containers are healthy (`docker compose ps`, `kubectl get pods -n signoz`, or `systemctl status 'signoz-*'`).
2. ClickHouse is on the new version: `SELECT version();`
3. The `signoz-telemetrystore-migrator` job finished. On older ClickHouse it could stall with a distributed DDL timeout (exception code 159); 25.12.5 fixes that.
4. No part-intersection errors (`LOGICAL_ERROR`, code 49) in the ClickHouse logs.
5. Clustered deployments: `SELECT * FROM system.distribution_queue WHERE error_count > 0;` returns nothing.
6. Fresh data is flowing:

   ```sql
   SELECT
     (SELECT count() FROM signoz_logs.logs_v2 WHERE timestamp > now() - INTERVAL 10 MINUTE) AS recent_logs,
     (SELECT count() FROM signoz_traces.signoz_index_v3 WHERE timestamp > now() - INTERVAL 10 MINUTE) AS recent_traces,
     (SELECT count() FROM signoz_metrics.samples_v4 WHERE unix_milli > toUnixTimestamp(now() - INTERVAL 10 MINUTE) * 1000) AS recent_metrics;
   ```

7. SigNoz reports v0.131.0 under **Settings**.
