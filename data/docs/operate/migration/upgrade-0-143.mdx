SigNoz v0.143.0 changes the default session token provider from `jwt` to `opaque`. Opaque tokens are stored server-side and can be revoked; JWT tokens are stateless and cannot. New deployments get the safer default automatically. An existing deployment that never set `tokenizer.provider` also switches to `opaque` on upgrade.

<Admonition type="warning" title="All active sessions are invalidated unless you opt in to JWT">
Sessions issued by the JWT provider are not valid for the opaque provider. If you upgrade without an explicit `tokenizer.provider: jwt` entry in your config, every logged-in user is signed out and must log in again. To avoid this, set `tokenizer.provider: jwt` before you upgrade.
</Admonition>

## Choose your path

- **Adopt the new default (recommended).** Do nothing to the config. Users are logged out once, then sign back in and get revocable, server-side sessions. This needs no extra infrastructure, only the SQL Metastore SigNoz already uses.
- **Keep the JWT provider.** Set `tokenizer.provider: jwt` (and keep your [JWT secret](https://signoz.io/docs/manage/administrator-guide/configuration/jwt-secret/) set) before upgrading. Existing sessions stay valid.

To keep JWT, add this to your config file:

```yaml
tokenizer:
  provider: jwt
```

Or set the environment variable:

```bash
SIGNOZ_TOKENIZER_PROVIDER=jwt
```

For the full tokenizer block, providers, and tuning options, see [Session Token Provider Configuration](https://signoz.io/docs/manage/administrator-guide/configuration/session-tokens/).

## Upgrade self-hosted SigNoz

### Step 1: Decide on the provider

Pick a path above. If you are keeping JWT, apply `tokenizer.provider: jwt` to your config now, before you upgrade. If you are more than one release behind, check the [Upgrade Path Tool](https://signoz.io/upgrade-path/) for required stops before you move to v0.143.0.

### Step 2: Upgrade SigNoz

<Tabs entityName="installer">
<TabItem value="foundry" label="Foundry" default>

Upgrade <a href="https://github.com/SigNoz/foundry/blob/main/docs/getting-started.md" target="_blank" rel="noopener noreferrer nofollow">foundryctl</a> to pick up the v0.143.0 defaults, then re-apply your existing `casting.yaml`:

```bash
curl -fsSL https://signoz.io/foundry.sh | bash
foundryctl cast -f casting.yaml
```

If your <a href="https://github.com/SigNoz/foundry/blob/main/docs/reference/casting-file.md" target="_blank" rel="noopener noreferrer nofollow">casting.yaml</a> pins image versions, the new defaults will not override them (your config wins), so bump the SigNoz image pin to v0.143.0 yourself.

</TabItem>
<TabItem value="helm" label="Kubernetes (Helm chart)">

Update the <a href="https://github.com/SigNoz/charts" target="_blank" rel="noopener noreferrer nofollow">chart</a> and upgrade. Replace `<namespace>` and `<release-name>` with your own values:

```bash
helm repo update
helm -n <namespace> upgrade <release-name> signoz/signoz
```

`helm upgrade` takes the newest chart; add `--version 0.143.0` to pin the v0.143.0 chart.

</TabItem>
</Tabs>

For Docker or binary deployments, follow the [standard upgrade guide](https://signoz.io/docs/operate/migration/upgrade-standard/) and set the target version to v0.143.0.

### Step 3: Verify the upgrade

1. Pods and containers are healthy (`kubectl get pods -n <namespace>`, `docker compose ps`, or `systemctl status 'signoz-*'`).
2. SigNoz reports v0.143.0 under **Settings**.
3. Sign in. If you adopted the opaque default, expect to be prompted to log in again; if you kept JWT, your existing session should still work.
