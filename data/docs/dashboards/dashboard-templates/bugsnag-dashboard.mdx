</Admonition>

This dashboard provides a comprehensive view of the Bugsnag error events forwarded to SigNoz as logs. It is built on the `bugsnag.*`, `exception.*`, `app.*`, `os.*`, and `device.*` log attributes produced by the integration's collector transform, and focuses on error volume, unhandled crash share, affected users, and how errors break down by app version, exception class, and device. Every panel filters on `service.name = bugsnag`, the service name the integration assigns to forwarded events, and an `exception.type` dashboard variable lets you focus the breakdown panels and the events list on one exception class for drill-down.

## What This Dashboard Monitors

This dashboard tracks the health of your mobile and web applications using the error events Bugsnag forwards to SigNoz, helping you:

- **Track Error Volume**: Watch error event counts over time to spot spikes and regressions the moment they start.
- **Separate Crashes from Handled Errors**: Surface the share of events that were unhandled crashes for an at-a-glance stability signal.
- **Measure User Impact**: Count the distinct users affected by errors, turning raw event volume into customer impact.
- **Catch Bad Releases**: Break error volume down by app version and release stage to see whether a new release introduced a regression.
- **Identify Top Offenders**: Rank exception classes by event count so the highest-impact bugs are fixed first.
- **Spot Device and OS Patterns**: Break errors down by OS version and device model to catch platform-specific failures.
- **Inspect Recent Errors**: Drill into the most recent error events — with stacktrace and Bugsnag deep link — when investigating an incident.

## Panels Included

### Stability Summary (Top Row)

| Panel | Type | What It Shows |
|-------|------|---------------|
| **Total Error Events** | Value | Count of all Bugsnag error events in the selected window, a quick pulse on overall error activity |
| **Unhandled Crashes** | Value | Share of events where `bugsnag.error.unhandled` is true, rendered as a percentage — the headline stability signal |
| **Affected Users** | Value | Count of distinct `user.id` values across error events, measuring customer impact rather than raw volume |
| **App Versions Reporting** | Value | Count of distinct `app.version` values seen in the window, showing how many releases are producing errors |

### Error Trends

- **Crashes vs Handled Errors**: Time-series graph split by `bugsnag.error.unhandled` — crashes and caught errors as separate series, so a stability regression stands out from ordinary error noise.
- **Error Events by Severity**: Time-series graph of event counts grouped by severity, revealing spikes and whether they are errors, warnings, or info events.
- **Error Events by App Version**: Time-series graph of event counts grouped by `app.version`, making release regressions immediately visible.

### Top Offenders

- **Top Exception Classes**: Table of `exception.type` ranked by event count and split by unhandled/handled, so the highest-impact bugs surface first. Select a class in the `exception.type` variable to focus the rest of the dashboard on it.
- **Errors by Context**: Table of `bugsnag.error.context` — the screen, activity, or route where errors concentrate.

### Devices & Platforms

- **Errors by OS Version**: Table of events grouped by `os.name` and `os.version`, catching failures tied to a platform update.
- **Errors by Device Model**: Table of each device model's error event count, surfacing device-specific problems.

### Recent Activity

- **Recent Error Events**: List of the most recent Bugsnag events with a readable `ExceptionClass: message` body line. Opening an event shows the stacktrace (`exception.stacktrace`), the full raw payload (`bugsnag.payload`), and a `bugsnag.error.url` deep link back to the issue in Bugsnag. Respects the `exception.type` variable for per-class investigation.
