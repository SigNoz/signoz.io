## Pie Chart

A Pie chart is a plot chart that shows the proportion of a single or a few different categories. This is useful when you want to show the composition of the data by categories.

### Data Formats

#### Supported signals

- Logs
- Traces
- Metrics

This panel type supports any time series data. The time series data can be from logs, traces, or metrics.

#### Visualization

- **Time range** (formerly "Panel Time Preference"): Override the global dashboard time range for this panel. Keep `Global Time` to follow the dashboard time picker, or choose a fixed time range.

#### ClickHouse SQL queries

When a pie panel is backed by a ClickHouse SQL query, each aggregation (value) column in the query renders as its own slice.

- A query with two or more value columns, for example `SELECT count() AS total_count, sum(value) AS total_value FROM ...`, produces one slice per column, labelled with the column alias (`total_count`, `total_value`).
- When the query also has group-by columns, each slice is labelled `<group> · <column>` (with a middle-dot separator) so slices stay distinct across groups.
- A single-aggregation ClickHouse query renders one slice, and grouped Query Builder (PromQL/metrics) panels are unaffected: each group is one slice as before.

<Admonition type="info">
Only positive, numeric values are plotted. Columns that resolve to zero, a negative number, or a non-numeric value are dropped from the chart.
</Admonition>

#### Formatting & Units

- **Unit**: The unit for the displayed values (for example, `Bytes`, `Percent`, `Requests/s`). The default is `None`.
- **Decimal places** (formerly "Decimal precision"): Choose how many decimals to show from compact tiles: `0`, `1`, `2`, `3`, `4`, or `Full` (the raw value, unrounded). A live **Shows as** preview beneath the tiles displays a sample value formatted at the selected precision (for example `1,234.56` at `2`). The default is `2`.

<Admonition type="info">
When you create a new panel, the **Unit** is pre-filled with the unit of the selected metric, so the values match how the metric was reported. If you choose a unit that is incompatible with the unit the metric was sent with, a warning icon appears on the unit selector. Hover the icon to see a tooltip explaining the mismatch and the unit the metric was sent with.
</Admonition>

#### Legend

- **Position**: Pick where the legend sits from a tile picker: **Below chart** (formerly "Bottom") or **Right of chart** (formerly "Right"). With **Right of chart**, the legend column sizes itself to fit the longest series name. Its width stays between 150 px and the smaller of 320 px or 40% of the panel width. Long labels stay whole, and the donut stays fully visible.
- **Series colors**: Assign a custom color to each slice. Select **Reset** to return a slice to its default color, or **Reset All** to reset every slice.
- **Search series**: A search box and a **Showing N of M series** count appear above the legend. A **Right of chart** legend shows them when it has at least one slice. A **Below chart** legend shows them only when the slices need more than two rows. Type part of a label to filter the list as you type. The count changes to match the results.

When you group by an attribute, legend and slice labels use the `{key="value"}` format (for example, `{service.name="frontend"}`), matching the time series, bar, and histogram panels. Series colors are keyed by this label, so a custom color override applies only when its key matches the label exactly.

<Admonition type="warning" title="Re-save custom colors set before this change">
Earlier pie panels showed group-by legends as bare values (for example, `frontend` instead of `{service.name="frontend"}`). If you set custom colors using those bare-value keys, the overrides no longer match the new labels. Open the panel, re-apply the colors against the new `{key="value"}` entries, and save.
</Admonition>

#### Context Links

Add context links to enable click-through navigation from the panel to other dashboards, external URLs, or filtered views. See [Interactivity](https://signoz.io/docs/dashboards/interactivity/) for details.
