This guide shows you how to collect JVM metrics from Spring Boot applications using Micrometer and Spring Boot Actuator. Metrics are exposed in Prometheus format and scraped by the OpenTelemetry Collector.

<KeyPointCallout title="Using self-hosted SigNoz?" defaultCollapsed={true}>
Most steps are identical. To adapt this guide, update the endpoint and remove the ingestion key header as shown in [Cloud → Self-Hosted](https://signoz.io/docs/ingestion/cloud-vs-self-hosted/#cloud-to-self-hosted).
</KeyPointCallout>

## Prerequisites

- A Spring Boot application (2.x or 3.x)
- A SigNoz Cloud account or self-hosted SigNoz instance
- OpenTelemetry Collector configured to send data to SigNoz

## Step 1. Add dependencies to your Spring Boot application

Add the following dependencies to your `pom.xml`:

```xml:pom.xml
<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-actuator</artifactId>
</dependency>
<dependency>
    <groupId>io.micrometer</groupId>
    <artifactId>micrometer-registry-prometheus</artifactId>
    <scope>runtime</scope>
</dependency>
```

For Gradle, add to `build.gradle`:

```groovy:build.gradle
implementation 'org.springframework.boot:spring-boot-starter-actuator'
runtimeOnly 'io.micrometer:micrometer-registry-prometheus'
```

## Step 2. Configure the Actuator endpoint

Add the following to your `application.properties`:

```properties:src/main/resources/application.properties
management.endpoints.web.exposure.include=prometheus,health,info,metrics
management.endpoint.prometheus.enabled=true
management.health.probes.enabled=true
management.endpoint.health.show-details=always
```

Or if using `application.yml`:

```yaml:src/main/resources/application.yml
management:
  endpoints:
    web:
      exposure:
        include: prometheus,health,info,metrics
  endpoint:
    prometheus:
      enabled: true
    health:
      show-details: always
  health:
    probes:
      enabled: true
```

## Step 3. Build and run your application

Rebuild your Spring Boot application:

```bash
./mvnw clean package
java -jar target/your-app.jar
```

Verify the metrics endpoint is working:

```bash
curl http://localhost:8080/actuator/prometheus
```

You should see Prometheus-formatted metrics output.

## Step 4. Configure OTel Collector to scrape metrics

Add the Prometheus receiver to your `otel-collector-config.yaml`. Append the following to your existing `receivers` section:

```yaml:otel-collector-config.yaml
receivers:
  prometheus:
    config:
      scrape_configs:
        - job_name: 'jvm-metrics'
          scrape_interval: 10s
          metrics_path: '/actuator/prometheus'
          static_configs:
            - targets: ['<app-host>:<app-port>']
```

Replace:
- `<app-host>`: Hostname or IP of your Spring Boot application
- `<app-port>`: Port your application is running on (default: `8080`)

<Admonition type="info">
If SigNoz and your app are on the same machine using Docker, use `host.docker.internal` as the host.
</Admonition>

Enable the receiver in your metrics pipeline:

```yaml:otel-collector-config.yaml
service:
  pipelines:
    metrics:
      receivers: [prometheus]
      processors: [batch]
      exporters: [otlp]
```

Restart the OTel Collector to apply changes:

```bash
# For Docker deployments
docker compose restart otel-collector

# For Kubernetes deployments
kubectl rollout restart deployment otel-collector
```

## Step 5. Import the JVM dashboard

SigNoz provides a pre-built JVM dashboard for visualizing these metrics.

1. Download the <a href="https://github.com/SigNoz/dashboards/tree/main/jvm" target="_blank" rel="noopener noreferrer nofollow">JVM dashboard JSON</a>
2. In SigNoz, go to **Dashboards** → **New Dashboard** → **Import JSON**
3. Paste the JSON content or upload the file

See the [JVM Dashboard Template](https://signoz.io/docs/dashboards/dashboard-templates/jvm-metrics/) for more details on available panels.

## Validate

1. Generate load on your application by making requests
2. Open SigNoz and go to **Dashboards**
3. Open the imported JVM dashboard
4. Verify metrics like heap usage, GC pauses, and thread counts are populating

## Troubleshooting
</ToggleHeading>

### Metrics not appearing in SigNoz?

- Verify the `/actuator/prometheus` endpoint returns metrics
- Check OTel Collector logs for scrape errors
- Ensure the target IP/port is reachable from the Collector
- Verify the Prometheus receiver is enabled in the metrics pipeline

### "Connection refused" when scraping?

- Check if the application is running and the port is correct
- For Docker: use `host.docker.internal` instead of `localhost`
- For Kubernetes: use the service DNS name (e.g., `my-app.default.svc.cluster.local:8080`)

### Only some metrics appear?

- Verify `management.endpoints.web.exposure.include` includes `prometheus`
- Check that `micrometer-registry-prometheus` dependency is correctly added
- Some metrics require specific configurations (e.g., HikariCP metrics need the connection pool)
