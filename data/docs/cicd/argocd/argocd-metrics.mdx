## Overview

[ArgoCD](https://argo-cd.readthedocs.io/en/stable/) exposes Prometheus-format metrics from five components. This guide shows you how to collect those metrics with an OpenTelemetry Collector and send them to SigNoz.

## Prerequisites

- A running ArgoCD installation
- Access to SigNoz ([Cloud](https://signoz.io/teams/) or [Self-Hosted](https://signoz.io/docs/install/self-host/))
- OpenTelemetry Collector deployed

## Setup

<Admonition type="info">
  If you haven't deployed an OpenTelemetry Collector yet, follow the [OpenTelemetry Collection Agents](https://signoz.io/docs/opentelemetry-collection-agents/get-started/) guide before continuing.
</Admonition>

### Step 1. Set environment variables

These variables configure the OTLP exporter in your collector's existing config.

<Tabs>
<TabItem value="vm" label="VM" default>

<KeyPointCallout title="What classifies as VM?" defaultCollapsed="true">
  A VM is a virtual computer that runs on physical hardware. This includes:
  - **Cloud VMs**: AWS EC2, Google Compute Engine, Azure VMs, DigitalOcean Droplets
  - **On-premise VMs**: VMware, VirtualBox, Hyper-V, KVM
  - **Bare metal servers**: Physical servers running Linux/Unix directly

Use this section if you're running the OTel Collector directly on a server without containerization.

</KeyPointCallout>

```bash
export SIGNOZ_OTLP_ENDPOINT="https://ingest.<region>.signoz.cloud:443"
export SIGNOZ_INGESTION_KEY="<your-ingestion-key>"
```

</TabItem>
<TabItem value="kubernetes" label="Kubernetes">

Add these to your OpenTelemetry Collector deployment manifest:

```yaml
env:
  - name: K8S_CLUSTER_NAME
    value: '<your-cluster-name>'
  - name: SIGNOZ_OTLP_ENDPOINT
    value: 'https://ingest.<region>.signoz.cloud:443'
  - name: SIGNOZ_INGESTION_KEY
    value: '<your-ingestion-key>'
```

</TabItem>
<TabItem value="docker" label="Docker">

Set these in your shell before Step 3. The `docker run` command passes them into the container via `-e` flags.

```bash
export SIGNOZ_OTLP_ENDPOINT="https://ingest.<region>.signoz.cloud:443"
export SIGNOZ_INGESTION_KEY="<your-ingestion-key>"
```

</TabItem>
</Tabs>

Verify these values:

- `<region>`: Your SigNoz Cloud [region](https://signoz.io/docs/ingestion/signoz-cloud/overview/#endpoint)
- `<your-ingestion-key>`: Your SigNoz [ingestion key](https://signoz.io/docs/ingestion/signoz-cloud/keys/)
- `<your-cluster-name>` (Kubernetes only): Your Kubernetes cluster identifier

### Step 2. Configure the collector

Append the `prometheus` receiver and `resource/argocd` processor to your collector `config.yaml`:

```yaml
receivers:
  # ... existing receivers ...
  prometheus:
    config:
      global:
        scrape_interval: 60s
        scrape_timeout: 30s
      scrape_configs:
        - job_name: argocd-metrics
          metrics_path: /metrics
          scheme: http
          static_configs:
            - targets:
                # replace with host:port on VM/Docker
                - argocd-metrics.argocd.svc.cluster.local:8082
              labels:
                argocd_component: application-controller

        - job_name: argocd-server-metrics
          metrics_path: /metrics
          scheme: http
          static_configs:
            - targets:
                # replace with host:port on VM/Docker
                - argocd-server-metrics.argocd.svc.cluster.local:8083
              labels:
                argocd_component: api-server

        - job_name: argocd-repo-server-metrics
          metrics_path: /metrics
          scheme: http
          static_configs:
            - targets:
                # replace with host:port on VM/Docker
                - argocd-repo-server.argocd.svc.cluster.local:8084
              labels:
                argocd_component: repo-server

        - job_name: argocd-applicationset-controller-metrics
          metrics_path: /metrics
          scheme: http
          static_configs:
            - targets:
                # replace with host:port on VM/Docker
                - argocd-applicationset-controller.argocd.svc.cluster.local:8080
              labels:
                argocd_component: applicationset-controller

        - job_name: argocd-notifications-controller-metrics
          metrics_path: /metrics
          scheme: http
          static_configs:
            - targets:
                # replace with host:port on VM/Docker
                - argocd-notifications-controller-metrics.argocd.svc.cluster.local:9001
              labels:
                argocd_component: notifications-controller

processors:
  # ... existing processors ...
  resource/argocd:
    attributes:
      - key: service.name
        value: argocd
        action: upsert
```

Next, add them to your metrics pipeline:

```yaml
service:
  pipelines:
    metrics:
      receivers: [..., prometheus]
      processors: [..., resource/argocd, batch]
      exporters: [..., otlp]
```

<Admonition type="info">
  If ArgoCD runs in a different namespace, update the service names accordingly (for example, `argocd-metrics.<your-namespace>.svc.cluster.local`). You can verify your exact service names by running `kubectl get svc -n <your-namespace>`.
</Admonition>

<KeyPointCallout title="Running on Kubernetes?" defaultCollapsed="true">
Add the `k8s.cluster.name` attribute to the `resource/argocd` processor:

```yaml
processors:
  # ...
  resource/argocd:
    attributes:
      - key: service.name
        value: argocd
        action: upsert
      - key: k8s.cluster.name
        value: ${K8S_CLUSTER_NAME}
        action: upsert
```

</KeyPointCallout>

### Step 3. Run the collector

<Tabs>
<TabItem value="vm" label="VM" default>

```bash
otelcol-contrib --config config.yaml
```

</TabItem>
<TabItem value="kubernetes" label="Kubernetes">

```bash
kubectl apply -f otel-collector-argocd-config.yaml -n otel-collector
```

</TabItem>
<TabItem value="docker" label="Docker">

```bash
docker run -d \
  -e SIGNOZ_OTLP_ENDPOINT \
  -e SIGNOZ_INGESTION_KEY \
  -v $(pwd)/config.yaml:/etc/otelcol-contrib/config.yaml \
  otel/opentelemetry-collector-contrib:latest \
  --config /etc/otelcol-contrib/config.yaml
```

</TabItem>
</Tabs>

### Filter internal metrics

Drop OTel Collector self-telemetry and Prometheus scrape metadata before sending to SigNoz. Append the `filter/drop_internal` processor and add it to your pipeline:

```yaml
processors:
  # ... existing processors ...
  filter/drop_internal:
    error_mode: ignore
    metric_conditions:
      - 'IsMatch(metric.name, "^otelcol_.*")'
      - 'IsMatch(metric.name, "^scrape_.*")'
      - 'metric.name == "up"'
```

Include it in your pipeline before the `batch` processor:

```yaml
service:
  pipelines:
    metrics:
      receivers: [..., prometheus]
      processors: [..., resource/argocd, filter/drop_internal, batch]
      exporters: [..., otlp]
```

</details>

## Validate

1. Go to **Metrics** in SigNoz.
2. Search for `argocd_app_info` or any `argocd_`-prefixed metric.
3. Confirm the `argocd_component` label appears on the metrics.

## Troubleshooting

</ToggleHeading>

**No metrics appearing:**

1. Verify the collector reaches the ArgoCD metrics endpoints:

   ```bash
   kubectl port-forward svc/argocd-metrics 8082:8082 -n argocd
   curl localhost:8082/metrics
   ```

2. Check collector logs for scrape errors:

   ```bash
   kubectl logs -n otel-collector <collector-pod-name>
   ```

3. Confirm service names and ports match your ArgoCD deployment.

**Missing component metrics:**

Verify the relevant ArgoCD component is running. Some components expose metrics only when enabled (for example, ApplicationSet Controller, Notifications Controller).

**Dashboard showing no data:**

Confirm the `service.name` resource attribute equals `argocd`. The dashboard queries filter on this label.
