No-auth mode lets SigNoz run without individual user identities. Every request is automatically treated as the root user - there is no login page, no sign-up, and no session management.

This is designed for:

- Single-developer setups
- Small teams operating entirely behind a VPN or firewall
- Air-gapped environments
- CI/automation pipelines where managing user accounts adds unnecessary friction

<Admonition type="warning" title="Network is the trust boundary">
In no-auth mode, authentication is disabled. **Anyone who can reach your SigNoz instance has full root-level access.** Only enable this when network-level controls (VPN, private network, firewall) prevent unauthorized access.
</Admonition>

## Configuration

Set the following environment variables:

```bash
SIGNOZ_IDENTN_IMPERSONATION_ENABLED=true
SIGNOZ_IDENTN_TOKENIZER_ENABLED=false
SIGNOZ_IDENTN_APIKEY_ENABLED=false
```

All three are required - setting only `SIGNOZ_IDENTN_IMPERSONATION_ENABLED` without disabling the tokenizer and API key authenticators will not fully activate no-auth mode.

## What changes in no-auth mode

Once enabled, SigNoz adjusts the UI to reflect the authentication-free context:

- **Login/signup routes are bypassed** - the app redirects directly to the home page.
- **Sign-out is hidden** from the user settings dropdown.
- **A dismissable banner appears on the home page**: *"No-auth mode: authentication is disabled, network is the trust boundary."*
- **User management actions are disabled** with a tooltip - including inviting members, editing member details, managing roles, service accounts, and auth domain settings.

## Validate

After restarting SigNoz with the updated configuration:

1. Open the SigNoz UI. You should be taken directly to the home page without a login prompt.
2. Confirm the no-auth banner appears at the top of the home page.
3. Navigate to **Settings → Members** and verify that the **Invite member** button is disabled with the tooltip *"Not available in no-auth mode"*.

## Disable no-auth mode

To re-enable authentication, set `SIGNOZ_IDENTN_IMPERSONATION_ENABLED` to `false` or remove it:

```bash
SIGNOZ_IDENTN_IMPERSONATION_ENABLED=false
```

## Troubleshooting

### Login page still appears after enabling no-auth mode

- Confirm all three environment variables are set correctly.
- Check SigNoz logs for startup errors related to the identity configuration.

### No-auth banner does not appear

- Confirm the flag is set and the backend is returning `identN.impersonation.enabled: true` from `GET /api/v1/global/config`.
- Hard-refresh the browser (`Ctrl+Shift+R` / `Cmd+Shift+R`) to clear any cached UI state.
