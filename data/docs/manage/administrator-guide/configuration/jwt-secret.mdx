SigNoz issues opaque session tokens by default, and those need no secret. This guide is for administrators who want the JWT provider instead. It covers how to select that provider and set the secret it requires.

<Admonition type="warning" title="JWT is no longer the default in v0.143.0">

Before v0.143.0, JWT was the default, so a secret alone was enough. To keep JWT sessions, set both:

```bash
SIGNOZ_TOKENIZER_PROVIDER=jwt
SIGNOZ_TOKENIZER_JWT_SECRET=<your secret>
```

With the JWT provider and no secret, SigNoz refuses to start:

```bash
jwt::secret must be set when provider is jwt
```

Users sign in again once after the switch. See the [v0.143 upgrade guide](https://signoz.io/docs/operate/migration/upgrade-0-143/) and the <a href="https://github.com/SigNoz/signoz/releases/tag/v0.143.0" target="_blank" rel="noopener noreferrer nofollow">v0.143.0 release notes</a>.

</Admonition>

## How to Set the JWT Secret

1. **Choose a Strong Secret:**  
   Use a long, random string. Avoid using simple or guessable values.

2. **Set the Environment Variables:**  
   Set the following to your environment configuration:

   ```bash
   SIGNOZ_TOKENIZER_PROVIDER=jwt
   SIGNOZ_TOKENIZER_JWT_SECRET=your-very-strong-random-secret
   ```

   The secret must be set, as SigNoz refuses to start with the `jwt` provider and an empty secret.

3. **Restart SigNoz:**  
   After setting the variable, restart your SigNoz services to apply the change.

## Best Practices

- **Never share your JWT secret publicly.**
- **Rotate the secret periodically** and update your environment configuration accordingly.
