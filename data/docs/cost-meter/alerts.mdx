Meter Alerts let you create alert rules on any meter metric — total spend, per-signal spend, or ingestion limits scoped by service, environment, or ingestion key. Alerts fire when a metric crosses a threshold over a configured evaluation window, giving you time to act before costs spiral.

## Why set up Meter Alerts

- **Prevent budget overruns** — get notified when costs approach or exceed your monthly budget
- **Monitor signal breakdown** — know which signals or services are driving increased spend
- **Enforce fair usage** — prevent specific teams, services, or ingestion keys from consuming more than their allocated share
- **Act proactively** — catch unexpected cost spikes before they impact your organization

## How Meter Alerts work

Meter Alerts use the same alerting engine as other SigNoz alert types. You select a meter metric, define a threshold condition, choose an evaluation window (point-in-time or cumulative), and attach notification channels.

<Admonition type="info">
Meter and billing data in SigNoz always use the UTC timezone. Align your alert windows with your organization's billing cycle, or use **Current Month** for monthly budget limits.
</Admonition>

## Alert-compatible metrics

You can set alerts on any of the following meter metrics:

| Metric | Description |
|---|---|
| `signoz.meter.log.count` | Total number of log records ingested |
| `signoz.meter.log.size` | Total size of logs ingested (bytes) |
| `signoz.meter.span.count` | Total number of spans ingested |
| `signoz.meter.span.size` | Total size of spans ingested (bytes) |
| `signoz.meter.metric.datapoint.count` | Number of metric datapoints ingested |

Metrics can be filtered or grouped by `service.name`, `deployment.environment`, `host.name`, and `signoz.workspace.key.id` for granular, targeted alerting.
