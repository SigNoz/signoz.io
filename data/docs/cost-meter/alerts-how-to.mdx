## Overview

This guide walks you through creating a Meter Alert in SigNoz. Meter Alerts fire when a cost or ingestion metric crosses a threshold over a configured evaluation window.

<Admonition type="info">

**Prerequisites:**

- A running SigNoz instance with telemetry data being ingested
- Familiarity with the [Meter Alerts overview](https://signoz.io/docs/cost-meter/alerts/)

</Admonition>

## Steps

### Step 1: Navigate to the Alerts section

Go to **Alerts** in the SigNoz sidebar. Click **New Alert**, then select **Try the new experience**.

<Figure
  src="/img/docs/cost-meter/alerts/navigate-1.png"
  alt="Create alerts (try new experience)"
  caption="Start by creating a new alert in SigNoz"
/>

Choose **Metric Based Alerts** as the alert type.

### Step 2: Select Meter as your data source

In the signal or metric source dropdown, select `meter` under the **Metrics** signal type. From the metrics list, pick the meter metric you want to monitor (for example, `signoz.meter.log.size` for log size or `signoz.meter.span.count` for span counts).

<Figure
  src="/img/docs/cost-meter/alerts/navigate-2.png"
  alt="Select Meter source in the dropdown"
  caption="Choose 'meter' under Metrics to see cost-related metrics"
/>

Optionally, add filters or groupings using available labels (`service.name`, `deployment.environment`, `signoz.workspace.key.id`, etc.) to scope the alert to a specific service, environment, or workspace.

### Step 3: Configure thresholds and evaluation window

Define the condition for when the alert should trigger:

- Set a **threshold** (for example, cumulative log size over 1 GB).
- Choose the aggregation — for cost/usage monitoring, select **In Total** to aggregate all values within the window.
- Set the **evaluation window**:
  - Select **Cumulative** to monitor total usage for the chosen period.
  - Choose a suitable range — **Current Day** for daily alerts, **Current Month** for monthly budget limits.

<Figure
  src="/img/docs/cost-meter/alerts/navigate-3.png"
  alt="Select cumulative window alerts"
  caption="Set up a cumulative window for billing-aligned alerts"
/>

### Step 4: Configure notification channels

Attach notification channels (Email, Slack, PagerDuty, etc.) to receive real-time alerts. Optionally customize the notification message to include context such as the service or environment and a recommended action.

### Step 5: Review and save

Give the alert a clear, descriptive name (for example, "Daily Log Data Budget" or "Prod Ingestion Key Quota Exceeded"). Double-check query conditions, filters, and notification preferences, then click **Save** to activate the alert.

## Verify

After saving, the alert appears in the Alerts list with status **Inactive** until the threshold is first evaluated. Confirm the alert is listed and the query preview shows data by opening the alert detail view.

<details>
<ToggleHeading>
## Troubleshooting
</ToggleHeading>

- **No meter data shown** — Ensure your query time range is larger than 1 hour. Meter data is aggregated hourly and queries under 1 hour return no results.
- **Alert never triggers** — Confirm your condition and threshold accurately reflect the metric's scale (bytes for size metrics, raw counts for count metrics).
- **Mismatch with billing page** — Meter data uses UTC. If usage here doesn't match the billing page, compare values within the same UTC-aligned period.

</details>
