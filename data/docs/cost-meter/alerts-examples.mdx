These examples cover the most common Meter Alert scenarios. Each example walks through the query setup, threshold, and evaluation window. For the setup steps, see [How to Set Up Meter Alerts](https://signoz.io/docs/cost-meter/alerts-how-to/).

## Alert for monthly log costs exceeding $500

1. Go to the billing page to find your per-GB log price (varies based on retention settings).

<Figure
  src="/img/docs/cost-meter/alerts/usecase-1.1.png"
  alt="Per GB logs price from billing page"
  caption="Fetch the price of logs (per GB) from the billing page"
/>

2. In the query builder, select `signoz.meter.log.size` with `timeAggregation` set to `Increase`.
3. Add a formula to convert usage to cost: `(A / 1e9) * (cost per GB)`.

<Figure
  src="/img/docs/cost-meter/alerts/usecase-1.2.png"
  alt="Query for logs ingestion size with formula for calculating the price"
  caption="Query for logs ingestion size with formula for calculating the price"
/>

4. Set the alert threshold on this formula using **In Total** aggregation.
5. Choose **Cumulative** evaluation window with **Current Month** as the time range. Set the start date to match your billing cycle as shown on the billing page.
6. Set the evaluation window start to `00:00:00` UTC (billing is calculated in UTC).

<Figure
  src="/img/docs/cost-meter/alerts/usecase-1.3.png"
  alt="Threshold condition for monthly log billing"
  caption="Threshold condition for monthly log billing"
/>

7. Select a notification channel and save.

## Alert for monthly total costs exceeding $1,000

1. On the billing page, find: per-GB price for logs and spans, and per-million datapoint price for metrics.

<Figure
  src="/img/docs/cost-meter/alerts/usecase-2.1.png"
  alt="Per GB price for logs and spans, per million data point price for metrics from billing page"
  caption="Per GB price for logs and spans, per million datapoints for metrics from the billing page"
/>

2. In the query builder, add three queries:
   - `signoz.meter.log.size` with `timeAggregation: Increase`
   - `signoz.meter.span.size` with `timeAggregation: Increase`
   - `signoz.meter.metric.datapoint.count` with `timeAggregation: Increase`

3. Combine with a formula for total cost:
   - Logs: `(A / 1e9) * (cost per GB of logs)`
   - Spans: `(B / 1e9) * (cost per GB of spans)`
   - Metrics: `(C / 1e6) * (cost per million datapoints)`
   - Total: sum all three components

<Figure
  src="/img/docs/cost-meter/alerts/usecase-2.2.png"
  alt="Query for total ingestion with formula for calculating the price"
  caption="Query for total ingestion with formula for calculating the price"
/>

4. Apply the formula as the threshold condition with **In Total** aggregation.
5. Use **Cumulative** window, **Current Month** range. Set the start date from your billing cycle and align to `00:00:00` UTC.

<Figure
  src="/img/docs/cost-meter/alerts/usecase-2.3.png"
  alt="Threshold condition for monthly billing"
  caption="Threshold condition for monthly billing"
/>

6. Choose a notification channel and save.

## Alert when an ingestion key is nearing its daily quota

1. Go to the Ingestion Keys page and expand the key you want to monitor.
2. Click the **bell** icon next to the daily limit for the relevant signal type.

<Figure
  src="/img/docs/cost-meter/alerts/usecase-3.1.png"
  alt="Ingestion Keys Page for alerting"
  caption="Ingestion Keys Page — click the bell icon to set an alert for a specific key"
/>

3. You are redirected to the Alerts page with a pre-filled query that includes all necessary fields.

<Figure
  src="/img/docs/cost-meter/alerts/usecase-3.2.png"
  alt="Query for ingestion key limits based alert"
  caption="Pre-filled query for ingestion key limits"
/>

4. Give the alert a meaningful name, choose a notification channel, and save.

## Alert when any service ingests over 1 million spans in a day

1. Select `signoz.meter.span.count` and add a **group by** for `service.name` to monitor spans per service.

<Figure
  src="/img/docs/cost-meter/alerts/usecase-4.1.png"
  alt="Query for span count per service"
  caption="Span count grouped by service.name"
/>

2. Set the threshold to 1,000,000 spans with **In Total** aggregation.
3. Set evaluation window to **Cumulative** with **Current Day** range.

<Figure
  src="/img/docs/cost-meter/alerts/usecase-4.2.png"
  alt="Threshold for any service exceeding 1M spans in a day"
  caption="Threshold for any service exceeding 1M spans in a day"
/>

4. Configure notifications and save.

## Best practices

- **Align thresholds with budgets** — set alert thresholds just below your actual budget limit to allow time for action before the limit is hit.
- **Review regularly** — periodically revisit alert thresholds as usage patterns change over time.
- **Use UTC-aligned windows** — billing is calculated in UTC; ensure your cumulative window start matches `00:00:00` UTC to avoid discrepancies with the billing page.
