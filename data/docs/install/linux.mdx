Use this page to install SigNoz on a Linux host that runs systemd. You use <a href="https://github.com/SigNoz/foundry" target="_blank" rel="noopener noreferrer nofollow">Foundry</a> to create and manage the systemd units for SigNoz, ClickHouse, ClickHouse Keeper, PostgreSQL, the SigNoz OTel Collector, and the database migrator.

## Prerequisites

- A Linux host with systemd.
- Root access or a user with **sudo** privileges.
- Open inbound ports: **8080** for the SigNoz UI, and **4317** and **4318** for OpenTelemetry Protocol (OTLP) ingestion.
- At least 4 GB of memory for a small test installation. For production sizing, see [resource planning](https://signoz.io/docs/setup/capacity-planning/community/resources-planning/).

## Install SigNoz

<Admonition type="info" title="Why use Foundry?" defaultCollapsed="true">
Foundry turns one `casting.yaml` file into the service files, configs, users, directories, and startup order that SigNoz needs on systemd.
</Admonition>

### Step 1: Install foundryctl

Run the installer on the Linux host:

```bash
curl -fsSL https://signoz.io/foundry.sh | bash
```

Add `foundryctl` to your current shell and verify the install:

```bash
export PATH="$HOME/.local/bin:$PATH"
foundryctl --help
```

Persist the PATH change by adding the same line to your shell profile (`~/.bashrc` for bash, `~/.zshrc` for zsh):

```bash
echo 'export PATH="$HOME/.local/bin:$PATH"' >> ~/.bashrc
```

For manual install options or version pinning, see the <a href="https://github.com/SigNoz/foundry/blob/main/docs/getting-started.md" target="_blank" rel="noopener noreferrer nofollow">Foundry getting-started guide</a>.

### Step 2: Install host dependencies

Install ClickHouse with the <a href="https://clickhouse.com/docs/install" target="_blank" rel="noopener noreferrer nofollow">official ClickHouse installation guide</a>. The single `clickhouse` binary serves both the telemetry store and the keeper, so no separate Keeper package is needed. Foundry manages the ClickHouse services after deployment, so stop any package-managed services:

```bash
sudo systemctl disable --now clickhouse-server.service clickhouse-keeper.service 2>/dev/null || true
```

Install PostgreSQL with the <a href="https://www.postgresql.org/download/linux/" target="_blank" rel="noopener noreferrer nofollow">official PostgreSQL Linux installation guide</a>, then stop the package-managed service:

```bash
sudo systemctl disable --now postgresql.service
```

On Debian and Ubuntu, PostgreSQL stores binaries under `/usr/lib/postgresql/<version>/bin`. Expose the latest installed version where Foundry expects it:

```bash
PG_VERSION=$(ls /usr/lib/postgresql/ | sort -V | tail -n 1)
sudo ln -sf /usr/lib/postgresql/${PG_VERSION}/bin/initdb /usr/bin/initdb
sudo ln -sf /usr/lib/postgresql/${PG_VERSION}/bin/postgres /usr/bin/postgres
sudo ln -sf /usr/lib/postgresql/${PG_VERSION}/bin/pg_ctl /usr/bin/pg_ctl
```

For other distributions, create equivalent links or set binary path annotations in `casting.yaml`. See the <a href="https://github.com/SigNoz/foundry/tree/main/docs/examples/systemd/binary" target="_blank" rel="noopener noreferrer nofollow">Foundry systemd binary example</a>.

### Step 3: Download SigNoz binaries

Download the SigNoz and SigNoz OTel Collector release archives into the paths that the Foundry systemd casting uses:

```bash
ARCH=$(uname -m | sed 's/x86_64/amd64/' | sed 's/aarch64/arm64/')

sudo mkdir -p /opt/signoz
curl -fsSL "https://github.com/SigNoz/signoz/releases/latest/download/signoz_linux_${ARCH}.tar.gz" \
  | sudo tar -xz --strip-components=1 -C /opt/signoz

sudo mkdir -p /opt/ingester
curl -fsSL "https://github.com/SigNoz/signoz-otel-collector/releases/latest/download/signoz-otel-collector_linux_${ARCH}.tar.gz" \
  | sudo tar -xz --strip-components=1 -C /opt/ingester
```

<Admonition type="info">
Extract the full SigNoz tarball; do not move the `signoz` binary on its own. It loads the web UI and email/alert templates relative to itself, so `bin/`, `web/`, `templates/`, and `conf/` must stay together.
</Admonition>

`foundryctl cast` creates the `signoz` service user and the data directories automatically.

### Step 4: Create casting.yaml

Create a working directory outside `/root` so the generated `pours/` files remain readable by the `signoz` system user:

```bash
sudo mkdir -p /opt/signoz-foundry
sudo chown "$(id -u):$(id -g)" /opt/signoz-foundry
cd /opt/signoz-foundry
```

Create `casting.yaml` for the systemd binary deployment:

```bash
cat <<'EOF' > casting.yaml
apiVersion: v1alpha1
kind: Installation
metadata:
  name: signoz
spec:
  deployment:
    flavor: binary
    mode: systemd
EOF
```

### Step 5: Deploy with Foundry

Run the full deployment pipeline:

```bash
sudo foundryctl cast -f casting.yaml
```

`foundryctl cast` validates dependencies, generates service files and configs under `pours/`, installs systemd units, and starts the SigNoz services.

<Admonition type="warning" title="Note">
`foundryctl cast` needs `sudo` because it writes to system directories and manages systemd services.
</Admonition>

### Step 6: Validate the installation

Check that the main services are running:

```bash
systemctl status signoz-signoz.service
systemctl status signoz-ingester.service
systemctl status signoz-telemetrystore-clickhouse-0-0.service
systemctl status signoz-telemetrykeeper-clickhousekeeper-0.service
systemctl status signoz-metastore-postgres.service
```

Each service should show `active (running)`.

View logs for all SigNoz services:

```bash
journalctl -u 'signoz-*' -f
```

View logs for one service:

```bash
journalctl -u signoz-signoz.service -f
```

Open `http://<your-server-ip>:8080/` in a browser. The SigNoz setup screen should load.

### Step 7: Enable the SigNoz MCP server (optional)

Foundry can also deploy the <a href="https://github.com/SigNoz/foundry/blob/main/docs/concepts/mcp-server.md" target="_blank" rel="noopener noreferrer nofollow">SigNoz MCP server</a> alongside the stack so AI clients can query your telemetry. It is disabled by default.

1. Download the MCP server binary into the path the casting expects:

   ```bash
   ARCH=$(uname -m | sed 's/x86_64/amd64/' | sed 's/aarch64/arm64/')
   sudo mkdir -p /opt/mcp
   curl -fsSL "https://github.com/SigNoz/signoz-mcp-server/releases/latest/download/signoz-mcp-server_linux_${ARCH}.tar.gz" \
     | sudo tar -xz --strip-components=1 -C /opt/mcp
   ```

2. Add an `mcp` block under `spec` in `casting.yaml`:

   ```yaml
   apiVersion: v1alpha1
   kind: Installation
   metadata:
     name: signoz
   spec:
     deployment:
       flavor: binary
       mode: systemd
     mcp:
       spec:
         enabled: true
   ```

3. Re-run cast to add the MCP service on port `8000`:

   ```bash
   sudo foundryctl cast -f casting.yaml
   ```

   Verify it is live:

   ```bash
   curl -fsS localhost:8000/livez && echo " OK"
   ```

4. Create an API key from a [service account](https://signoz.io/docs/manage/administrator-guide/iam/service-accounts/) (**Settings → Service Accounts**, requires **Admin** role).

5. Add the server to your AI client. For example, with Claude Code:

   ```bash
   claude mcp add --scope user --transport http signoz http://localhost:8000/mcp \
     --header "SIGNOZ-API-KEY: <your-api-key>"
   ```

   - `<your-api-key>`: the key from step 4

   To confirm the connection, run `/mcp` inside Claude Code and check that the `signoz` server is listed as connected.

For other clients and example workflows, see [SigNoz MCP Server](https://signoz.io/docs/ai/signoz-mcp-server/) and [AI use cases](https://signoz.io/docs/ai/use-cases/).

## Customize the installation

Every change follows the same loop: edit `casting.yaml`, then re-run `foundryctl cast` to apply it.

- **Binary locations**: if a component lives outside its default path, point Foundry at it with a binary-path annotation under `metadata.annotations`. The <a href="https://github.com/SigNoz/foundry/tree/main/docs/examples/systemd/binary" target="_blank" rel="noopener noreferrer nofollow">systemd binary example</a> lists every annotation.
- **Anything Foundry does not model**: add <a href="https://github.com/SigNoz/foundry/blob/main/docs/concepts/patches.md" target="_blank" rel="noopener noreferrer nofollow">patches</a> under `spec.patches`. Do not edit the generated files in `pours/` by hand, since `forge` overwrites them.
- **Pin a version**: download a specific SigNoz or SigNoz OTel Collector release in Step 3 instead of `latest`.

## Troubleshooting
</ToggleHeading>

### `foundryctl cast` fails

Re-run the failing command with `--debug` for verbose logs:

```bash
sudo foundryctl cast -f casting.yaml --debug
```

### `sudo` cannot find `foundryctl`

Run `foundryctl` through `sudo` with your current PATH:

```bash
sudo env "PATH=$PATH" foundryctl cast -f casting.yaml
```

You can also install `foundryctl` into a system path such as `/usr/local/bin`.

### ClickHouse cannot connect to Keeper on Ubuntu

On some Ubuntu hosts, `localhost` resolves to `::1` first while ClickHouse Keeper listens on IPv4. If `signoz-telemetrystore-clickhouse-0-0.service` fails to start, replace `localhost` with `127.0.0.1` in the generated config:

```bash
sudo sed -i 's/host: localhost/host: 127.0.0.1/' /etc/clickhouse-server/config-0-0.yaml
sudo systemctl restart signoz-telemetrystore-clickhouse-0-0.service
```

Check the service logs again:

```bash
journalctl -u signoz-telemetrystore-clickhouse-0-0.service -f
```

### A SigNoz service fails after cast

Inspect the unit and logs for the failing service:

```bash
systemctl status <service-name>
journalctl -u <service-name> -n 200 --no-pager
```
