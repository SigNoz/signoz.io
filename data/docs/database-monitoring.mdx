SigNoz monitors your databases across three layers of telemetry:

- **Metrics** — connection counts, query throughput, cache hit ratios, replication lag, and disk usage, collected by OpenTelemetry Collector receivers or by scraping the database's Prometheus exporter.
- **Logs** — error logs, slow query logs, and audit logs, parsed into structured fields you can search and alert on.
- **Traces** — individual database calls captured as spans from your instrumented application, so a slow endpoint can be traced to the exact query behind it.

Pick your database below. If you run a managed database from a cloud provider, use the cloud sections — those integrations pull metrics from the provider's monitoring API rather than connecting to the database directly.

<Admonition type="info">
For the fullest picture, set up both database telemetry (this page) and [application instrumentation](https://signoz.io/docs/instrumentation/overview/). Database metrics tell you *that* the database is slow; traces tell you *which query* and *which endpoint* caused it.
</Admonition>

## Setting Up Alerts

Once metrics are flowing, create alerts on the signals that matter for your database — connection saturation, replication lag, disk usage, or slow query volume. See [creating alert rules](https://signoz.io/docs/alerts-management/metrics-based-alerts/) to get started.
