Alerts in SigNoz give you proactive monitoring across all telemetry signals. Configure alert rules on metrics, logs, traces, anomalies, exceptions, or Apdex scores, and route notifications to the right team through your preferred channels.

## Key capabilities

- **6 alert types**: Cover every signal and use case — from threshold-based metric alerts to anomaly detection based on historical baselines.
- **Routing policies**: Direct alert notifications to the right team or channel based on labels, severity, or service ownership.
- **Planned maintenance windows**: Suppress alerts during scheduled downtime to avoid alert fatigue from known events.
- **Alert history**: Review a full history of alert firings and resolutions to understand patterns and recurrence.
- **Terraform support**: Manage alert rules as code using the [SigNoz Terraform provider](https://signoz.io/docs/alerts-management/terraform-provider-signoz/) for repeatable, version-controlled alert configuration.

## Alert types

SigNoz supports six alert types to cover all monitoring scenarios:

- **Metrics-based**: Trigger alerts when a metric query crosses a threshold. Suitable for CPU usage, latency percentiles, error rates, and any other numeric metric.
- **Logs-based**: Fire alerts when a log query matches a pattern, count, or attribute condition. Use this to detect error bursts, security events, or missing log lines.
- **Trace-based**: Alert on span conditions such as high p99 latency, elevated error counts, or specific attribute values on traces. Ideal for SLO enforcement at the service level.
- **Anomaly**: Alert when a metric deviates from its expected historical baseline. Catches unexpected changes without requiring a hardcoded threshold.
- **Exceptions**: Alert on new or recurring exceptions reported by instrumented services. Integrates with the Exceptions view for context.
- **Apdex**: Alert when user satisfaction scores fall below a configured target. Combines latency thresholds into a single user-experience signal.
