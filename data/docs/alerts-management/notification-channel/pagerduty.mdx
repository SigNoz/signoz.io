## Prerequisites

Before setting up PagerDuty as a notification channel in SigNoz, ensure the following:

- **Valid Integration Key**: You have a valid Integration Key (also known as Routing Key) from PagerDuty.
- **SigNoz Version**: <a href="https://github.com/SigNoz/signoz/releases/tag/v0.8.0" target="_blank" rel="noopener noreferrer nofollow">v0.8.0</a> or later

There are two main ways to integrate with PagerDuty:

- **Global <a href="https://support.pagerduty.com/docs/event-orchestration" target="_blank" rel="noopener noreferrer nofollow">Event Orchestration</a>**: Ideal for automating incident creation and management.
- **Direct Integration on <a href="https://support.pagerduty.com/docs/services-and-integrations" target="_blank" rel="noopener noreferrer nofollow">PagerDuty service</a>**: Suitable for specific service-level integrations.

## Obtaining Integration or Routing key

### For Global Event Orchestration

1. From the **AIOps** menu, select **Event Orchestration**
2. Select or create your orchestration
3. Expand **Global Orchestration Key** and copy the **Integration Key** shown there. Keep it safe for later use.

<Admonition type="note">
PagerDuty updates its own UI independently of this doc. If your navigation looks different from the screenshot below, follow PagerDuty's <a href="https://support.pagerduty.com/docs/event-orchestration" target="_blank" rel="noopener noreferrer nofollow">Event Orchestration documentation</a> instead.
</Admonition>

### For PagerDuty Service Integration

1. Navigate to **Services > Service Directory** and select the **service** where you’d like to add the integration.
2. Select **Integration tab** and click **Add another integration**
3. Select **Events API V2** from the list
4. Click **Add**
5. Locate your integration in the list and click down arrow to view and copy integration key.

For more details on PagerDuty service setup, visit <a href="https://support.pagerduty.com/docs/services-and-integrations#add-integrations-to-an-existing-service" target="_blank" rel="noopener noreferrer nofollow">PagerDuty Service and Integrations</a>.

## Create a New PagerDuty Channel

To create a new PagerDuty notification channel in SigNoz, follow these steps:

- Navigate to `Settings > Account Settings > Notification Channels` and click on `New Channel`.
- Enter a **Name** for the channel and select PagerDuty as the channel type.
- **Routing Key**: Enter Routing Key (Integration Key) obtained from PagerDuty.
- **More information**: Enter more information as necessary. Refer to the <a href="https://developer.pagerduty.com/docs/ZG9jOjExMDI5NTgw-events-api-v2-overview" target="_blank" rel="noopener noreferrer nofollow">Events API V2 Overview</a> for more details.

<Admonition>
You can use <a href="https://prometheus.io/docs/alerting/latest/notifications/" target="_blank" rel="noopener noreferrer nofollow">Go templates</a> for customizing the title and description.
</Admonition>

**Test Configuration**:
Click the Test button to test the connection with your application.

## Turn-off Resolved alerts

The resolve alerts toggle is switched on by default. To turn-off receiving the Resolved alerts for your Notification Channel, follow these steps:

- Navigate to `Settings > Account Settings > Notification Channels`
- Click on `Edit` button for a particular alert.
- Toggle off the **Send resolved alerts** button and hit `Save`.

## Configure programmatically

You can also configure the PagerDuty notification channel programmatically using the SigNoz API.

**API Endpoint:** `POST /api/v1/channels`

To create a new PagerDuty notification channel, send a `POST` request to the `/api/v1/channels` endpoint with the following `curl` command. Replace `YOUR_API_KEY` with an API key from **Settings → Service Accounts** (see [Service Accounts](https://signoz.io/docs/manage/administrator-guide/iam/service-accounts/) to create one).

```bash
curl 'YOUR_SIGNOZ_CLOUD_URL/api/v1/channels' \
  -H 'SIGNOZ-API-KEY: YOUR_API_KEY' \
  -H 'Content-Type: application/json' \
  --data-raw '{
    "name": "Platform Team - PagerDuty",
    "pagerduty_configs": [
        {
            "send_resolved": true,
            "routing_key": "PagerDutyRoutingKey",
            "client": "SigNoz Alert Manager",
            "client_url": "YOUR_SIGNOZ_CLOUD_URL/alerts",
            "description": "[{{ .Status | toUpper }}{{ if eq .Status \"firing\" }}:{{ .Alerts.Firing | len }}{{ end }}] {{ .CommonLabels.alertname }} for {{ .CommonLabels.job }}\n\t{{- if gt (len .CommonLabels) (len .GroupLabels) -}}\n\t {{\" \"}}(\n\t {{- with .CommonLabels.Remove .GroupLabels.Names }}\n\t\t{{- range $index, $label := .SortedPairs -}}\n\t\t {{ if $index }}, {{ end }}\n\t\t {{- $label.Name }}=\"{{ $label.Value -}}\"\n\t\t{{- end }}\n\t {{- end -}}\n\t )\n\t{{- end }}",
            "severity": "{{ (index .Alerts 0).Labels.severity }}",
            "class": "class1",
            "component": "Component1",
            "group": "group1",
            "details": {
                "firing": "{{ template \"pagerduty.default.instances\" .Alerts.Firing }}",
                "resolved": "{{ template \"pagerduty.default.instances\" .Alerts.Resolved }}",
                "num_firing": "{{ .Alerts.Firing | len }}",
                "num_resolved": "{{ .Alerts.Resolved | len }}"
            }
        }
    ]
}'
```

**Request Body Attributes:**

| Field                               | Type      | Description                                                                       |
| :---------------------------------- | :-------- | :-------------------------------------------------------------------------------- |
| `name`                              | `string`  | The name of the receiver/channel. **Required**; must be unique in all the config. |
| `pagerduty_configs`                 | `array`   | List of PagerDuty configurations.                                                 |
| `pagerduty_configs[].send_resolved` | `boolean` | Whether to send notifications when an alert is resolved.                          |
| `pagerduty_configs[].routing_key`   | `string`  | The PagerDuty Integration Key (Routing Key). **Mandatory**.                       |
| `pagerduty_configs[].client`        | `string`  | Client identification string.                                                     |
| `pagerduty_configs[].client_url`    | `string`  | Client URL.                                                                       |
| `pagerduty_configs[].description`   | `string`  | Templated description of the incident.                                            |
| `pagerduty_configs[].severity`      | `string`  | Severity of the incident (critical, error, warning, info).                        |
| `pagerduty_configs[].class`         | `string`  | Class of the event.                                                               |
| `pagerduty_configs[].component`     | `string`  | Component of the event.                                                           |
| `pagerduty_configs[].group`         | `string`  | Group of the event.                                                               |
| `pagerduty_configs[].details`       | `object`  | Additional details to include in the incident.                                    |

## Troubleshooting

If you encounter issues with the PagerDuty integration:

- **Check the Integration Key**: Ensure that the Routing Key or Integration Key is correctly entered in SigNoz.
- **Verify PagerDuty Configuration**: Confirm that the PagerDuty service or global event orchestration is set up correctly.
- **Test Connectivity**: Use the Test button in SigNoz to verify connectivity with PagerDuty. If the test fails, review your network settings and integration key.
