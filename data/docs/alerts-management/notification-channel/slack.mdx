## Overview

A Slack notification channel sends SigNoz alerts to Slack through an Incoming Webhook URL. Slack posts every alert to the channel that the webhook is bound to. You can then reuse this notification channel in any alert rule.

This page covers the webhook setup, channel creation in the SigNoz UI, validation, Slack group mentions, and the API equivalent.

## Prerequisites

Before you configure Slack as a notification channel, you need:

- **Incoming Webhook**: Follow the steps outlined in <a href="https://docs.slack.dev/messaging/sending-messages-using-incoming-webhooks" target="_blank" rel="noopener noreferrer nofollow">sending messages to Slack using Incoming Webhooks</a> to set up an Incoming Webhook in your Slack workspace. Create it from a **Slack app**, not from Workflow Builder. The URL must start with `https://hooks.slack.com/services/`.
- **SigNoz Version**: <a href="https://github.com/SigNoz/signoz/releases/tag/v0.5.0" target="_blank" rel="noopener noreferrer nofollow">v0.5.0</a> or later

<Admonition type="warning">
Slack has two kinds of webhook, and only one works with SigNoz.

- **App Incoming Webhook** (works): the URL starts with `https://hooks.slack.com/services/`. Slack posts the message body as sent.
- **Workflow Builder webhook** (does not work): the URL starts with `https://hooks.slack.com/triggers/`. This URL starts a workflow and accepts only the input variables that the workflow declares. It rejects the alert message that SigNoz sends.

If your webhook URL contains `/triggers/`, create an app Incoming Webhook instead.

</Admonition>

## Create a Notification Channel

To create a new Slack notification channel in SigNoz, follow these steps:

1. Navigate to `Alerts > Notification Channels` and click **New Channel**. The create page opens with an **All channels** back-link on the first row and the **New channel** title on the second. If you start from a Slack-filtered list, use **New Slack Channel** instead: the **Type** is pre-selected as Slack and the back-link returns you to that same filtered list.
2. In the **General** section, enter a **Name**, set the **Send resolved alerts** toggle, and select Slack as the **Type**. Both **Send resolved alerts** and **Type** show a tooltip (hover the `?` icon) that explains what the control does.
3. In the **Connection** section, paste the Incoming Webhook URL into **Webhook URL**. **Recipient** is optional: for an app Incoming Webhook it does not change where the alert lands (see the note below); the webhook always posts to its bound channel.
4. In the **Message** section, keep the default **Title** and **Description** templates, or edit them to change the message that SigNoz posts.
5. Click **Save**. **Save** stays disabled until you change at least one field; hovering it before then shows the tooltip **Nothing has changed yet.**

<Admonition type="info">
**Discard** sits at the bottom-left of the action bar. If you have not changed anything, it exits immediately. If there are unsaved changes, a **Discard your changes?** dialog asks you to confirm before leaving.
</Admonition>

<Admonition type="info">
An app Incoming Webhook is bound to the channel that was selected when the Slack app was installed. Slack does not let the request body override that destination, so the **Recipient** value cannot redirect an alert to a different channel or to a direct message. To post to another channel, create a second Incoming Webhook for that channel and a second notification channel in SigNoz. See <a href="https://docs.slack.dev/messaging/sending-messages-using-incoming-webhooks" target="_blank" rel="noopener noreferrer nofollow">Slack: sending messages using Incoming Webhooks</a>.
</Admonition>

<Admonition>
  You can use <a href="https://prometheus.io/docs/alerting/latest/notifications/" target="_blank" rel="noopener noreferrer nofollow">Go templates</a> for customizing the title and description.
</Admonition>

## Customize the Message

The Slack channel form is organised into three sections: **Connection** (Webhook URL and Recipient), **Message** (Title and Description), and **Advanced**. The **Advanced** section holds the rest of what Slack calls an attachment and is described in the form as "The rest of the Slack attachment. Every box here is optional." All of these boxes accept <a href="https://prometheus.io/docs/alerting/latest/notifications/" target="_blank" rel="noopener noreferrer nofollow">Go templates</a>, so they can read values off the alert.

<Figure
  src="/img/docs/notification-channels/slack-form-advanced.webp"
  alt="Advanced section of the SigNoz Slack channel form with Color, Pretext, Fallback text, Footer, Fields, and Actions."
  caption="The Advanced section holds the optional Slack attachment boxes."
/>

| Option | What Slack does with it |
| --- | --- |
| **Title link** | Turns the title into a link. Use it to point at a dashboard or a runbook. |
| **Color** | The bar down the left of the message. `good`, `warning`, `danger`, or a hex value such as `#439FE0`. A template lets you colour by status. |
| **Pretext** | A line above the attachment, outside the coloured block. |
| **Fallback text** | Plain text shown wherever the attachment cannot render, such as a push notification on a phone. |
| **Footer** | A small line under the message, usually where the alert came from. |

### Fields

Fields are a small table inside the attachment. In the **Advanced** section, each field is a numbered card (**FIELD 1**, **FIELD 2**, and so on) with a remove control in its top-right corner. Click **Add field** to append another card. Each one has a **title**, which Slack shows in bold, and a **value** under it.

**Short** controls the layout. With it on, Slack places the field in a narrow column and can sit two of them side by side. With it off, the field takes the full width of the attachment. Use short for things like a severity or an environment, and leave it off for anything long.

<Figure
  src="/img/docs/notification-channels/slack-fields-cards.webp"
  alt="Two numbered field cards, FIELD 1 and FIELD 2, in the Advanced section of the SigNoz Slack channel form, each with Title, Value, and Short inputs."
  caption="Fields and Actions appear as individually numbered cards."
/>

### Actions

Actions are buttons Slack renders under the message, added from the **Advanced** section. Like Fields, each action is a numbered card with a remove control; click **Add action** to append another. There are two kinds.

A **link button** needs only **text** and a **URL**. Slack shows the text and opens the URL when someone clicks it. This is the one most alerts want: a link to the runbook, the dashboard or the trace.

A **callback button** is handled by a Slack app rather than opening a link. It uses **name** and **value** so the app can tell which button was pressed, and it needs an app configured to receive Slack's interactivity payload. Without one, the button does nothing.

Either kind can set **style**, which is `default`, `primary` or `danger` and decides the button's colour, and **confirm**, which is the text of a prompt Slack shows before the action runs. Leave confirm empty for no prompt.

<Admonition type="info">
Slack renders at most five actions per attachment. For the full rules, see <a href="https://docs.slack.dev/messaging/formatting-message-text" target="_blank" rel="noopener noreferrer nofollow">Slack: formatting message text</a>.
</Admonition>

## Validate

1. On the channel form, click **Test**. SigNoz posts a test alert through the webhook.
2. Open the Slack channel that the webhook is bound to. This is the channel that was selected when the Slack app was installed. A test alert message from SigNoz appears within a few seconds.
3. Click **Save**. The channel now appears in the list under `Alerts > Notification Channels`.

If no message reaches Slack, see [Troubleshooting](#troubleshooting).

## Mention Slack Groups in Alerts

To tag a Slack user group in an alert, use the group mention format below. A plain group name stays plain text and notifies nobody.

### Slack Group Mention Format

Use this format, where `GROUP_ID` is the unique identifier of your Slack group:

```text
<!subteam^GROUP_ID>
```

### Find Your Group ID

To find the Group ID for your Slack group:

1. In Slack, go to your group's settings
2. The Group ID will be displayed in the group information
3. Copy this ID and use it in the format above

### Example

If your group ID is `S1234567890`, your mention should look like:

```text
<!subteam^S1234567890>
```

You can include this format in the **Title** or **Description** fields when creating or editing a notification channel. The mention has to sit in the message body, because that is what Slack renders. The **Description** field maps to `text` in the API payload.

For more detailed information about Slack message formatting, refer to the <a href="https://docs.slack.dev/messaging/formatting-message-text/#mentioning-groups" target="_blank" rel="noopener noreferrer nofollow">official Slack documentation on mentioning groups</a>.

## Edit a Notification Channel

To edit an existing Slack notification channel:

- Navigate to `Alerts > Notification Channels` and select the channel (or use its **Actions** menu). The edit page opens with an **All channels** back-link on the first row and the channel name on the second. While the name is being fetched, the header shows a loading indicator in its place.
- Next to the name, use the **Copy channel ID** button to copy the channel's ID (hover it to see the tooltip).
- You can edit the Slack webhook URL and other parameters. The channel **Name** and **Type** are disabled, because they cannot change after creation.

## Turn Off Resolved Alerts

The **Send resolved alerts** toggle lives in the **General** section and is switched on by default, on both the create form and the edit form. To stop receiving resolved alerts for an existing channel, follow these steps:

- Navigate to `Alerts > Notification Channels`.
- Select the channel to open its edit page.
- In the **General** section, toggle off **Send resolved alerts** and click `Save`.

## Configure Programmatically

You can also create the Slack notification channel with the SigNoz API instead of the UI.

**API Endpoint:** `POST /api/v1/channels`

To create a new Slack notification channel, send a `POST` request to the `/api/v1/channels` endpoint with the following `curl` command.

```bash
curl '<your-signoz-cloud-url>/api/v1/channels' \
  -H 'SIGNOZ-API-KEY: <your-api-key>' \
  -H 'Content-Type: application/json' \
  --data-raw '{
    "name": "Prod Critical Alerts - Slack",
    "slack_configs": [
        {
            "send_resolved": true,
            "api_url": "https://hooks.slack.com/services/<your-webhook-path>",
            "channel": "#prod-critical-alerts",
            "title": "[{{ .Status | toUpper }}{{ if eq .Status \"firing\" }}:{{ .Alerts.Firing | len }}{{ end }}] {{ .CommonLabels.alertname }} for {{ .CommonLabels.job }}\n {{- if gt (len .CommonLabels) (len .GroupLabels) -}}\n {{\" \"}}(\n {{- with .CommonLabels.Remove .GroupLabels.Names }}\n {{- range $index, $label := .SortedPairs -}}\n {{ if $index }}, {{ end }}\n {{- $label.Name }}=\"{{ $label.Value -}}\"\n {{- end }}\n {{- end -}}\n )\n {{- end }}",
            "text": "{{ range .Alerts -}}\n *Alert:* {{ .Labels.alertname }}{{ if .Labels.severity }} - {{ .Labels.severity }}{{ end }}\n\n *Summary:* {{ .Annotations.summary }}\n *Description:* {{ .Annotations.description }}\n *RelatedLogs:* {{ if gt (len .Annotations.related_logs) 0 -}} View in <{{ .Annotations.related_logs }}|logs explorer> {{- end}}\n *RelatedTraces:* {{ if gt (len .Annotations.related_traces) 0 -}} View in <{{ .Annotations.related_traces }}|traces explorer> {{- end}}\n\n *Details:*\n {{ range .Labels.SortedPairs }} • *{{ .Name }}:* {{ .Value }}\n {{ end }}\n {{ end }}"
        }
    ]
}'
```

**Verify these values:**

- `<your-signoz-cloud-url>`: The base URL of your SigNoz instance, for example `https://<your-organization>.signoz.cloud`.
- `<your-api-key>`: An API key from `Settings > Service Accounts`. See [Service Accounts](https://signoz.io/docs/manage/administrator-guide/iam/service-accounts/) to create one.
- `<your-webhook-path>`: The path of your Slack Incoming Webhook URL, which follows `https://hooks.slack.com/services/`.

**Request Body Attributes:**

| Field                           | Type      | Description                                                                                                                                  |
| :------------------------------ | :-------- | :------------------------------------------------------------------------------------------------------------------------------------------- |
| `name`                          | `string`  | The name of the receiver/channel. **Required**; must be unique in all the config.                                                            |
| `slack_configs`                 | `array`   | List of Slack configurations.                                                                                                                |
| `slack_configs[].send_resolved` | `boolean` | Whether to send notifications when an alert is resolved.                                                                                     |
| `slack_configs[].api_url`       | `string`  | The Slack Incoming Webhook URL. **Mandatory**. Must be a valid URL.                                                                          |
| `slack_configs[].channel`       | `string`  | The channel or user to send notifications to. Slack ignores this value for an app Incoming Webhook, which always posts to its bound channel. |
| `slack_configs[].title`         | `string`  | Templated title of the message. Go templates are supported.                                                                                  |
| `slack_configs[].text`          | `string`  | Templated text of the message. Go templates are supported.                                                                                   |

## Troubleshooting

If you encounter issues:

- **Check the Webhook URL**: Make sure that the webhook URL is entered correctly in SigNoz.
- **Alerts never arrive and the URL contains `/triggers/`**: That URL is a Workflow Builder webhook, which cannot post a SigNoz alert message. Create an app Incoming Webhook (`https://hooks.slack.com/services/...`) and paste that URL instead.
- **Check Slack Permissions**: Make sure that the webhook has permission to post to the target channel.
