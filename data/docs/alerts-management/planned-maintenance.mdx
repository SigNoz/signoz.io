## Overview

Use planned maintenance to schedule maintenance windows for your services. This helps you to avoid alerting during maintenance windows and to resume alerts after the maintenance window is over. The alerts continue to be evaluated, but the notifications are suppressed during the maintenance window.

The **Planned Downtime** page lists every maintenance window in a full-width, sortable table. The default columns are **Downtime** (name), **Status**, **Schedule**, **Repeats**, and **Alerts Silenced**, and the page header shows a count pill with the total number of downtimes.

## Create a Maintenance Window

To create a maintenance window, go to **Alerts > Configuration > Planned Downtime** and click the **+ New downtime** button in the top-right corner.

### Types of maintenance windows

SigNoz supports two types of maintenance schedules:

- **One-time**: A maintenance window that is scheduled at a specific time for a fixed duration.
- **Recurring**: A maintenance window that is scheduled at a specific time and repeats at a regular interval. Optionally, you can specify an end date for the maintenance window.

#### One-time Maintenance Window

<Figure
  src="/img/docs/product-features/alerts/one-time.webp"
  alt="one-time maintenance window"
  caption="One-time maintenance window"
/>

Create a one-time maintenance window by clicking on the **`+ New downtime`** button at the top right corner. Since this is a one-time maintenance window, leave the *Repeats every* field with default value `Does not repeat`.

The following fields are required to create a one-time maintenance window:

- **Name**: A descriptive name for the maintenance window.
- **Start Time**: The start time of the maintenance window in the selected timezone.
- **End Time**: The end time of the maintenance window in the selected timezone.
- **Timezone**: The timezone of the maintenance window. This is the timezone in which the maintenance window is scheduled.

Example:

```
Start time: 2024-08-01 22:00:00
End time: 2024-08-01 23:00:00
Timezone: America/New_York
```

This means that the maintenance window is scheduled for 22:00:00 to 23:00:00 in the America/New_York timezone.

<Admonition type="info">
The **Timezone** field belongs to the maintenance window only. It is independent of the [display timezone](https://signoz.io/docs/manage/timezone/) that the rest of the console uses.
</Admonition>

The following fields are optional:

- **Silence Alerts**: The alerts that are silenced during the maintenance window. If nothing is selected, all alerts are silenced.
- **Scope**: A label expression that further filters which alert instances are suppressed. See [Scoping with Label Expressions](#scoping-with-label-expressions).

#### Recurring Maintenance Window

<Figure
  src="/img/docs/product-features/alerts/recurring-daily.webp"
  alt="recurring maintenance window"
  caption="Recurring maintenance window"
/>

Create a recurring maintenance window by clicking on the **`+ New downtime`** button at the top right corner. Since this is a recurring maintenance window, select the *Repeats every* field with the desired repetition type.

There are three types of repetition types available:

- **Daily**: The maintenance window repeats every day.
- **Weekly**: The maintenance window repeats every week on a specific day(s) of the week. The weekly repetition type allows you to select the days of the week on which the maintenance window repeats.
- **Monthly**: The maintenance window repeats every month on a specific day of the month.

The following fields are required to create a recurring maintenance window:

- **Name**: A descriptive name for the maintenance window.
- **Start Time**: The start time of the maintenance window.
- **Duration**: The duration of the maintenance window.
- **Timezone**: The timezone of the maintenance window.
- **Repeats every**: The type of repetition.

The following fields are optional:

- **Ends**: The end date of the maintenance window.
- **Silence Alerts**: The alerts that are silenced during the maintenance window. If nothing is selected, all alerts are silenced.
- **Scope**: A label expression that further filters which alert instances are suppressed. See [Scoping with Label Expressions](#scoping-with-label-expressions).

Examples:

1. Daily maintenance window that repeats every day for 1 hour starting from 22:00:00 in the America/New_York timezone.

```
Start time: 2024-08-01 22:00:00
Repeats every: Daily
Duration: 1 hour
Timezone: America/New_York
```

2. Weekly maintenance window that repeats every week on Monday for 1 hour starting from 22:00:00 in the America/New_York timezone.

```
Start time: 2024-08-01 22:00:00
Repeats every: Weekly
Weekly Occurence: [Monday]
Duration: 1 hour
Timezone: America/New_York
```

3. Monthly maintenance window that repeats every month on the 12th day of the month for 1 hour starting from 22:00:00 in the America/New_York timezone.

```
Start time: 2024-08-12 22:00:00
Repeats every: Monthly
Duration: 1 hour
Timezone: America/New_York
```

## Manage maintenance windows

The main **Planned Downtime** page lists all maintenance windows in a full-width, sortable table:

- **Downtime** (name), **Status**, **Schedule**, **Repeats**, and **Alerts Silenced** columns are shown by default.
- A count pill in the page header shows the total number of downtimes.
- Sort any column by clicking its header.
- Pagination controls at the bottom let you set the page size and show the total count.

Use the search field (**Search by name**) to filter downtimes. Search is case-insensitive.

### Column details

- **Status** shows a color-coded badge: **Active**, **Upcoming**, or **Expired**.
- **Schedule** shows the start and end time with the timezone embedded in the cell, for example `2024-01-01 10:00 ↱ 11:00 (Asia/Kolkata)`.
- **Repeats** shows the recurrence and per-occurrence duration together, for example `Weekly on Mon · 2h`.

### Show or hide columns

Click the **column picker** button in the table header to show or hide any column. **Description**, **Timezone**, **Duration**, and the audit columns (**Created By**, **Created At**, **Updated By**, **Updated At**) are hidden by default.

### Row actions

- Click anywhere on a downtime's row to open the edit form directly.
- Click the ellipsis (**⋯**) button on a row to open a menu with **Edit** and **Delete** actions.

<Admonition type="info">
Users with the Viewer role see the **New downtime** button disabled with a tooltip, rather than the button being hidden.
</Admonition>

### Empty, no-results, and error states

- **Empty state**: when no downtimes exist, the page shows an icon, a short description, a **New downtime** button, and a link to this documentation instead of an empty table.
- **No-results state**: when a search matches nothing, a message with a **Clear Search** button is shown.
- **Error state**: when the data fails to load, a screen with a **Refresh** button is shown.

## Scoping with Label Expressions

By default, a maintenance window silences all firing instances of the selected alerts (or every alert, if none are selected). **Scope** lets you narrow this further so that only alert instances whose labels match the expression are suppressed.

### How it works

- **No Scope set**: every firing instance of the selected alerts is silenced during the window.
- **Scope set, no alerts selected**: every alert whose labels match the expression is silenced, regardless of which alert rule fired it.
- **Both Scope and alerts selected**: only instances that belong to one of the selected alerts *and* match the expression are silenced.

### Expression syntax

Scope expressions use the <a href="https://expr-lang.org/" target="_blank" rel="noopener noreferrer nofollow">expr-lang</a> expression language. The expression must evaluate to a boolean (`true` = suppress, `false` = pass through). Each alert label is available as a variable with the same name.

| Pattern | Example |
|---|---|
| Equality | `severity = "critical"` |
| Inequality | `http.route != "/health"` |
| Logical AND | `env = "production" AND service.name = "payments"` |
| Logical OR | `url.scheme = "https" OR host = "localhost"` |
| `in` list | `k8s.cluster.region in ["us-east-1", "eu-central-1"]` |

References to labels that are not present on an alert instance are treated as `undefined` and evaluate to `false`, so the instance is not suppressed.
