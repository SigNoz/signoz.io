SigNoz processes every incoming span and automatically generates RED (Request, Error, Duration) metrics. The tables below describe each metric, what it measures, and which dimensions are attached.

## Request and error metrics

| Metric | Description |
|---|---|
| `signoz_calls_total` | Count of all spans per unique dimension set, including errors. Used to compute request rate and error rate. |

**Example — successful calls:**
```
signoz_calls_total{http_status_code="200",operation="/Address",service_name="shippingservice",span_kind="SPAN_KIND_SERVER",status_code="STATUS_CODE_UNSET"} 142
```

**Error counts** are derived from `signoz_calls_total` where `status_code = "STATUS_CODE_ERROR"`:
```
signoz_calls_total{http_status_code="503",operation="/checkout",service_name="frontend",span_kind="SPAN_KIND_CLIENT",status_code="STATUS_CODE_ERROR"} 220
```

Multiple dimensions can be aggregated — for example, querying call counts grouped only by `service_name` and `operation`.

## Latency metrics

| Metric | Description |
|---|---|
| `signoz_latency_sum` | Total sum of all recorded span durations |
| `signoz_latency_count` | Number of spans measured. Divide `signoz_latency_sum` by this to get average latency. |
| `signoz_latency_bucket` | Histogram buckets tracking how many spans fall into each latency range |

**Default latency buckets:** 2ms, 4ms, 6ms, 8ms, 10ms, … 15s

**Example — most spans have ≤ 100ms latency:**
```
signoz_latency_bucket{...,le="10"}  1195
signoz_latency_bucket{...,le="100"} 10180
signoz_latency_bucket{...,le="250"} 10180
```

## Database call metrics

| Metric | Description |
|---|---|
| `signoz_db_latency_sum` | Total latency for all database operations |
| `signoz_db_latency_count` | Number of database operations measured. Divide into sum for average DB latency. |

## External call metrics

| Metric | Description |
|---|---|
| `signoz_external_call_latency_sum` | Total latency for all external (outbound) calls |
| `signoz_external_call_latency_count` | Number of external calls made. Divide into sum for average external call latency. |

## Dimensions

### Request and latency metrics

| Dimension | Description |
|---|---|
| `service_name` | The `service.name` resource attribute of the instrumented service |
| `operation` | The span name (typically the HTTP route or RPC method) |
| `span_kind` | `SPAN_KIND_SERVER`, `SPAN_KIND_CLIENT`, etc. |
| `status_code` | `STATUS_CODE_OK`, `STATUS_CODE_ERROR`, or `STATUS_CODE_UNSET` |
| `http_status_code` | HTTP response status code (e.g., `200`, `503`) |

### Database call metrics

| Dimension | Description |
|---|---|
| `service_name` | Service generating the database call |
| `operation` | Database operation or query name |
| `span_kind` | Span kind |
| `status_code` | Span status |
| `database_system` | Database technology (e.g., `mysql`, `postgresql`) |
| `database_name` | Name of the specific database |

### External call metrics

| Dimension | Description |
|---|---|
| `service_name` | Service making the external call |
| `operation` | External call name |
| `span_kind` | Span kind |
| `status_code` | Span status |
| `external_http_url` | Hostname of the external service |
| `http_status_code` | HTTP response status code |
