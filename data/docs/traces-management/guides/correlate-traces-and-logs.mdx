## Overview

When you click **"Go to related logs"** from a trace and see "No logs found for this trace," it means your logs and traces are not yet correlated. This guide shows you how to link them by injecting `trace_id` and `span_id` into your log records.

:::info Prerequisites
- Your application is instrumented and sending traces to SigNoz
- Your application is emitting logs that are collected by SigNoz
:::

## Steps

### Step 1: Choose your correlation method

| Method | When to use |
|---|---|
| **Automatic (OpenTelemetry SDK)** | Your application already uses an OTel SDK for tracing — this is the recommended path |
| **Manual (Log Pipelines)** | Your logs come from files, Kubernetes log agents (FluentBit, FluentD), or log to a format that does not include OTel trace context automatically |

---

### Step 2A: Automatic correlation with the OpenTelemetry SDK

**Action:** Enable logging instrumentation in your OTel SDK setup.

OpenTelemetry SDKs automatically inject `trace_id` and `span_id` into log records when logging instrumentation is enabled. Supported languages: **Java, .NET, Python, Go, Node.js, PHP**.

Refer to the [instrumentation documentation](/docs/instrumentation/) for your language to enable the logging bridge or log appender.

Once enabled, every log emitted within a traced request will automatically include the active trace context — no further configuration needed.

---

### Step 2B: Manual correlation for file-based and Kubernetes logs

**Action:** Use SigNoz Log Pipelines to extract `trace_id` and `span_id` from your log records.

This path applies when:
- Your application logs to files read by a log collector
- You use Kubernetes and logs are collected by agents like FluentBit or FluentD
- Your logs contain trace IDs and span IDs in the message body or in custom fields

Follow the detailed guide: **[Parse Trace Information from Logs](https://signoz.io/docs/logs-pipelines/guides/trace/)**

That guide covers:
1. Creating a log pipeline in SigNoz
2. Using the Trace Parser processor to extract `trace_id` and `span_id`
3. Configuring regex or JSON parsers if the fields are embedded in the log message
4. Testing and deploying the pipeline

---

## Verify

**Action:** Generate traffic in your application, then check correlation end-to-end.

1. Go to **Traces** in SigNoz.
2. Click any trace to open Trace Details.
3. Click **"Go to related logs"**.
4. In the Logs Explorer, confirm that `trace_id` and `span_id` fields are present and populated.

:::tip Best practices
- Use OpenTelemetry SDKs when possible — automatic correlation requires no pipeline configuration.
- Use structured logging (JSON) for easier parsing in log pipelines.
- Include relevant context like user IDs and request IDs in your logs for richer correlation.
- Ensure consistent trace context propagation across all services so every log entry in a request chain shares the same `trace_id`.
:::
