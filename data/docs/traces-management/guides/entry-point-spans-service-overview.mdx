The **Key Operations** table in the service detail view surfaces the most important spans for a service, displaying P50, P95, and P99 latencies, call count, and error rate so you can compare performance at a glance.

## What are Entry Point Spans?

An **entry-point span** is the first span created when a request enters a service from any upstream service — the point where the `serviceName` changes in the trace hierarchy. It represents the service's view of an inbound operation, independent of any internal or downstream work the service subsequently performs.

## Key Operations table

| Column | Description |
|---|---|
| Operation | Span name (typically an HTTP route or RPC method) |
| P50 | Median latency for this operation |
| P95 | 95th-percentile latency |
| P99 | 99th-percentile latency |
| Rate | Calls per second |
| Error Rate | Percentage of calls with `STATUS_CODE_ERROR` |

## Entry Point Spans toggle

| Toggle state | What the table shows |
|---|---|
| **Off** (default) | All spans for the service, including internal and downstream spans |
| **On** | Only entry-point spans — the first span when a request enters this service from an upstream |

Enabling the toggle hides internal and downstream child spans, giving a concise, high-level view of how external traffic is behaving. This is useful for identifying latency outliers or error hotspots caused by inbound calls, without noise from internal processing.
