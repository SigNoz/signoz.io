## Overview

Traces can include sensitive information — IP addresses, email addresses, auth tokens — in span attributes. Storing this data may violate regulations like GDPR and CCPA. This guide shows how to use the OpenTelemetry Collector's transform processor to scrub PII before trace data reaches SigNoz.

:::info Prerequisites
- A [SigNoz Cloud](https://signoz.io/teams/) account
- An OpenTelemetry Collector receiving traces from your application. See the [OTel Collector setup guide](https://signoz.io/docs/collection-agents/get-started/) if you haven't set this up yet.
:::

## Steps

### Step 1: Instrument your application and point it at the Collector

**Action:** Make sure your application sends traces to the OTel Collector, not directly to SigNoz.

If you are currently sending traces directly to SigNoz, update your exporter endpoint to point to the Collector instead. The Collector will then forward scrubbed data to SigNoz.

---

### Step 2: Identify the PII attribute to scrub

**Action:** Find the span attribute that contains sensitive data.

For example, consider a span with this attribute:

```json
{
  "Key": "client.address",
  "Value": {
    "Type": "STRING",
    "Value": "127.0.0.1"
  }
}
```

In this case, `client.address` holds an IP address that should be redacted.

---

### Step 3: Write the transform processor config

**Action:** Add a `transform` processor to your `otel-collector-config.yaml` that uses [`replace_pattern`](https://github.com/open-telemetry/opentelemetry-collector-contrib/tree/main/pkg/ottl/ottlfuncs#replace_pattern) to replace the sensitive value with a placeholder.

```yaml
processors:
  transform:
    error_mode: ignore
    trace_statements:
      - replace_pattern(
          span.attributes["client.address"],
          "((25[0-5]|2[0-4][0-9]|[01]?[0-9][0-9]?)(\\.|$)){4}",
          "*.*.*.*"
        )
```

This uses a regex to match any IPv4 address in `client.address` and replaces it with `*.*.*.*`. Learn more about regex syntax at [MDN Regular Expressions](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Guide/Regular_expressions).

---

### Step 4: Apply the processor to the traces pipeline

**Action:** Add `transform` to the `processors` list in your traces pipeline configuration:

```yaml
service:
  pipelines:
    traces:
      receivers: [otlp]
      processors: [batch, transform]
      exporters: [otlp]
```

## Verify

**Action:** Restart the OpenTelemetry Collector and generate traffic from your application.

Go to **Traces** in SigNoz, open a trace, and inspect a span that previously contained the PII attribute. The value should now be replaced with the placeholder.

<figure data-zoomable align='center'>
    <img src="/img/docs/traces-management/sample-scrubbed-trace-output.webp" alt="Sample trace output with PII data scrubbed out"/>
    <figcaption><i>The client IP address is now masked — the raw value never reached SigNoz</i></figcaption>
</figure>

:::tip
To scrub multiple attributes, add additional `replace_pattern` statements inside the same `trace_statements` list.
:::
