This guide explains how to configure Kubernetes metrics collection in the k8s-infra OpenTelemetry collection agent, specifically for IPv6, dual-stack, or other non-standard Kubernetes environments.

The `k8s-infra` collection agent provides the `kubeletMetrics` preset, which is built on the OpenTelemetry Collector’s **`kubeletstats` receiver** for gathering Kubernetes metrics.

<Admonition type="info">

By default, `kubeletMetrics` sets the endpoint to `${env:K8S_HOST_IP}:10250`. If the `endpoint` field is missing or empty in your configuration, the `kubeletstats` receiver will attempt to use the **hostname** of the pod running the collector as the kubelet API endpoint.

If `hostNetwork: true` is set on the collector pod (which is common), this hostname resolves in the node's network namespace.

However, DNS resolution of node hostnames can fail or be unreliable, particularly with certain cloud providers, resulting in failed metric scrapes.

</Admonition>

## Configure kubeletMetrics Endpoint for IPv6 or Custom Networking

The `kubeletstats` receiver connects to the Kubelet API on each node to collect essential metrics. Using the node IP works well for most standard clusters. However, in **IPv6-only**, **dual-stack**, or some cloud/provider environments (like EKS/IPv6), you may need to configure the endpoint to use the node name for reliable connectivity.

### Step 1: Update kubeletMetrics Endpoint

Update your `values.yaml` for [presets.kubeletMetrics](https://github.com/SigNoz/charts/blob/9ee23874aa122317fdcbd99d712a63b0ab07248d/charts/k8s-infra/values.yaml#L354):

```yaml
presets:
  kubeletMetrics:
    endpoint: '${env:K8S_NODE_NAME}:10250'
```

This allows the receiver to reach the kubelet using node name addressing, which works in:

- IPv6-only clusters
- Dual-stack clusters
- Environments where metrics scraping fails using the default (host IP)

Other kubeletMetrics settings (authType, collectionInterval, etc.) can remain at defaults unless you have specific requirements.
