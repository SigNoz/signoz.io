This guide explains how to configure Kubernetes metrics collection in the k8s-infra OpenTelemetry collection agent for IPv6, dual-stack, or other non-standard Kubernetes environments.

The `k8s-infra` collection agent includes a `kubeletMetrics` preset, based on the OpenTelemetry Collector’s **`kubeletstats` receiver**, which gathers essential Kubernetes metrics.

## Prerequisites

Before setting up OpenTelemetry monitoring for your Kubernetes cluster, ensure you have:

- A SigNoz backend (SigNoz Cloud or self-hosted) to receive OpenTelemetry data
- kubectl access to your Kubernetes cluster
- Helm v3 installed for deploying the OpenTelemetry collector
- Basic understanding of Kubernetes concepts (pods, nodes, namespaces)

<Admonition type="info">

By default, `kubeletMetrics` sets the endpoint to `${env:K8S_HOST_IP}:10250`. If the `endpoint` field is missing or empty in your configuration, the `kubeletstats` receiver will attempt to use the **hostname** of the pod running the collector as the kubelet API endpoint.

If `hostNetwork: true` is set on the collector pod (which is common), this hostname resolves in the node's network namespace.

However, DNS resolution of node hostnames can fail or be unreliable, particularly with certain cloud providers, resulting in failed metric scrapes.

</Admonition>

## Configure kubeletMetrics Endpoint for IPv6 or Custom Networking

The `kubeletstats` receiver connects to the Kubelet API on each node. Using the node IP is sufficient for most clusters, but some environments may need to use the node name instead for metrics collection.

### Step 1: Set the Endpoint

To override the default and use the node name, update your `values.yaml` for [presets.kubeletMetrics](https://github.com/SigNoz/charts/blob/main/charts/k8s-infra/values.yaml#L354):

```yaml
presets:
  kubeletMetrics:
    endpoint: '${env:K8S_NODE_NAME}:10250'
```

Other kubeletMetrics settings (authType, collectionInterval, etc.) can remain at defaults unless you have specific requirements.

### Step 2: Apply and Validate

1. Apply your configuration changes using Helm upgrade or your preferred deployment method.
2. Confirm that node and pod metrics appear in the SigNoz dashboard.
3. To revert to the default behavior (typically suitable for standard clusters), set:

```yaml
presets:
  kubeletMetrics:
    endpoint: '${env:K8S_HOST_IP}:10250'
```
