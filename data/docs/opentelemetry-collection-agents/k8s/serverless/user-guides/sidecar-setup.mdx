This page covers the sidecar setup that earlier versions of the install guide used: the `k8s-infra` chart without its agent, plus a collector sidecar in each application Pod. New setups use the [install guide](https://signoz.io/docs/opentelemetry-collection-agents/k8s/serverless/install/).

## Prerequisites

- An EKS cluster with a <a href="https://docs.aws.amazon.com/eks/latest/userguide/fargate-profile.html" target="_blank" rel="noopener noreferrer nofollow">Fargate profile</a> that selects the `k8s-infra` release's namespace and your applications' namespaces.
- `kubectl` configured to reach the cluster, and Helm 3 installed on the same machine.
- A SigNoz Instance to send data to: [SigNoz Cloud](https://signoz.io/teams/) or a [self-hosted SigNoz](https://signoz.io/docs/install/self-host/).

## Install k8s-infra and the Sidecar

<Admonition type="info" title="Using Self-Hosted SigNoz?" defaultCollapsed="true">
Most steps are identical. To adapt this guide, update the endpoint and remove the ingestion key in `override-values.yaml`, as shown in [Cloud → Self-Hosted for the k8s-infra chart](https://signoz.io/docs/ingestion/cloud-vs-self-hosted/?ingestion-client=collection-agent&collection-agent=k8s-infra#cloud-to-self-hosted), and in the sidecar's `otlphttp` exporter, as shown in [Cloud → Self-Hosted for the OpenTelemetry Collector](https://signoz.io/docs/ingestion/cloud-vs-self-hosted/?ingestion-client=collector#cloud-to-self-hosted).
</Admonition>

### Step 1: Install k8s-infra without the agent

Run this on the machine where you use `kubectl` to add the Helm repository:

```bash
helm repo add signoz https://charts.signoz.io
helm repo update
```

Create a file named `override-values.yaml`. `otelAgent.enabled: false` turns off the agent DaemonSet and keeps the cluster collector:

```yaml:override-values.yaml
global:
  clusterName: <CLUSTER_NAME>
  deploymentEnvironment: <DEPLOYMENT_ENVIRONMENT>
otelCollectorEndpoint: https://ingest.<region>.signoz.cloud:443
otelInsecure: false
signozApiKey: <your-ingestion-key>
otelAgent:
  enabled: false
```

**Verify these values:**

- `<region>`: Your SigNoz Cloud [region](https://signoz.io/docs/ingestion/signoz-cloud/overview/#endpoint).
- `<your-ingestion-key>`: Your SigNoz Cloud [ingestion key](https://signoz.io/docs/ingestion/signoz-cloud/keys/).
- `<CLUSTER_NAME>`: A name for this cluster, unique across the clusters that send to the same SigNoz. It becomes `k8s.cluster.name` on every signal and names the cluster in the SigNoz Kubernetes views.
- `<DEPLOYMENT_ENVIRONMENT>`: Your deployment environment, for example `staging` or `production`. It becomes `deployment.environment` on the collected telemetry.

Run this from the directory that contains `override-values.yaml`:

```bash
helm install my-release signoz/k8s-infra -f override-values.yaml
```

Helm installs the release `my-release` into the namespace of your current `kubectl` context, `default` unless you set another. A Fargate profile must select that namespace.

### Step 2: Create the sidecar ConfigMap

Create a file named `otel-agent-sidecar-config.yaml`. It holds the sidecar collector's config and the in-cluster kubeconfig the `kubeletstats` receiver uses to reach the kubelet through the Kubernetes API server:

```yaml:otel-agent-sidecar-config.yaml minimap defaultCollapsed
apiVersion: v1
kind: ConfigMap
metadata:
  name: otel-agent-sidecar-config
  namespace: <YOUR_NAMESPACE>
data:
  kubeconfig: |
    apiVersion: v1
    kind: Config
    clusters:
    - name: in-cluster
      cluster:
        server: https://kubernetes.default.svc:443
        certificate-authority: /var/run/secrets/kubernetes.io/serviceaccount/ca.crt
    contexts:
    - name: in-cluster
      context: { cluster: in-cluster, user: in-cluster }
    current-context: in-cluster
    users:
    - name: in-cluster
      user:
        tokenFile: /var/run/secrets/kubernetes.io/serviceaccount/token
  otel-agent-config.yaml: |
    exporters:
      debug:
        sampling_initial: 2
        sampling_thereafter: 500
        verbosity: basic
      otlphttp:
        endpoint: ${env:OTEL_EXPORTER_OTLP_ENDPOINT}
        headers:
          signoz-ingestion-key: ${env:SIGNOZ_API_KEY}

    extensions:
      health_check:
        endpoint: 0.0.0.0:13133
      pprof:
        endpoint: localhost:1777
      zpages:
        endpoint: localhost:55679
    processors:
      batch:
        send_batch_size: 10000
        timeout: 200ms
      k8sattributes:
        extract:
          annotations: []
          labels: []
          metadata:
            - k8s.namespace.name
            - k8s.deployment.name
            - k8s.statefulset.name
            - k8s.daemonset.name
            - k8s.cronjob.name
            - k8s.job.name
            - k8s.node.name
            - k8s.node.uid
            - k8s.pod.name
            - k8s.pod.uid
            - k8s.pod.start_time
        filter:
          node_from_env_var: K8S_NODE_NAME
        passthrough: false
        pod_association:
        - sources:
          - from: resource_attribute
            name: k8s.pod.ip
        - sources:
          - from: resource_attribute
            name: k8s.pod.uid
        - sources:
          - from: connection
      resourcedetection:
        detectors:
        - eks
        - env
        - system
        override: false
        system:
          resource_attributes:
            host.id:
              enabled: false
            host.name:
              enabled: false
            os.type:
              enabled: true
        timeout: 2s

    receivers:
      kubeletstats:
        auth_type: kubeConfig
        collection_interval: 30s
        endpoint: ${env:K8S_NODE_NAME}
        insecure_skip_verify: true
        metric_groups:
        - container
        - pod
        - node
        - volume
        metrics:
          container.cpu.usage:
            enabled: true
          container.uptime:
            enabled: true
          k8s.container.cpu_limit_utilization:
            enabled: true
          k8s.container.cpu_request_utilization:
            enabled: true
          k8s.container.memory_limit_utilization:
            enabled: true
          k8s.container.memory_request_utilization:
            enabled: true
          k8s.node.cpu.usage:
            enabled: true
          k8s.node.uptime:
            enabled: true
          k8s.pod.cpu.usage:
            enabled: true
          k8s.pod.cpu_limit_utilization:
            enabled: true
          k8s.pod.cpu_request_utilization:
            enabled: true
          k8s.pod.memory_limit_utilization:
            enabled: true
          k8s.pod.memory_request_utilization:
            enabled: true
          k8s.pod.uptime:
            enabled: true
      otlp:
        protocols:
          grpc: { endpoint: 0.0.0.0:4317, max_recv_msg_size_mib: 4 }
          http: { endpoint: 0.0.0.0:4318 }

    service:
      extensions: [health_check, zpages, pprof]
      pipelines:
        logs:
          receivers:  [otlp]
          processors: [resourcedetection, k8sattributes, batch]
          exporters:  [debug, otlphttp]
        metrics:
          receivers:  [otlp, kubeletstats]
          processors: [resourcedetection, k8sattributes, batch]
          exporters:  [otlphttp, debug]
        traces:
          receivers:  [otlp]
          processors: [resourcedetection, k8sattributes, batch]
          exporters:  [otlphttp, debug]

      telemetry:
        logs:    { encoding: json }
```

**Verify these values:**

- `<YOUR_NAMESPACE>`: The namespace of the application Pods that run the sidecar.

The collector reads its endpoint and ingestion key from the sidecar's environment, which Step 4 sets.

### Step 3: Create the service account and RBAC

Create a file named `rbac.yaml` with a service account and the RBAC the sidecar needs to call the API server's node proxy:

```yaml:rbac.yaml minimap defaultCollapsed
apiVersion: v1
kind: ServiceAccount
metadata:
  name: otel-agent-sidecar
  namespace: <YOUR_NAMESPACE>
---
apiVersion: rbac.authorization.k8s.io/v1
kind: ClusterRole
metadata:
  name: otel-kubeletstats-proxy
rules:
  # Needed for: GET /api/v1/nodes/<node>/proxy/stats/summary
  - apiGroups: ['']
    resources: ['nodes/stats', 'nodes/proxy']
    verbs: ['get']
  # Informers for enrichment (k8sattributes/resourcedetection)
  - apiGroups: ['']
    resources: ['pods', 'namespaces', 'nodes']
    verbs: ['get', 'list', 'watch']
  # Optional: owner lookups (ReplicaSets)
  - apiGroups: ['apps']
    resources: ['replicasets']
    verbs: ['get', 'list', 'watch']
---
apiVersion: rbac.authorization.k8s.io/v1
kind: ClusterRoleBinding
metadata:
  name: otel-kubeletstats-proxy
roleRef:
  apiGroup: rbac.authorization.k8s.io
  kind: ClusterRole
  name: otel-kubeletstats-proxy
subjects:
  - kind: ServiceAccount
    name: otel-agent-sidecar
    namespace: <YOUR_NAMESPACE>
```

**Verify these values:**

- `<YOUR_NAMESPACE>`: The same namespace as in Step 2.

### Step 4: Add the sidecar to your application

In your application's Deployment manifest, add the service account, the ConfigMap volume, and the sidecar container:

```yaml minimap defaultCollapsed
# Example Deployment fragment
spec:
  template:
    spec:
      ## Service Account for otel-agent-sidecar container ##
      serviceAccountName: otel-agent-sidecar

      ## Mount the otel-agent config configMap
      volumes:
        - name: otel-agent-config-vol
          configMap:
            name: otel-agent-sidecar-config

      containers:
        - name: your-app
          image: <YOUR_IMAGE>
          env:
            - name: OTEL_EXPORTER_OTLP_ENDPOINT
              value: http://localhost:4318

        ###### Otel Agent Sidecar container ####
        - name: opentelemetry-collector-contrib
          image: otel/opentelemetry-collector-contrib:0.139.0
          command:
            - /otelcol-contrib
            - --config=/conf/otel-agent-config.yaml
          env:
            # This endpoint should be reachable from your pod
            - name: OTEL_EXPORTER_OTLP_ENDPOINT
              value: https://ingest.<region>.signoz.cloud:443
            - name: SIGNOZ_API_KEY
              value: <your-ingestion-key>
            - name: KUBECONFIG
              value: /conf/kubeconfig
            - name: OTEL_EXPORTER_OTLP_INSECURE
              value: 'true'
            - name: OTEL_SECRETS_PATH
              value: /secrets
            - name: K8S_CLUSTER_NAME
              value: <CLUSTER_NAME>
            - name: K8S_NODE_NAME
              valueFrom:
                fieldRef:
                  apiVersion: v1
                  fieldPath: spec.nodeName
            - name: K8S_POD_IP
              valueFrom:
                fieldRef:
                  apiVersion: v1
                  fieldPath: status.podIP
            - name: K8S_HOST_IP
              valueFrom:
                fieldRef:
                  apiVersion: v1
                  fieldPath: status.hostIP
            - name: K8S_POD_NAME
              valueFrom:
                fieldRef:
                  apiVersion: v1
                  fieldPath: metadata.name
            - name: K8S_POD_UID
              valueFrom:
                fieldRef:
                  apiVersion: v1
                  fieldPath: metadata.uid
            - name: K8S_NAMESPACE
              valueFrom:
                fieldRef:
                  apiVersion: v1
                  fieldPath: metadata.namespace
            - name: SIGNOZ_COMPONENT
              value: otel-agent
            - name: OTEL_RESOURCE_ATTRIBUTES
              value: signoz.component=$(SIGNOZ_COMPONENT),k8s.cluster.name=$(K8S_CLUSTER_NAME),k8s.node.name=$(K8S_NODE_NAME),host.name=$(K8S_NODE_NAME),k8s.pod.ip=$(K8S_POD_IP),k8s.pod.uid=$(K8S_POD_UID)
          livenessProbe:
            failureThreshold: 6
            httpGet:
              path: /
              port: 13133
              scheme: HTTP
            initialDelaySeconds: 10
            periodSeconds: 10
            successThreshold: 1
            timeoutSeconds: 5
          ports:
            - containerPort: 13133
              name: health-check
              protocol: TCP
            - containerPort: 8888
              name: metrics
              protocol: TCP
            - containerPort: 4317
              name: otlp
              protocol: TCP
            - containerPort: 4318
              name: otlp-http
              protocol: TCP
          readinessProbe:
            failureThreshold: 6
            httpGet:
              path: /
              port: 13133
              scheme: HTTP
            initialDelaySeconds: 10
            periodSeconds: 10
            successThreshold: 1
            timeoutSeconds: 5
          resources:
            requests:
              cpu: 100m
              memory: 100Mi
          volumeMounts:
            - mountPath: /conf
              name: otel-agent-config-vol
```

**Verify these values:**

- `<YOUR_IMAGE>`: Your application's image. Keep your application's container as it is, and add its `OTEL_EXPORTER_OTLP_ENDPOINT`, which points at the sidecar in the same Pod.
- `<region>`: Your SigNoz Cloud [region](https://signoz.io/docs/ingestion/signoz-cloud/overview/#endpoint).
- `<your-ingestion-key>`: Your SigNoz Cloud [ingestion key](https://signoz.io/docs/ingestion/signoz-cloud/keys/). It is set as a plain environment variable on the sidecar.
- `<CLUSTER_NAME>`: The same value as `global.clusterName` in Step 1.

### Step 5: Apply the manifests

Run this from the directory that contains the files from Steps 2 to 4:

```bash
kubectl apply -f otel-agent-sidecar-config.yaml
kubectl apply -f rbac.yaml
kubectl apply -f <app-manifest>.yaml
```

**Verify these values:**

- `<app-manifest>.yaml`: Your application's Deployment manifest from Step 4.

### Step 6: Verify the Collection Agent

Run this on the machine where you use `kubectl` to check that your application pods run with the sidecar:

```bash
kubectl get pods -n <YOUR_NAMESPACE>
```

The output should look similar to the following, with `2/2` under `READY` for each application pod: your application's container and the sidecar. Pod names and suffixes vary:

```output
NAME                        READY   STATUS    RESTARTS   AGE
your-app-6b8f9c7d5d-4kq2m   2/2     Running   0          2m
```

Then check the cluster collector in the `k8s-infra` release's namespace:

```bash
kubectl get pods
```

The output lists one `my-release-k8s-infra-otel-deployment` pod as `Running`.

In SigNoz, open the [Kubernetes Monitoring](https://signoz.io/docs/infrastructure-monitoring/kubernetes-monitoring/) views under **Infrastructure Monitoring**. The **Clusters** view lists your cluster under the name you set as `<CLUSTER_NAME>`, and the **Pods** view lists the pods that run the sidecar. Check **Logs Explorer** to confirm Kubernetes events are flowing.

## Customize the Collection Agent

The sidecars read their config when their Pod starts. Every change to it follows the same loop: edit `otel-agent-config.yaml` in `otel-agent-sidecar-config.yaml`, then run this from the directory that contains the file:

```bash
kubectl apply -f otel-agent-sidecar-config.yaml
kubectl rollout restart -n <YOUR_NAMESPACE> deployment/<app-name>
```

**Verify these values:**

- `<app-name>`: The name of your application's Deployment.

What to change, and where:

- **Sidecar collector config** (receivers, processors, pipelines): see [OpenTelemetry Collector configuration](https://signoz.io/docs/opentelemetry-collection-agents/opentelemetry-collector/configuration/).
- **Cluster collector** (cluster metrics, Kubernetes events): edit `override-values.yaml`, then run `helm upgrade my-release signoz/k8s-infra -f override-values.yaml` from the directory that contains it. See [Configure K8s Infra](https://signoz.io/docs/opentelemetry-collection-agents/k8s/k8s-infra/configure-k8s-infra/).

## Collect Container Logs

Application logs reach the collector over OTLP from the application, or through CloudWatch Logs from Fargate's log router. For both routes and the CloudWatch setup, see [Collect EKS Fargate Logs with OpenTelemetry and CloudWatch](https://signoz.io/docs/opentelemetry-collection-agents/k8s/serverless/user-guides/eks-fargate-logs/?fargate-setup=sidecar).

## Troubleshooting
</ToggleHeading>

### Application pod stays Pending

Run this on the machine where you use `kubectl` to see why the pod is unscheduled:

```bash
kubectl describe pod -n <YOUR_NAMESPACE> <pod-name>
```

Replace `<pod-name>` with the pod's name from `kubectl get pods -n <YOUR_NAMESPACE>`. The events show `FailedScheduling`.

**Cause:** no Fargate profile selects the namespace, so no Fargate node is started for the pod.

**Fix:** add a <a href="https://docs.aws.amazon.com/eks/latest/userguide/fargate-profile.html" target="_blank" rel="noopener noreferrer nofollow">Fargate profile</a> that selects the namespace, then run this on the machine where you use `kubectl` to recreate the pods:

```bash
kubectl rollout restart -n <YOUR_NAMESPACE> deployment/<app-name>
```

After the fix, `kubectl get pods -n <YOUR_NAMESPACE>` shows the pods as `Running` with `2/2` under `READY`.

### Sidecar logs a 404 for the kubelet stats

Run this on the machine where you use `kubectl` to read the sidecar's logs:

```bash
kubectl logs -n <YOUR_NAMESPACE> deployment/<app-name> -c opentelemetry-collector-contrib --since=10m
```

The logs show `404 Not Found` for `/api/v1/nodes/<node-name>/proxy/stats/summary`.

**Cause:** the `kubeletstats` receiver does not reach the kubelet of the Pod's node through the Kubernetes API server.

**Fix:** check that:

- the receiver's `endpoint` is `${env:K8S_NODE_NAME}`, not empty and not a `host:port`;
- the sidecar sets `K8S_NODE_NAME` from `spec.nodeName` and `KUBECONFIG=/conf/kubeconfig`;
- the ClusterRole in `rbac.yaml` allows `get` on `nodes/stats` and `nodes/proxy`.

Some EKS Fargate environments do not serve `/stats/summary` through the proxy. In that case, scrape cAdvisor through the proxy instead (`/api/v1/nodes/<node-name>/proxy/metrics/cadvisor`) with a Prometheus receiver.

After the fix, the sidecar's logs show no `kubeletstats` errors and the **Pods** view in SigNoz lists the pod.

### helm install fails with `cannot re-use a name that is still in use`

Run this on the machine where you use `kubectl` to list the releases in the current namespace:

```bash
helm list
```

**Cause:** the release `my-release` already exists.

**Fix:** apply your changes with `helm upgrade my-release signoz/k8s-infra -f override-values.yaml` from the directory that contains `override-values.yaml`.

After the fix, `kubectl get pods` shows the `my-release-k8s-infra-otel-deployment` pod as `Running`.
