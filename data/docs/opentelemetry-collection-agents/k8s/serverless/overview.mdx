EKS Fargate runs each Pod on a Fargate node of its own, with no DaemonSets, host paths, or host ports. The EKS Fargate Collection Agent collects kubelet metrics, cluster metrics, Kubernetes events, and telemetry from your applications with one OpenTelemetry Collector that runs as an ordinary Deployment.

[Install it](https://signoz.io/docs/opentelemetry-collection-agents/k8s/serverless/install/) with Foundry through Kustomize.

The EKS Fargate Collection Agent primarily performs the following:

- Collects kubelet metrics from every Fargate node through the Kubernetes API server.
- Gathers cluster-level metrics and Kubernetes events from the Kubernetes API server.
- Receives OTLP traces, metrics, and logs from your applications and forwards them to SigNoz.

## How it works

### Cluster collector (Deployment)

The collector runs as one Deployment and reaches every Fargate node through the Kubernetes API server:

- **Kubelet metrics:** container, pod, node, and volume metrics from every Fargate node via `kubeletstats`. The `k8s_observer` extension discovers the nodes, and the `receiver_creator` receiver starts one `kubeletstats` receiver per node through the API server's node proxy.
- **Cluster metrics:** node and pod conditions, allocatable resources, and workload status via `k8s_cluster`.
- **Kubernetes events:** via `k8s_events`.
- **OTLP:** traces, metrics, and logs from your applications over OTLP/gRPC (4317) and OTLP/HTTP (4318), on the collector's Service.
- **Resource attributes:** Kubernetes resource attributes via the `k8sattributes` processor, and `cloud.provider`, `cloud.platform`, and `k8s.cluster.name` via the `resource/identity` processor.

The collector runs as one replica. A rollout stops the old pod before it starts the new one, so each node is scraped once.

## Known Limitations

- **Host metrics:** Fargate exposes no host to a Pod, so no `hostmetrics` receiver runs. Node CPU, memory, network, and filesystem metrics come from `kubeletstats` instead. The SigNoz **Hosts** view stays empty, and telemetry carries no `host.name`.
- **Container logs:** Fargate keeps stdout and stderr out of a Pod's reach, so no `filelog` receiver runs. Send application logs over OTLP, or route stdout and stderr through CloudWatch Logs, as [Collect EKS Fargate Logs](https://signoz.io/docs/opentelemetry-collection-agents/k8s/serverless/user-guides/eks-fargate-logs/?fargate-setup=deployment) shows. The collector adds no Kubernetes resource attributes to the CloudWatch logs; the pod's details stay inside each log record, from the Fluent Bit Kubernetes filter.
- **Fargate nodes only:** the collector scrapes the nodes labelled `eks.amazonaws.com/compute-type=fargate`. EC2 nodes in the same cluster show no pod or container metrics unless an agent such as [K8s Infra](https://signoz.io/docs/opentelemetry-collection-agents/k8s/k8s-infra/overview/) runs on them.
- **One replica:** during a rollout, kubelet scrapes and OTLP intake pause until the new pod is ready.
