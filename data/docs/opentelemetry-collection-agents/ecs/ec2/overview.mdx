The ECS EC2 Collection Agent runs one OpenTelemetry Collector task on every container instance of an Amazon ECS cluster, as an ECS daemon service. It collects host metrics, container metrics, container and host logs, and telemetry from your applications, on EC2 container instances and on external instances registered through ECS Anywhere.

[Install it](https://signoz.io/docs/opentelemetry-collection-agents/ecs/ec2/install/) with Foundry and Terraform.

## How it works

The collector task uses the `host` network mode, with the `EC2` launch type on EC2 container instances and the `EXTERNAL` launch type on external instances. It reads the instance through read-only mounts of the Docker socket, the Docker container log directory, and the instance's root filesystem at `/hostfs`, and it runs as root because Docker writes container log files that only root can read:

- **Host metrics:** CPU, memory, disk, filesystem, network, paging, load, and process metrics of the instance via `hostmetrics`.
- **Container metrics:** CPU, memory, network, and block I/O metrics of every container via `docker_stats`, from the Docker Engine API, with the resource attributes `aws.ecs.cluster.name`, `aws.ecs.task.arn`, `aws.ecs.task.family`, and `aws.ecs.task.revision` from each container's ECS labels.
- **Container logs:** stdout and stderr of every container that uses the `json-file` log driver via `filelog`. `service.name` is the container's task family, with `aws.ecs.container.name`, `aws.ecs.task.arn`, `aws.ecs.cluster.name`, and `container.id`. The collector drops the logs of its own task.
- **Host logs:** `/var/log/messages`, `/var/log/secure`, and the ECS agent logs under `/var/log/ecs/` via `filelog/host`, with `service.name: ecs-host`.
- **OTLP:** traces, metrics, and logs from your applications over OTLP/gRPC (4317) and OTLP/HTTP (4318), on the instance's ports.
- **Resource attributes:** `host.name`, `host.id`, and the instance's `cloud.*` attributes via the `resourcedetection` processor's `ec2` detector, plus the attributes in the collector's `OTEL_RESOURCE_ATTRIBUTES`. On external instances, the `system` detector sets `host.name` and `os.type` instead.

A second container in the task, the AWS AppConfig agent, fetches the collector config from AWS AppConfig and writes it to the task, and the collector starts once that container is healthy.

## Known Limitations

- **Logs of `awslogs` and `awsfirelens` containers:** these log drivers send stdout and stderr to CloudWatch Logs or to FireLens and write no `json-file` log on the instance, so `filelog` does not collect them. Send those logs to the collector over OTLP from the application, or switch the container to the `json-file` log driver. Until then, they are missing from SigNoz Logs.
- **Container logs without `service.name`:** a `json-file` log carries the container's task family, task ARN, cluster, and container name only when its task definition sets the log driver's `labels` option, as [Collect Container Logs](https://signoz.io/docs/opentelemetry-collection-agents/ecs/ec2/configure/#collect-container-logs) shows. Without it, the logs arrive with `container.id` and `log.file.path` only, and SigNoz cannot attribute them to a service.
- **OTLP data without ECS task attributes:** the collector runs in its own task, so it cannot tell which task sent traces, metrics, or logs over OTLP. They carry `aws.ecs.*` attributes only when the application's SDK runs the ECS resource detector, as [Add ECS task attributes](https://signoz.io/docs/opentelemetry-collection-agents/ecs/ec2/configure/#add-ecs-task-attributes) shows. Without it, you can filter them by host but not by task.
- **Host logs on Amazon Linux 2023:** Amazon Linux 2023 writes system logs to the systemd journal and installs no `rsyslog` by default, so `/var/log/messages` and `/var/log/secure` do not exist there, and `filelog/host` collects only the ECS agent logs. To write the system log files again, install `rsyslog` as <a href="https://docs.aws.amazon.com/linux/al2023/ug/journald.html" target="_blank" rel="noopener noreferrer nofollow">systemd journal replaces rsyslog</a> describes.
- **Fargate:** tasks on Fargate have no instance to run a daemon on. For Fargate, use the [ECS Serverless Collection Agent](https://signoz.io/docs/opentelemetry-collection-agents/ecs/sidecar/overview/).
