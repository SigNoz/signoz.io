This guide explains how to install the Docker Collection Agent on a Docker host with Foundry.

<Admonition type="info" title="Installed the agent from an earlier version of this guide?">
Move it to Foundry with [Move an Existing Setup to Foundry](https://signoz.io/docs/opentelemetry-collection-agents/docker/configure/#move-an-existing-setup-to-foundry).
</Admonition>

## Prerequisites

- A Linux host with <a href="https://docs.docker.com/engine/install/" target="_blank" rel="noopener noreferrer nofollow">Docker Engine</a> 25.0 or newer.
- The Docker Compose plugin (`docker compose`) on the same host.
- Ports `4317`, `4318`, `8888`, and `13133` free on the host. To run the agent on the host that runs self-hosted SigNoz, see [Run on the same host as self-hosted SigNoz](https://signoz.io/docs/opentelemetry-collection-agents/docker/configure/#run-on-the-same-host-as-self-hosted-signoz).
- A SigNoz to send data to: [SigNoz Cloud](https://signoz.io/teams/) or a [self-hosted SigNoz](https://signoz.io/docs/install/self-host/).

## Install the Collection Agent

<Admonition type="info" title="What is Foundry?" defaultCollapsed="true">
Foundry is an open-source CLI that runs your self-hosted observability stack as code. One declarative config provisions the infrastructure, installs the SigNoz backend, and sets up OpenTelemetry collection on bare metal, containers, or Kubernetes. Learn more about <a href="https://github.com/SigNoz/foundry" target="_blank" rel="noopener noreferrer nofollow">Foundry</a>.
</Admonition>

### Step 1: Install foundryctl

Run this on the Docker host:

```bash
curl -fsSL https://signoz.io/foundry.sh | bash
```

For manual install (Windows PowerShell, air-gapped, etc.) or PATH setup, see the <a href="https://github.com/SigNoz/foundry/blob/main/docs/getting-started.md" target="_blank" rel="noopener noreferrer nofollow">foundry getting-started guide</a>.

### Step 2: Create casting.yaml

Create a file named `casting.yaml` on the Docker host, with one document for the agent described in [How it works](https://signoz.io/docs/opentelemetry-collection-agents/docker/overview/#how-it-works-the-agent-container):

<Admonition type="info" title="Using Self-Hosted SigNoz?" defaultCollapsed="true">
Most steps are identical. To adapt this guide, update the endpoint and remove the ingestion key as shown in [Cloud → Self-Hosted](https://signoz.io/docs/ingestion/cloud-vs-self-hosted/?ingestion-client=collection-agent&collection-agent=foundry#cloud-to-self-hosted).
</Admonition>

```yaml:casting.yaml defaultCollapsed
apiVersion: v1alpha1
kind: CollectionAgent
metadata:
  name: signoz
spec:
  deployment:
    mode: docker
    flavor: compose
  collector:
    spec:
      env:
        SIGNOZ_INGESTION_ENDPOINT: https://ingest.<region>.signoz.cloud:443
        SIGNOZ_INGESTION_KEY: <your-ingestion-key>
        OTEL_RESOURCE_ATTRIBUTES: deployment.environment=<your-environment>
      config:
        data:
          collector/agent/agent.yaml: |
            exporters:
              otlphttp/signoz:
                headers:
                  signoz-ingestion-key: ${env:SIGNOZ_INGESTION_KEY}
```

**Verify these values:**

- `<region>`: Your SigNoz Cloud [region](https://signoz.io/docs/ingestion/signoz-cloud/overview/#endpoint).
- `<your-ingestion-key>`: Your SigNoz Cloud [ingestion key](https://signoz.io/docs/ingestion/signoz-cloud/keys/).
- `<your-environment>`: Your deployment environment, for example `staging` or `production`.

For every option of this casting, see the <a href="https://github.com/SigNoz/foundry/tree/main/docs/examples/collectionagent/docker/compose" target="_blank" rel="noopener noreferrer nofollow">Docker Compose example</a>.

### Step 3: Deploy

Run this from the directory that contains `casting.yaml`:

```bash
foundryctl cast -f casting.yaml
```

This command:

- writes the Compose file `compose.yaml` to `pours/collectionagent/` and the collector config `agent.yaml` to `pours/collectionagent/collector/agent/`;
- applies `compose.yaml` with `docker compose up -d`, as the Compose project `signoz`;
- runs the agent in the container `signoz-collector-agent-1`.

Run the same command again after editing `casting.yaml`, then run `docker restart signoz-collector-agent-1` so the agent reads the new config.

<Admonition type="tip" title="Run Docker Compose yourself" defaultCollapsed="true">
To run Docker Compose directly, generate the files and start them. Run this from the directory that contains `casting.yaml`:

```bash
foundryctl forge -f casting.yaml   # writes compose.yaml and agent.yaml under pours/collectionagent
docker compose -f pours/collectionagent/compose.yaml up -d
```
</Admonition>

### Step 4: Verify the Collection Agent

Run this on the Docker host to check that the agent started:

```bash
docker logs signoz-collector-agent-1
```

The logs should include a line similar to the following:

```output
... Everything is ready. Begin running and processing data.
```

In SigNoz, open **Infrastructure Monitoring** > **Hosts**: your host appears under its host name as data arrives. Check **Logs Explorer** to confirm container logs are flowing.

## Customize the Collection Agent

Every change follows the same loop: edit `casting.yaml`, run `foundryctl cast -f casting.yaml` again, then run `docker restart signoz-collector-agent-1`.

- **Collector settings** (image, environment): set them in the collector's `spec` (see <a href="https://github.com/SigNoz/foundry/blob/main/docs/concepts/moldings.md#spec-fields" target="_blank" rel="noopener noreferrer nofollow">spec fields</a>). For example, to pin the collector image:

  ```yaml
  spec:
    collector:
      spec:
        image: otel/opentelemetry-collector-contrib:0.139.0
  ```

- **Collector config** (receivers, processors, pipelines): add it under `spec.collector.spec.config.data`, keyed `collector/agent/agent.yaml`. It merges into the generated config (see <a href="https://github.com/SigNoz/foundry/blob/main/docs/concepts/moldings.md#custom-config-files" target="_blank" rel="noopener noreferrer nofollow">custom config files</a>). For example, to collect host metrics every 30s:

  ```yaml
  spec:
    collector:
      spec:
        config:
          data:
            collector/agent/agent.yaml: |
              receivers:
                hostmetrics:
                  collection_interval: 30s
  ```

- **Compose file** (mounts, user, memory limit): add <a href="https://github.com/SigNoz/foundry/blob/main/docs/concepts/patches.md" target="_blank" rel="noopener noreferrer nofollow">patches</a> under `spec.patches` against `collectionagent/compose.yaml`. For example, to mount the host's `/var/log` into the agent:

  ```yaml
  spec:
    patches:
      - target: collectionagent/compose.yaml
        operations:
          - op: add
            path: /services/collector-agent/volumes/-
            value: /var/log:/var/log:ro
  ```

  Take the target and paths from the files under `pours/`. Each run regenerates them, so keep every change in `casting.yaml`.

## Troubleshooting
</ToggleHeading>

### The agent logs `at least one endpoint must be specified`

In Step 4, `docker logs signoz-collector-agent-1` shows `exporters::otlphttp/signoz: at least one endpoint must be specified`, and the agent keeps restarting.

**Cause:** the casting sets no `SIGNOZ_INGESTION_ENDPOINT` under `spec.collector.spec.env`.

**Fix:** add it as in Step 2, then run `foundryctl cast -f casting.yaml` again from the directory that contains it, and `docker restart signoz-collector-agent-1`.

After the fix, `docker logs signoz-collector-agent-1` shows `Everything is ready`.

### The agent logs `bind: address already in use`

In Step 4, `docker logs signoz-collector-agent-1` shows `bind: address already in use` for port `4317` or `4318`, and the agent keeps restarting.

**Cause:** another process on the host holds the port, such as a self-hosted SigNoz on the same host.

**Fix:** remove the agent with `docker rm -f signoz-collector-agent-1`, give it its own name and ports as [Run on the same host as self-hosted SigNoz](https://signoz.io/docs/opentelemetry-collection-agents/docker/configure/#run-on-the-same-host-as-self-hosted-signoz) shows, then run `foundryctl cast -f casting.yaml` again from the directory that contains it. The agent then runs as `signoz-agent-collector-agent-1`.

After the fix, `docker logs` for the agent shows `Everything is ready`.

### foundryctl cast rejects a patch

`foundryctl cast -f casting.yaml` stops before it starts the agent, with `failed to apply patch for target "<target>"` followed by one of these:

- `patch target "<target>" did not match any generated material`
- `doc is missing path: <path>: missing value`
- `doc is missing key: <path>: missing value`
- `unable to remove nonexistent key: <key>: missing value`

**Cause:** the patch's target or path does not exist in what Foundry generates.

**Fix:** remove the patch, then run this from the directory that contains `casting.yaml`:

```bash
foundryctl forge -f casting.yaml
```

Take the target and path from the files under `pours/collectionagent/`, add the patch back, then run `foundryctl cast -f casting.yaml` again and `docker restart signoz-collector-agent-1`.

After the fix, `docker logs signoz-collector-agent-1` shows `Everything is ready`.
