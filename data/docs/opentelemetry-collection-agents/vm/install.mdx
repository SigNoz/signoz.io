This guide explains how to install the VM Collection Agent on a virtual machine or server: with Foundry on Linux, and from the OpenTelemetry Collector's release packages on macOS and Windows.

<Admonition type="warning" title="Migrating from a collector you set up yourself on Linux?" defaultCollapsed="true">
Foundry, documented below, is now the supported way to install and manage the VM Collection Agent on Linux.

If you already run the agent on Linux as the `otelcol-contrib` package, or as an `otelcol-contrib` process you set up yourself, with your own `config.yaml`, follow [Migrate to Foundry](https://signoz.io/docs/opentelemetry-collection-agents/vm/configure/#migrate-to-foundry) to move it over.
</Admonition>

## Prerequisites

- One of these hosts:
  - A Linux host with <a href="https://systemd.io/" target="_blank" rel="noopener noreferrer nofollow">systemd</a> 238 or newer, with `sudo`, `curl`, and `tar` on it.
  - A Mac (Apple silicon or Intel) with macOS 12 or newer.
  - A Windows 10 version 1803, Windows Server 2019, or newer host (x64), with administrator access for the MSI. The MSI starts its default config first, which also needs TCP ports `1777`, `9411`, `14250`, `14268`, and `55679` and UDP ports `6831` and `6832` free.
- Ports `4317`, `4318`, `8888`, and `13133` free on the host. To run the agent on the host that runs self-hosted SigNoz, see [Run on the same host as self-hosted SigNoz](https://signoz.io/docs/opentelemetry-collection-agents/vm/configure/#run-on-the-same-host-as-self-hosted-signoz).
- A SigNoz to send data to: [SigNoz Cloud](https://signoz.io/teams/) or a [self-hosted SigNoz](https://signoz.io/docs/install/self-host/).

## Install on Linux with Foundry

<Admonition type="info" title="What is Foundry?" defaultCollapsed="true">
Foundry is an open-source CLI that runs your self-hosted observability stack as code. One declarative config provisions the infrastructure, installs the SigNoz backend, and sets up OpenTelemetry collection on bare metal, containers, or Kubernetes. Learn more about <a href="https://github.com/SigNoz/foundry" target="_blank" rel="noopener noreferrer nofollow">Foundry</a>.
</Admonition>

### Step 1: Install foundryctl

Run this on the Linux host:

```bash
curl -fsSL https://signoz.io/foundry.sh | bash
```

For a manual install or PATH setup, see the <a href="https://github.com/SigNoz/foundry/blob/main/docs/getting-started.md" target="_blank" rel="noopener noreferrer nofollow">foundry getting-started guide</a>.

### Step 2: Download the OpenTelemetry Collector

The agent runs the OpenTelemetry Collector Contrib binary that you place on the host. Run this on the Linux host to download version 0.139.0 to `/opt/signoz-collector-agent/bin/otelcol-contrib`, where Foundry looks for it by default:

```bash
ARCH=$(uname -m | sed 's/x86_64/amd64/;s/aarch64/arm64/')
curl -fsSL "https://github.com/open-telemetry/opentelemetry-collector-releases/releases/download/v0.139.0/otelcol-contrib_0.139.0_linux_${ARCH}.tar.gz" | tar -xz otelcol-contrib
sudo install -D -m 755 otelcol-contrib /opt/signoz-collector-agent/bin/otelcol-contrib
```

### Step 3: Create casting.yaml

Create a file named `casting.yaml` on the Linux host, with one document for the agent described in [How it works](https://signoz.io/docs/opentelemetry-collection-agents/vm/overview/#how-it-works):

<Admonition type="info" title="Using Self-Hosted SigNoz?" defaultCollapsed="true">
Most steps are identical. To adapt this guide, update the endpoint and remove the ingestion key as shown in [Cloud → Self-Hosted](https://signoz.io/docs/ingestion/cloud-vs-self-hosted/?ingestion-client=collection-agent&collection-agent=foundry#cloud-to-self-hosted).
</Admonition>

```yaml:casting.yaml defaultCollapsed
apiVersion: v1alpha1
kind: CollectionAgent
metadata:
  name: signoz
spec:
  deployment:
    mode: systemd
    flavor: binary
  collector:
    spec:
      env:
        SIGNOZ_INGESTION_ENDPOINT: https://ingest.<region>.signoz.cloud:443
        SIGNOZ_INGESTION_KEY: <your-ingestion-key>
        OTEL_RESOURCE_ATTRIBUTES: deployment.environment=<your-environment>
      config:
        data:
          collector/agent/agent.yaml: |
            exporters:
              otlphttp/signoz:
                headers:
                  signoz-ingestion-key: ${env:SIGNOZ_INGESTION_KEY}
```

**Verify these values:**

- `<region>`: Your SigNoz Cloud [region](https://signoz.io/docs/ingestion/signoz-cloud/overview/#endpoint).
- `<your-ingestion-key>`: Your SigNoz Cloud [ingestion key](https://signoz.io/docs/ingestion/signoz-cloud/keys/).
- `<your-environment>`: Your deployment environment, for example `staging` or `production`.

For every option of this casting, see the <a href="https://github.com/SigNoz/foundry/tree/main/docs/examples/collectionagent/systemd/binary" target="_blank" rel="noopener noreferrer nofollow">systemd binary example</a>.

<Admonition type="info" title="Collector binary in another location?" defaultCollapsed="true">
Foundry runs the collector from `/opt/signoz-collector-agent/bin/otelcol-contrib`. If you placed it elsewhere, set its path under `metadata`:

```yaml
metadata:
  name: signoz
  annotations:
    foundry.signoz.io/collector-binary-path: /opt/otelcol/otelcol-contrib
```
</Admonition>

### Step 4: Deploy

Run this from the directory that contains `casting.yaml`:

```bash
sudo foundryctl cast -f casting.yaml
```

This command:

- writes the collector config, the environment file and the systemd unit to `pours/collectionagent/collector/agent/`;
- installs them under `/etc` and creates the `signoz-collector-agent` user;
- enables and restarts the `signoz-collector-agent` service.

Run the same command again after editing `casting.yaml`.

### Step 5: Verify the Collection Agent

Run this on the Linux host to check that the agent started:

```bash
sudo journalctl -u signoz-collector-agent --no-pager
```

The logs should include a line similar to the following:

```output
... Everything is ready. Begin running and processing data.
```

In SigNoz, open **[Infrastructure Monitoring](https://signoz.io/docs/infrastructure-monitoring/overview/)** > **Hosts**: your host appears under its host name as data arrives. Check **[Logs Explorer](https://signoz.io/docs/userguide/logs_query_builder/)** for the warnings and errors that services on the host write to the systemd journal.

## Customize the Collection Agent

Every change follows the same loop: edit `casting.yaml`, then run `sudo foundryctl cast -f casting.yaml` again. Each run restarts the agent.

- **Collector settings** (environment): set them in the collector's `spec` (see <a href="https://github.com/SigNoz/foundry/blob/main/docs/concepts/moldings.md#spec-fields" target="_blank" rel="noopener noreferrer nofollow">spec fields</a>). For example, to add a `team` resource attribute to everything the agent sends:

  ```yaml
  spec:
    collector:
      spec:
        env:
          OTEL_RESOURCE_ATTRIBUTES: deployment.environment=<your-environment>,team=backend
  ```

  **Verify these values:**

  - `<your-environment>`: Your deployment environment, for example `staging` or `production`.

- **Collector config** (receivers, processors, pipelines): add it under `spec.collector.spec.config.data`, keyed `collector/agent/agent.yaml`. It merges into the generated config (see <a href="https://github.com/SigNoz/foundry/blob/main/docs/concepts/moldings.md#custom-config-files" target="_blank" rel="noopener noreferrer nofollow">custom config files</a>). For example, to collect host metrics every 30s:

  ```yaml
  spec:
    collector:
      spec:
        config:
          data:
            collector/agent/agent.yaml: |
              receivers:
                hostmetrics:
                  collection_interval: 30s
  ```

- **Unit file** (resource limits, capabilities): add <a href="https://github.com/SigNoz/foundry/blob/main/docs/concepts/patches.md" target="_blank" rel="noopener noreferrer nofollow">patches</a> under `spec.patches` against `collectionagent/collector/agent/signoz-collector-agent.service`. A `[Service]` directive's path is `/Service/<Directive>`. For example, to cap the agent at half a CPU:

  ```yaml
  spec:
    patches:
      - target: collectionagent/collector/agent/signoz-collector-agent.service
        operations:
          - op: add
            path: /Service/CPUQuota
            value: 50%
  ```

  Take the target and paths from the files under `pours/`. Each run regenerates them, so keep every change in `casting.yaml`.

## Troubleshooting
</ToggleHeading>

### `sudo` cannot find `foundryctl`

In Step 4, `sudo foundryctl cast -f casting.yaml` stops with `sudo: foundryctl: command not found`.

**Cause:** the installer from Step 1 puts `foundryctl` in `~/.local/bin` (or `$XDG_BIN_HOME` when it is set), which is not on the `PATH` that `sudo` uses.

**Fix:** run `foundryctl` through `sudo` with your current `PATH`, from the directory that contains `casting.yaml`:

```bash
sudo env "PATH=$PATH" foundryctl cast -f casting.yaml
```

To make `foundryctl` available to `sudo` for every later command, install it into `/usr/local/bin` instead:

```bash
curl -fsSL https://signoz.io/foundry.sh | sudo bash -s -- -d /usr/local/bin
```

After the fix, the command installs the agent, and Step 5 shows `Everything is ready`.

### foundryctl cast stops with `binary not found`

In Step 4, `sudo foundryctl cast -f casting.yaml` stops with `otelcol-contrib binary not found at "/opt/signoz-collector-agent/bin/otelcol-contrib"`, before it installs anything under `/etc`.

**Cause:** the collector binary is not at that path.

**Fix:** run Step 2 again, or set the binary's path as **Collector binary in another location?** in Step 3 shows, then run Step 4 again.

After the fix, Step 5 shows `Everything is ready`.

### foundryctl cast refuses the collector's settings

In Step 4, `sudo foundryctl cast -f casting.yaml` stops with `failed to enrich molding collector`, followed by one of these:

- `spec.collector.spec.enabled is false, the CollectionAgent kind requires an enabled collector`
- `spec.collector.spec.cluster.replicas is 2, an agent runs once per host`

**Cause:** the casting turns the collector off or asks for more than one agent. The agent runs once on each host.

**Fix:** remove `enabled` and `cluster.replicas` from `spec.collector.spec`, then run Step 4 again.

After the fix, Step 5 shows `Everything is ready`.

### The agent logs `at least one endpoint must be specified`

In Step 5, `sudo journalctl -u signoz-collector-agent --no-pager` shows `exporters::otlphttp/signoz: at least one endpoint must be specified`, and systemd keeps restarting the agent.

**Cause:** the casting sets no `SIGNOZ_INGESTION_ENDPOINT` under `spec.collector.spec.env`.

**Fix:** add it as in Step 3, then run Step 4 again.

After the fix, Step 5 shows `Everything is ready`.

### The agent logs `bind: address already in use`

In Step 5, `sudo journalctl -u signoz-collector-agent --no-pager` shows `listen tcp 127.0.0.1:8888: bind: address already in use`, or the same error for `0.0.0.0:13133`, `0.0.0.0:4317`, or `0.0.0.0:4318`, and systemd keeps restarting the agent.

**Cause:** another process on the host holds the port, such as the `otelcol-contrib` service from the OpenTelemetry Collector package or a self-hosted SigNoz on the same host.

**Fix:** remove the old collector as [Migrate to Foundry](https://signoz.io/docs/opentelemetry-collection-agents/vm/configure/#migrate-to-foundry) shows, or move the agent's ports as [Run on the same host as self-hosted SigNoz](https://signoz.io/docs/opentelemetry-collection-agents/vm/configure/#run-on-the-same-host-as-self-hosted-signoz) shows, then run Step 4 again.

After the fix, Step 5 shows `Everything is ready`.

### foundryctl cast rejects a patch

In Step 4, `sudo foundryctl cast -f casting.yaml` stops before it installs the agent, with `failed to apply patch for target "<target>"` followed by one of these:

- `patch target "<target>" did not match any generated material`
- `doc is missing path: <path>: missing value`
- `doc is missing key: <path>: missing value`
- `unable to remove nonexistent key: <key>: missing value`
- `json patch on blob material "<target>" is not supported`

**Cause:** the patch's target or path does not exist in what Foundry generates. Patches apply to `agent.yaml` and the unit file; set the agent's variables under `spec.collector.spec.env`.

**Fix:** remove the patch, then run this from the directory that contains `casting.yaml`:

```bash
sudo foundryctl forge -f casting.yaml
```

Take the target and path from the files under `pours/collectionagent/`, add the patch back, then run Step 4 again.

After the fix, Step 5 shows `Everything is ready`.

## Install on macOS

On macOS, you run the OpenTelemetry Collector from its release tarball. Run every command in Terminal, in the directory where you keep the collector binary.

### Step 1: Download the tarball

Run this to download version 0.139.0 for your Mac:

```bash
ARCH=$(uname -m | sed 's/x86_64/amd64/')
curl -fsSL -O "https://github.com/open-telemetry/opentelemetry-collector-releases/releases/download/v0.139.0/otelcol-contrib_0.139.0_darwin_${ARCH}.tar.gz"
```

### Step 2: Extract the tarball

Run this in the same shell as Step 1:

```bash
tar -xzf otelcol-contrib_0.139.0_darwin_${ARCH}.tar.gz otelcol-contrib
```

This writes the collector binary `otelcol-contrib` to the current directory.

### Step 3: Create the collector config

Create `config.yaml` in the same directory, with this content:

<Admonition type="info" title="Using Self-Hosted SigNoz?" defaultCollapsed="true">
Most steps are identical. To adapt this guide, remove the `headers` block from `config.yaml`, then in Step 4 set `SIGNOZ_INGESTION_ENDPOINT` to `http://<signoz-host>:4318`, and leave out `SIGNOZ_INGESTION_KEY`. See [Cloud → Self-Hosted](https://signoz.io/docs/ingestion/cloud-vs-self-hosted/?ingestion-client=collector#cloud-to-self-hosted).

**Verify these values:**

- `<signoz-host>`: Your self-hosted SigNoz's address.
</Admonition>

```yaml:config.yaml minimap defaultCollapsed
receivers:
  otlp/grpc:
    protocols:
      grpc:
        endpoint: 0.0.0.0:4317
        max_recv_msg_size_mib: 16
  otlp/http:
    protocols:
      http:
        endpoint: 0.0.0.0:4318
  hostmetrics:
    collection_interval: 60s
    scrapers:
      cpu: {}
      memory: {}
      disk: {}
      filesystem:
        exclude_fs_types:
          match_type: strict
          fs_types:
            - autofs
        exclude_mount_points:
          match_type: regexp
          mount_points:
            - /dev/*
            - ^/System/Volumes/(Preboot|VM|Update|xarts|iSCPreboot|Hardware)$
      network:
        exclude:
          match_type: regexp
          interfaces:
            - ^lo0$
            - ^utun\d+$
            - ^awdl\d+$
            - ^llw\d+$
            - ^bridge\d+$
            - ^vmenet\d+$
            - ^anpi\d+$
            - ^ap\d+$
            - ^gif\d+$
            - ^stf\d+$
      load: {}
      paging: {}
      process:
        mute_process_all_errors: true
      processes: {}
      system: {}

processors:
  memory_limiter:
    check_interval: 5s
    limit_mib: 4000
    spike_limit_mib: 800
  resourcedetection:
    detectors: [env, ec2, gcp, azure, system]
    timeout: 2s
    override: false
    system:
      hostname_sources: [os]
      resource_attributes:
        host.id:
          enabled: true
  batch:
    send_batch_size: 1000
    send_batch_max_size: 2048
    timeout: 10s

exporters:
  otlphttp/signoz:
    endpoint: ${env:SIGNOZ_INGESTION_ENDPOINT}
    headers:
      signoz-ingestion-key: ${env:SIGNOZ_INGESTION_KEY}

extensions:
  health_check:
    endpoint: 0.0.0.0:13133
    path: /healthz

service:
  extensions: [health_check]
  pipelines:
    traces:
      receivers: [otlp/http, otlp/grpc]
      processors: [memory_limiter, resourcedetection, batch]
      exporters: [otlphttp/signoz]
    metrics:
      receivers: [otlp/http, otlp/grpc, hostmetrics]
      processors: [memory_limiter, resourcedetection, batch]
      exporters: [otlphttp/signoz]
    logs:
      receivers: [otlp/http, otlp/grpc]
      processors: [memory_limiter, resourcedetection, batch]
      exporters: [otlphttp/signoz]
```

### Step 4: Run the collector

Run this to set the agent's environment and start it in the background:

```bash
export SIGNOZ_INGESTION_ENDPOINT="https://ingest.<region>.signoz.cloud:443"
export SIGNOZ_INGESTION_KEY="<your-ingestion-key>"
export OTEL_RESOURCE_ATTRIBUTES="deployment.environment=<your-environment>"
nohup ./otelcol-contrib --config ./config.yaml > otelcol-output.log 2>&1 & echo "$!" > otel-pid
```

**Verify these values:**

- `<region>`: Your SigNoz Cloud [region](https://signoz.io/docs/ingestion/signoz-cloud/overview/#endpoint).
- `<your-ingestion-key>`: Your SigNoz Cloud [ingestion key](https://signoz.io/docs/ingestion/signoz-cloud/keys/).
- `<your-environment>`: Your deployment environment, for example `staging` or `production`.

The agent runs until you stop it, log out, or restart the Mac. It writes its logs to `otelcol-output.log` and its process ID to `otel-pid`.

### Step 5: Verify the Collection Agent

Run this to check that the agent started:

```bash
tail -n 20 otelcol-output.log
```

The logs should include a line similar to the following:

```output
... Everything is ready. Begin running and processing data.
```

In SigNoz, open **[Infrastructure Monitoring](https://signoz.io/docs/infrastructure-monitoring/overview/)** > **Hosts**: your Mac appears under its host name as data arrives.

## Customize the Collection Agent

Every change follows the same loop: edit `config.yaml`, then stop the agent and run Step 4 again:

```bash
kill "$(cat otel-pid)"
```

The [configure guide](https://signoz.io/docs/opentelemetry-collection-agents/vm/configure/?os=macos) shows what to add to `config.yaml` for each change.

## Troubleshooting
</ToggleHeading>

### The agent logs `at least one endpoint must be specified`

In Step 5, `otelcol-output.log` shows `exporters::otlphttp/signoz: at least one endpoint must be specified`, and the agent exits.

**Cause:** `SIGNOZ_INGESTION_ENDPOINT` is not set in the shell that started the agent.

**Fix:** run Step 4 again, with its `export` lines, in the same shell.

After the fix, Step 5 shows `Everything is ready`.

### The agent logs `bind: address already in use`

In Step 5, `otelcol-output.log` shows `listen tcp 127.0.0.1:8888: bind: address already in use`, or the same error for `0.0.0.0:13133`, `0.0.0.0:4317`, or `0.0.0.0:4318`, and the agent exits.

**Cause:** another process on the Mac holds the port, such as a collector you started earlier or a self-hosted SigNoz on the same Mac.

**Fix:** find the process that holds the port, for example `4317`:

```bash
sudo lsof -nP -iTCP:4317 -sTCP:LISTEN
```

Stop it, or move the agent's ports as [Run on the same host as self-hosted SigNoz](https://signoz.io/docs/opentelemetry-collection-agents/vm/configure/?os=macos#run-on-the-same-host-as-self-hosted-signoz) shows, then run Step 4 again.

After the fix, Step 5 shows `Everything is ready`.

## Install on Windows with the MSI

The OpenTelemetry Collector MSI installs the agent as the `otelcol-contrib` Windows service, which runs as LocalSystem and starts at boot. Run every command in PowerShell as Administrator.

### Step 1: Install the MSI

Run this to download version 0.139.0 and install it:

```powershell
curl.exe -fsSL -o "$env:TEMP\otelcol-contrib.msi" "https://github.com/open-telemetry/opentelemetry-collector-releases/releases/download/v0.139.0/otelcol-contrib_0.139.0_windows_x64.msi"
(Start-Process msiexec.exe -Wait -PassThru -ArgumentList "/i `"$env:TEMP\otelcol-contrib.msi`" /qn /norestart").ExitCode
```

The second command prints `0` when the install succeeds. The MSI installs `otelcol-contrib.exe` and a default `config.yaml` in `C:\Program Files\OpenTelemetry Collector\`, and starts the service. The service reads that `config.yaml`.

### Step 3: Set the environment and restart

Run this to set the service's environment and restart it:

```powershell
New-ItemProperty -Path 'HKLM:\SYSTEM\CurrentControlSet\Services\otelcol-contrib' -Name Environment -PropertyType MultiString -Force -Value @(
  'SIGNOZ_INGESTION_ENDPOINT=https://ingest.<region>.signoz.cloud:443'
  'SIGNOZ_INGESTION_KEY=<your-ingestion-key>'
  'OTEL_RESOURCE_ATTRIBUTES=deployment.environment=<your-environment>'
) | Out-Null
Restart-Service otelcol-contrib
```

**Verify these values:**

- `<region>`: Your SigNoz Cloud [region](https://signoz.io/docs/ingestion/signoz-cloud/overview/#endpoint).
- `<your-ingestion-key>`: Your SigNoz Cloud [ingestion key](https://signoz.io/docs/ingestion/signoz-cloud/keys/).
- `<your-environment>`: Your deployment environment, for example `staging` or `production`.

The environment variables go in the `otelcol-contrib` service's `Environment` registry value.

### Step 4: Verify the Collection Agent

Run this to check that the service started:

```powershell
(Get-Service otelcol-contrib).Status
Get-WinEvent -ProviderName otelcol-contrib -MaxEvents 20 | Select-Object -ExpandProperty Message
```

The first command prints `Running`, and the events should include a message similar to the following:

```output
... Everything is ready. Begin running and processing data.
```

In SigNoz, open **[Infrastructure Monitoring](https://signoz.io/docs/infrastructure-monitoring/overview/)** > **Hosts**: your host appears under its host name as data arrives.

## Customize the Collection Agent

Every change follows the same loop: edit `C:\Program Files\OpenTelemetry Collector\config.yaml`, then restart the service:

```powershell
Restart-Service otelcol-contrib
```

The [configure guide](https://signoz.io/docs/opentelemetry-collection-agents/vm/configure/?os=windows) shows what to add to `config.yaml` for each change. To change an environment variable, run Step 3 again with every variable the agent needs.

</ToggleHeading>

### The MSI install prints a code other than `0`

In Step 1, the install command prints a code other than `0`, such as `1603`, and `C:\Program Files\OpenTelemetry Collector\` has no `config.yaml`.

**Cause:** the MSI starts the service with its default config, which needs the ports in the [prerequisites](https://signoz.io/docs/opentelemetry-collection-agents/vm/install/#prerequisites), and another process on the host holds one of them, such as a self-hosted SigNoz or a collector you started yourself. When the service cannot start, the install is rolled back.

**Fix:** stop the other process and run Step 1 again, or [install the agent manually](https://signoz.io/docs/opentelemetry-collection-agents/vm/install/?os=windows&windows-method=manual#install-on-windows-manually).

After the fix, Step 1 prints `0`.

### The agent logs `at least one endpoint must be specified`

In Step 3, `Restart-Service otelcol-contrib` fails, and the events from Step 4 show `exporters::otlphttp/signoz: at least one endpoint must be specified`.

**Cause:** the service's `Environment` value sets no `SIGNOZ_INGESTION_ENDPOINT`.

**Fix:** run Step 3 again with every variable the agent needs, including `SIGNOZ_INGESTION_ENDPOINT`.

After the fix, Step 4 shows `Running` and `Everything is ready`.

### The agent logs `Only one usage of each socket address`

In Step 3, `Restart-Service otelcol-contrib` fails, and the events from Step 4 show `listen tcp 127.0.0.1:8888: bind: Only one usage of each socket address (protocol/network address/port) is normally permitted.`, or the same error for `0.0.0.0:13133`, `0.0.0.0:4317`, or `0.0.0.0:4318`.

**Cause:** another process on the host holds the port, such as a collector you started yourself or a self-hosted SigNoz on the same host.

**Fix:** find the process that holds the port, for example `4317`:

```powershell
Get-Process -Id (Get-NetTCPConnection -LocalPort 4317 -State Listen).OwningProcess
```

Stop it, or move the agent's ports as [Run on the same host as self-hosted SigNoz](https://signoz.io/docs/opentelemetry-collection-agents/vm/configure/?os=windows#run-on-the-same-host-as-self-hosted-signoz) shows, then run `Restart-Service otelcol-contrib`.

After the fix, Step 4 shows `Running` and `Everything is ready`.

## Install on Windows manually

You run the OpenTelemetry Collector from its release tarball. Run every command in PowerShell, in the folder where you keep the collector binary.

### Step 1: Download the tarball

Run this to download version 0.139.0:

```powershell
curl.exe -fsSL -o otelcol-contrib_0.139.0_windows_amd64.tar.gz "https://github.com/open-telemetry/opentelemetry-collector-releases/releases/download/v0.139.0/otelcol-contrib_0.139.0_windows_amd64.tar.gz"
```

### Step 2: Extract the tarball

Run this in the same PowerShell session:

```powershell
tar.exe -xzf otelcol-contrib_0.139.0_windows_amd64.tar.gz otelcol-contrib.exe
```

This writes the collector binary `otelcol-contrib.exe` to the current folder.

### Step 3: Create the collector config

Run this to create `config.yaml` in the same folder:

<Admonition type="info" title="Using Self-Hosted SigNoz?" defaultCollapsed="true">
Most steps are identical. To adapt this guide, remove the `headers` block from `config.yaml`, then in Step 4 set `SIGNOZ_INGESTION_ENDPOINT` to `http://<signoz-host>:4318`, and leave out `SIGNOZ_INGESTION_KEY`. See [Cloud → Self-Hosted](https://signoz.io/docs/ingestion/cloud-vs-self-hosted/?ingestion-client=collector#cloud-to-self-hosted).

**Verify these values:**

- `<signoz-host>`: Your self-hosted SigNoz's address.
</Admonition>

```powershell minimap defaultCollapsed
Set-Content -Encoding ascii -Path .\config.yaml -Value @'
receivers:
  otlp/grpc:
    protocols:
      grpc:
        endpoint: 0.0.0.0:4317
        max_recv_msg_size_mib: 16
  otlp/http:
    protocols:
      http:
        endpoint: 0.0.0.0:4318
  hostmetrics:
    collection_interval: 60s
    scrapers:
      cpu: {}
      memory: {}
      disk: {}
      filesystem: {}
      network: {}
      load: {}
      paging: {}
      process:
        mute_process_all_errors: true
      system: {}

processors:
  memory_limiter:
    check_interval: 5s
    limit_mib: 4000
    spike_limit_mib: 800
  resourcedetection:
    detectors: [env, ec2, gcp, azure, system]
    timeout: 2s
    override: false
    system:
      hostname_sources: [os]
      resource_attributes:
        host.id:
          enabled: true
  batch:
    send_batch_size: 1000
    send_batch_max_size: 2048
    timeout: 10s

exporters:
  otlphttp/signoz:
    endpoint: ${env:SIGNOZ_INGESTION_ENDPOINT}
    headers:
      signoz-ingestion-key: ${env:SIGNOZ_INGESTION_KEY}

extensions:
  health_check:
    endpoint: 0.0.0.0:13133
    path: /healthz

service:
  extensions: [health_check]
  pipelines:
    traces:
      receivers: [otlp/http, otlp/grpc]
      processors: [memory_limiter, resourcedetection, batch]
      exporters: [otlphttp/signoz]
    metrics:
      receivers: [otlp/http, otlp/grpc, hostmetrics]
      processors: [memory_limiter, resourcedetection, batch]
      exporters: [otlphttp/signoz]
    logs:
      receivers: [otlp/http, otlp/grpc]
      processors: [memory_limiter, resourcedetection, batch]
      exporters: [otlphttp/signoz]
'@
```

### Step 4: Run the collector

Run this to set the agent's environment and start it in the background:

```powershell
$env:SIGNOZ_INGESTION_ENDPOINT = 'https://ingest.<region>.signoz.cloud:443'
$env:SIGNOZ_INGESTION_KEY = '<your-ingestion-key>'
$env:OTEL_RESOURCE_ATTRIBUTES = 'deployment.environment=<your-environment>'
$collector = Start-Process -FilePath .\otelcol-contrib.exe -ArgumentList '--config', '.\config.yaml' -RedirectStandardError otelcol-output.log -WindowStyle Hidden -PassThru
$collector.Id | Set-Content otel-pid
```

**Verify these values:**

- `<region>`: Your SigNoz Cloud [region](https://signoz.io/docs/ingestion/signoz-cloud/overview/#endpoint).
- `<your-ingestion-key>`: Your SigNoz Cloud [ingestion key](https://signoz.io/docs/ingestion/signoz-cloud/keys/).
- `<your-environment>`: Your deployment environment, for example `staging` or `production`.

The agent runs until you stop it, sign out, or restart the host. It writes its logs to `otelcol-output.log` and its process ID to `otel-pid`.

### Step 5: Verify the Collection Agent

Run this to check that the agent started:

```powershell
Get-Content otelcol-output.log -Tail 20
```

The logs should include a line similar to the following:

```output
... Everything is ready. Begin running and processing data.
```

In SigNoz, open **[Infrastructure Monitoring](https://signoz.io/docs/infrastructure-monitoring/overview/)** > **Hosts**: your host appears under its host name as data arrives.

## Customize the Collection Agent

Every change follows the same loop: edit `config.yaml`, then stop the agent and run Step 4 again:

```powershell
Stop-Process -Id (Get-Content otel-pid)
```

The [configure guide](https://signoz.io/docs/opentelemetry-collection-agents/vm/configure/?os=windows) shows what to add to `config.yaml` for each change.
