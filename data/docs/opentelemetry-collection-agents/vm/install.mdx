This guide explains how to install the VM Collection Agent on a virtual machine or server: with Foundry on Linux, and as a service you create on macOS and Windows.

<Admonition type="warning" title="Migrating from a collector you set up yourself?" defaultCollapsed="true">
Foundry, documented below, is now the supported way to install and manage the VM Collection Agent on Linux.

If you already run the agent as the `otelcol-contrib` service from the OpenTelemetry Collector package, or from the tarball, with your own `config.yaml`, follow [Migrate to Foundry](https://signoz.io/docs/opentelemetry-collection-agents/vm/configure/#migrate-to-foundry) to move it over.

On macOS and Windows, first stop the collector you run today: on macOS, the process you started from the tarball, for example with `kill "$(cat otel-pid)"`; on Windows, uninstall the **OpenTelemetry Collector** app that the MSI installed, or stop the `otelcol-contrib.exe` process you started. Then follow the tab for your system, and carry your `config.yaml` customizations into the agent's `custom.yaml` with the component names and environment variables that step 2 of [Migrate to Foundry](https://signoz.io/docs/opentelemetry-collection-agents/vm/configure/#migrate-to-foundry) describes.
</Admonition>

## Prerequisites

- One of these hosts:
  - A Linux host with <a href="https://systemd.io/" target="_blank" rel="noopener noreferrer nofollow">systemd</a> 232 or newer, and `sudo` on it.
  - A Mac (Apple silicon or Intel) with macOS 12 or newer, and administrator access.
  - A Windows 10 version 1803, Windows Server 2019, or newer host (x64), with administrator access.
- Ports `4317`, `4318`, `8888`, and `13133` free on the host. To run the agent on the host that runs self-hosted SigNoz, see [Run on the same host as self-hosted SigNoz](https://signoz.io/docs/opentelemetry-collection-agents/vm/configure/#run-on-the-same-host-as-self-hosted-signoz).
- A SigNoz to send data to: [SigNoz Cloud](https://signoz.io/teams/) or a [self-hosted SigNoz](https://signoz.io/docs/install/self-host/).

## Install on Linux with Foundry

<Admonition type="info" title="What is Foundry?" defaultCollapsed="true">
Foundry is an open-source CLI that runs your self-hosted observability stack as code. One declarative config provisions the infrastructure, installs the SigNoz backend, and sets up OpenTelemetry collection on bare metal, containers, or Kubernetes. Learn more about <a href="https://github.com/SigNoz/foundry" target="_blank" rel="noopener noreferrer nofollow">Foundry</a>.
</Admonition>

### Step 1: Install foundryctl

Run this on the Linux host:

```bash
curl -fsSL https://signoz.io/foundry.sh | bash
```

For a manual install or PATH setup, see the <a href="https://github.com/SigNoz/foundry/blob/main/docs/getting-started.md" target="_blank" rel="noopener noreferrer nofollow">foundry getting-started guide</a>.

### Step 2: Download the OpenTelemetry Collector

The agent runs the OpenTelemetry Collector Contrib binary that you place on the host. Run this on the Linux host to download version 0.139.0 to `/opt/signoz-collector-agent/bin/otelcol-contrib`, where Foundry looks for it by default:

```bash
ARCH=$(uname -m | sed 's/x86_64/amd64/;s/aarch64/arm64/')
curl -fsSL "https://github.com/open-telemetry/opentelemetry-collector-releases/releases/download/v0.139.0/otelcol-contrib_0.139.0_linux_${ARCH}.tar.gz" | tar -xz otelcol-contrib
sudo install -D -m 755 otelcol-contrib /opt/signoz-collector-agent/bin/otelcol-contrib
```

### Step 3: Create casting.yaml

Create a file named `casting.yaml` on the Linux host, with one document for the agent described in [How it works](https://signoz.io/docs/opentelemetry-collection-agents/vm/overview/#how-it-works):

<Admonition type="info" title="Using Self-Hosted SigNoz?" defaultCollapsed="true">
Most steps are identical. To adapt this guide, update the endpoint and remove the ingestion key as shown in [Cloud → Self-Hosted](https://signoz.io/docs/ingestion/cloud-vs-self-hosted/?ingestion-client=collection-agent&collection-agent=foundry#cloud-to-self-hosted).
</Admonition>

```yaml:casting.yaml defaultCollapsed
apiVersion: v1alpha1
kind: CollectionAgent
metadata:
  name: signoz
spec:
  deployment:
    mode: systemd
    flavor: binary
  collector:
    spec:
      env:
        SIGNOZ_INGESTION_ENDPOINT: https://ingest.<region>.signoz.cloud:443
        SIGNOZ_INGESTION_KEY: <your-ingestion-key>
        OTEL_RESOURCE_ATTRIBUTES: deployment.environment=<your-environment>
      config:
        data:
          collector/agent/agent.yaml: |
            exporters:
              otlphttp/signoz:
                headers:
                  signoz-ingestion-key: ${env:SIGNOZ_INGESTION_KEY}
```

**Verify these values:**

- `<region>`: Your SigNoz Cloud [region](https://signoz.io/docs/ingestion/signoz-cloud/overview/#endpoint).
- `<your-ingestion-key>`: Your SigNoz Cloud [ingestion key](https://signoz.io/docs/ingestion/signoz-cloud/keys/).
- `<your-environment>`: Your deployment environment, for example `staging` or `production`.

For every option of this casting, see the <a href="https://github.com/SigNoz/foundry/tree/main/docs/examples/collectionagent/systemd/binary" target="_blank" rel="noopener noreferrer nofollow">systemd binary example</a>.

<Admonition type="info" title="Change the collector binary's path" defaultCollapsed="true">
If the binary from Step 2 is somewhere other than `/opt/signoz-collector-agent/bin/otelcol-contrib`, point Foundry at it with an annotation under `metadata`:

```yaml
metadata:
  name: signoz
  annotations:
    foundry.signoz.io/collector-binary-path: /opt/otelcol/otelcol-contrib
```
</Admonition>

### Step 4: Deploy

Run this from the directory that contains `casting.yaml`:

```bash
sudo foundryctl cast -f casting.yaml
```

This command:

- writes the collector config `agent.yaml`, the environment file `signoz-collector-agent.conf`, the systemd unit `signoz-collector-agent.service`, and the service-user file `signoz-collector-agent.sysusers.conf` to `pours/collectionagent/collector/agent/`;
- checks that the collector binary exists, then installs `agent.yaml` and the environment file to `/etc/signoz-collector-agent/`, the unit to `/etc/systemd/system/`, and the service-user file to `/etc/sysusers.d/signoz-collector-agent.conf`;
- creates the `signoz-collector-agent` user, then enables and restarts the `signoz-collector-agent` service.

It needs `sudo` because it writes to `/etc` and manages systemd. The file, directory and unit names follow `metadata.name`; the user is `signoz-collector-agent` for every name. Run the same command again after editing `casting.yaml`: it reinstalls the files and restarts the agent.

### Step 5: Verify the Collection Agent

Run this on the Linux host to check that the agent started:

```bash
sudo journalctl -u signoz-collector-agent --no-pager
```

The logs should include a line similar to the following:

```output
... Everything is ready. Begin running and processing data.
```

In SigNoz, open **[Infrastructure Monitoring](https://signoz.io/docs/infrastructure-monitoring/overview/)** > **Hosts**: your host appears under its host name as data arrives. Check **[Logs Explorer](https://signoz.io/docs/userguide/logs_query_builder/)** for the warnings and errors that services on the host write to the systemd journal.

## Customize the Collection Agent

Every change follows the same loop: edit `casting.yaml`, then run `sudo foundryctl cast -f casting.yaml` again. Each run restarts the agent.

- **Environment variables:** set them under `spec.collector.spec.env`, which becomes the agent's environment file. For example, to add a `team` resource attribute to everything the agent sends:

  ```yaml
  spec:
    collector:
      spec:
        env:
          OTEL_RESOURCE_ATTRIBUTES: deployment.environment=<your-environment>,team=backend
  ```

  **Verify these values:**

  - `<your-environment>`: Your deployment environment, for example `staging` or `production`.

- **Collector config** (receivers, processors, pipelines): add it under `spec.collector.spec.config.data`, keyed `collector/agent/agent.yaml`. It merges into the generated config (see <a href="https://github.com/SigNoz/foundry/blob/main/docs/concepts/moldings.md#custom-config-files" target="_blank" rel="noopener noreferrer nofollow">custom config files</a>). For example, to collect host metrics every 30s:

  ```yaml
  spec:
    collector:
      spec:
        config:
          data:
            collector/agent/agent.yaml: |
              receivers:
                hostmetrics:
                  collection_interval: 30s
  ```

- **Unit file** (resource limits, capabilities): add <a href="https://github.com/SigNoz/foundry/blob/main/docs/concepts/patches.md" target="_blank" rel="noopener noreferrer nofollow">patches</a> under `spec.patches` against `collectionagent/collector/agent/signoz-collector-agent.service`. A `[Service]` directive's path is `/Service/<Directive>`. For example, to cap the agent at half a CPU:

  ```yaml
  spec:
    patches:
      - target: collectionagent/collector/agent/signoz-collector-agent.service
        operations:
          - op: add
            path: /Service/CPUQuota
            value: 50%
  ```

  Take the target and paths from the files under `pours/`. Each run regenerates them, so keep every change in `casting.yaml`.

## Troubleshooting
</ToggleHeading>

### `sudo` cannot find `foundryctl`

In Step 4, `sudo foundryctl cast -f casting.yaml` stops with `sudo: foundryctl: command not found`.

**Cause:** the installer from Step 1 puts `foundryctl` in `~/.local/bin` (or `$XDG_BIN_HOME` when it is set), which is not on the `PATH` that `sudo` uses.

**Fix:** run `foundryctl` through `sudo` with your current `PATH`, from the directory that contains `casting.yaml`:

```bash
sudo env "PATH=$PATH" foundryctl cast -f casting.yaml
```

To make `foundryctl` available to `sudo` for every later command, install it into `/usr/local/bin` instead:

```bash
curl -fsSL https://signoz.io/foundry.sh | sudo bash -s -- -d /usr/local/bin
```

After the fix, the command installs the agent, and Step 5 shows `Everything is ready`.

### foundryctl cast stops with `binary not found`

In Step 4, `sudo foundryctl cast -f casting.yaml` stops with `otelcol-contrib binary not found at "/opt/signoz-collector-agent/bin/otelcol-contrib"`, before it installs anything under `/etc`.

**Cause:** the collector binary is not at that path.

**Fix:** run Step 2 again, or point Foundry at the binary's path as **Change the collector binary's path** in Step 3 shows, then run Step 4 again.

After the fix, Step 5 shows `Everything is ready`.

### foundryctl cast refuses the collector's settings

In Step 4, `sudo foundryctl cast -f casting.yaml` stops with `failed to enrich molding collector`, followed by one of these:

- `spec.collector.spec.enabled is false, the CollectionAgent kind requires an enabled collector`
- `spec.collector.spec.cluster.replicas is 2, an agent runs once per host`

**Cause:** the casting turns the collector off or asks for more than one agent. The agent runs once on each host.

**Fix:** remove `enabled` and `cluster.replicas` from `spec.collector.spec`, then run Step 4 again.

After the fix, Step 5 shows `Everything is ready`.

### The agent logs `at least one endpoint must be specified`

In Step 5, `sudo journalctl -u signoz-collector-agent --no-pager` shows `exporters::otlphttp/signoz: at least one endpoint must be specified`, and systemd keeps restarting the agent.

**Cause:** the casting sets no `SIGNOZ_INGESTION_ENDPOINT` under `spec.collector.spec.env`.

**Fix:** add it as in Step 3, then run Step 4 again.

After the fix, Step 5 shows `Everything is ready`.

### The agent logs `bind: address already in use`

In Step 5, `sudo journalctl -u signoz-collector-agent --no-pager` shows `listen tcp 127.0.0.1:8888: bind: address already in use`, or the same error for `0.0.0.0:13133`, `0.0.0.0:4317`, or `0.0.0.0:4318`, and systemd keeps restarting the agent.

**Cause:** another process on the host holds the port, such as the `otelcol-contrib` service from the OpenTelemetry Collector package or a self-hosted SigNoz on the same host.

**Fix:** remove the old collector as [Migrate to Foundry](https://signoz.io/docs/opentelemetry-collection-agents/vm/configure/#migrate-to-foundry) shows, or move the agent's ports as [Run on the same host as self-hosted SigNoz](https://signoz.io/docs/opentelemetry-collection-agents/vm/configure/#run-on-the-same-host-as-self-hosted-signoz) shows, then run Step 4 again.

After the fix, Step 5 shows `Everything is ready`.

### foundryctl cast rejects a patch

In Step 4, `sudo foundryctl cast -f casting.yaml` stops before it installs the agent, with `failed to apply patch for target "<target>"` followed by one of these:

- `patch target "<target>" did not match any generated material`
- `doc is missing path: "<path>": missing value`
- `doc is missing key: <path>: missing value`
- `unable to remove nonexistent key: <key>: missing value`
- `json patch on blob material "<target>" is not supported`

**Cause:** the patch's target or path does not exist in what Foundry generates. The environment file `signoz-collector-agent.conf` and the service-user file take no patches: set the agent's variables under `spec.collector.spec.env`.

**Fix:** remove the patch, then run this from the directory that contains `casting.yaml`:

```bash
sudo foundryctl forge -f casting.yaml
```

Take the target and path from the files under `pours/collectionagent/`, add the patch back, then run Step 4 again.

After the fix, Step 5 shows `Everything is ready`.

## Install on macOS

On macOS, the agent runs as the launchd daemon `io.signoz.signoz-collector-agent`, which you create in the steps below. Run every command in Terminal on the Mac.

### Step 1: Download the OpenTelemetry Collector

Run this to download the OpenTelemetry Collector Contrib binary, version 0.139.0, to `/opt/signoz-collector-agent/bin/otelcol-contrib`:

```bash
ARCH=$(uname -m | sed 's/x86_64/amd64/')
curl -fsSL "https://github.com/open-telemetry/opentelemetry-collector-releases/releases/download/v0.139.0/otelcol-contrib_0.139.0_darwin_${ARCH}.tar.gz" | tar -xz otelcol-contrib
sudo install -d /opt/signoz-collector-agent/bin
sudo install -m 755 otelcol-contrib /opt/signoz-collector-agent/bin/otelcol-contrib
```

### Step 2: Create the collector config

The agent reads two config files in `/etc/signoz-collector-agent/`. `agent.yaml` holds its defaults, the same config Foundry generates on Linux with macOS filters for host metrics and no host logs. Keep it as it is: your changes go in `custom.yaml`. Run this to create `agent.yaml`:

```bash minimap defaultCollapsed
sudo mkdir -p /etc/signoz-collector-agent
sudo tee /etc/signoz-collector-agent/agent.yaml > /dev/null <<'EOF'
receivers:
  otlp/grpc:
    protocols:
      grpc:
        endpoint: 0.0.0.0:4317
        max_recv_msg_size_mib: 16
  otlp/http:
    protocols:
      http:
        endpoint: 0.0.0.0:4318
  hostmetrics:
    collection_interval: 60s
    scrapers:
      cpu: {}
      memory: {}
      disk: {}
      filesystem:
        exclude_fs_types:
          match_type: strict
          fs_types:
            - autofs
        exclude_mount_points:
          match_type: regexp
          mount_points:
            - /dev/*
      network:
        exclude:
          match_type: regexp
          interfaces:
            - ^lo0$
      load: {}
      paging: {}
      process:
        mute_process_name_error: true
        mute_process_exe_error: true
        mute_process_io_error: true
        mute_process_user_error: true
      processes: {}
      system: {}

processors:
  memory_limiter:
    check_interval: 5s
    limit_mib: 4000
    spike_limit_mib: 800
  resourcedetection:
    detectors: [env, ec2, gcp, azure, system]
    timeout: 2s
    override: false
    system:
      hostname_sources: [os]
      resource_attributes:
        host.id:
          enabled: true
  batch:
    send_batch_size: 1000
    send_batch_max_size: 2048
    timeout: 10s

exporters:
  otlphttp/signoz:
    endpoint: ${env:SIGNOZ_INGESTION_ENDPOINT}

extensions:
  health_check:
    endpoint: 0.0.0.0:13133
    path: /healthz

service:
  extensions: [health_check]
  pipelines:
    traces:
      receivers: [otlp/http, otlp/grpc]
      processors: [memory_limiter, resourcedetection, batch]
      exporters: [otlphttp/signoz]
    metrics:
      receivers: [otlp/http, otlp/grpc, hostmetrics]
      processors: [memory_limiter, resourcedetection, batch]
      exporters: [otlphttp/signoz]
    logs:
      receivers: [otlp/http, otlp/grpc]
      processors: [memory_limiter, resourcedetection, batch]
      exporters: [otlphttp/signoz]
EOF
```

<Admonition type="info" title="Using Self-Hosted SigNoz?" defaultCollapsed="true">
Most steps are identical. To adapt this guide, create `custom.yaml` empty, then in Step 3 set `SIGNOZ_INGESTION_ENDPOINT` in the environment file to `http://<signoz-host>:4318`, where `<signoz-host>` is your self-hosted SigNoz's address, and remove the `SIGNOZ_INGESTION_KEY` line.
</Admonition>

Then create `custom.yaml`. The collector merges it over `agent.yaml`, and it starts with the header that sends your ingestion key:

```bash
sudo tee /etc/signoz-collector-agent/custom.yaml > /dev/null <<'EOF'
exporters:
  otlphttp/signoz:
    headers:
      signoz-ingestion-key: ${env:SIGNOZ_INGESTION_KEY}
EOF
```

### Step 3: Create the launchd daemon

Run this to write the agent's environment file, `signoz-collector-agent.conf`, readable by root only:

```bash
sudo install -m 600 /dev/null /etc/signoz-collector-agent/signoz-collector-agent.conf
sudo tee /etc/signoz-collector-agent/signoz-collector-agent.conf > /dev/null <<'EOF'
SIGNOZ_INGESTION_ENDPOINT="https://ingest.<region>.signoz.cloud:443"
SIGNOZ_INGESTION_KEY="<your-ingestion-key>"
OTEL_RESOURCE_ATTRIBUTES="deployment.environment=<your-environment>"
EOF
```

**Verify these values:**

- `<region>`: Your SigNoz Cloud [region](https://signoz.io/docs/ingestion/signoz-cloud/overview/#endpoint).
- `<your-ingestion-key>`: Your SigNoz Cloud [ingestion key](https://signoz.io/docs/ingestion/signoz-cloud/keys/).
- `<your-environment>`: Your deployment environment, for example `staging` or `production`.

Then run this to create the log directory and the daemon's definition, `/Library/LaunchDaemons/io.signoz.signoz-collector-agent.plist`:

```bash defaultCollapsed
sudo mkdir -p /Library/Logs/signoz-collector-agent
sudo tee /Library/LaunchDaemons/io.signoz.signoz-collector-agent.plist > /dev/null <<'EOF'
<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE plist PUBLIC "-//Apple//DTD PLIST 1.0//EN" "http://www.apple.com/DTDs/PropertyList-1.0.dtd">
<plist version="1.0">
<dict>
  <key>Label</key>
  <string>io.signoz.signoz-collector-agent</string>
  <key>ProgramArguments</key>
  <array>
    <string>/bin/sh</string>
    <string>-c</string>
    <string>set -a; . /etc/signoz-collector-agent/signoz-collector-agent.conf; exec /opt/signoz-collector-agent/bin/otelcol-contrib --config=/etc/signoz-collector-agent/agent.yaml --config=/etc/signoz-collector-agent/custom.yaml</string>
  </array>
  <key>RunAtLoad</key>
  <true/>
  <key>KeepAlive</key>
  <true/>
  <key>StandardErrorPath</key>
  <string>/Library/Logs/signoz-collector-agent/collector.log</string>
</dict>
</plist>
EOF
```

The daemon loads the environment file, runs the collector as root with both config files, restarts it whenever it exits, and writes the collector's own logs to `/Library/Logs/signoz-collector-agent/collector.log`. The ingestion key stays in the environment file, which only root can read.

### Step 4: Start the agent

Run this to load the daemon:

```bash
sudo launchctl bootstrap system /Library/LaunchDaemons/io.signoz.signoz-collector-agent.plist
```

launchd starts the agent now and at every boot.

### Step 5: Verify the Collection Agent

Run this to check that the agent started:

```bash
sudo launchctl print system/io.signoz.signoz-collector-agent | grep 'state ='
sudo tail -n 20 /Library/Logs/signoz-collector-agent/collector.log
```

The first command prints `state = running`, and the log should include a line similar to the following:

```output
... Everything is ready. Begin running and processing data.
```

In SigNoz, open **[Infrastructure Monitoring](https://signoz.io/docs/infrastructure-monitoring/overview/)** > **Hosts**: your Mac appears under its host name as data arrives.

## Customize the Collection Agent

Every change follows the same loop: edit `custom.yaml` or the environment file `signoz-collector-agent.conf` in `/etc/signoz-collector-agent/`, then restart the agent:

```bash
sudo launchctl kickstart -k system/io.signoz.signoz-collector-agent
```

- **Collector config** (receivers, processors, pipelines): add it to `custom.yaml`, which the collector merges over `agent.yaml`. Each section of the configure guide shows the YAML to add, under a `collector/agent/agent.yaml: |` line, as [Apply Changes](https://signoz.io/docs/opentelemetry-collection-agents/vm/configure/?os=macos#apply-changes) explains. For example, to collect host metrics every 30s, `custom.yaml` becomes:

  ```yaml:custom.yaml
  exporters:
    otlphttp/signoz:
      headers:
        signoz-ingestion-key: ${env:SIGNOZ_INGESTION_KEY}
  receivers:
    hostmetrics:
      collection_interval: 30s
  ```

- **Environment variables:** set them in `signoz-collector-agent.conf`, one `NAME="value"` per line. The daemon loads the file each time the agent starts.

## Troubleshooting
</ToggleHeading>

### The agent logs `at least one endpoint must be specified`

In Step 5, `collector.log` shows `exporters::otlphttp/signoz: at least one endpoint must be specified`, and launchd keeps restarting the agent.

**Cause:** the environment file `signoz-collector-agent.conf` sets no `SIGNOZ_INGESTION_ENDPOINT`.

**Fix:** add it as in Step 3, then restart the agent:

```bash
sudo launchctl kickstart -k system/io.signoz.signoz-collector-agent
```

After the fix, Step 5 shows `Everything is ready`.

### The agent logs `bind: address already in use`

In Step 5, `collector.log` shows `listen tcp 127.0.0.1:8888: bind: address already in use`, or the same error for `0.0.0.0:13133`, `0.0.0.0:4317`, or `0.0.0.0:4318`, and launchd keeps restarting the agent.

**Cause:** another process on the Mac holds the port, such as a collector you started yourself or a self-hosted SigNoz on the same Mac.

**Fix:** find the process that holds the port, for example `4317`:

```bash
sudo lsof -nP -iTCP:4317 -sTCP:LISTEN
```

Stop it, or move the agent's ports as [Run on the same host as self-hosted SigNoz](https://signoz.io/docs/opentelemetry-collection-agents/vm/configure/#run-on-the-same-host-as-self-hosted-signoz) shows, then restart the agent with `sudo launchctl kickstart -k system/io.signoz.signoz-collector-agent`.

After the fix, Step 5 shows `Everything is ready`.

</details>

## Install on Windows

On Windows, the agent runs as the Windows service `signoz-collector-agent`, which you create in the steps below. Run every command in Windows PowerShell as Administrator.

### Step 1: Download the OpenTelemetry Collector

Run this to download the OpenTelemetry Collector Contrib binary, version 0.139.0, to `C:\Program Files\signoz-collector-agent\bin\otelcol-contrib.exe`:

```powershell
New-Item -ItemType Directory -Force -Path 'C:\Program Files\signoz-collector-agent\bin' | Out-Null
curl.exe -fsSL -o "$env:TEMP\otelcol-contrib.tar.gz" "https://github.com/open-telemetry/opentelemetry-collector-releases/releases/download/v0.139.0/otelcol-contrib_0.139.0_windows_amd64.tar.gz"
tar.exe -xzf "$env:TEMP\otelcol-contrib.tar.gz" -C 'C:\Program Files\signoz-collector-agent\bin' otelcol-contrib.exe
```

### Step 2: Create the collector config

The agent reads two config files in `C:\ProgramData\signoz-collector-agent\`. `agent.yaml` holds its defaults, the same config Foundry generates on Linux with Windows settings for host metrics and no host logs. Keep it as it is: your changes go in `custom.yaml`. Run this to create `agent.yaml`:

```powershell minimap defaultCollapsed
New-Item -ItemType Directory -Force -Path 'C:\ProgramData\signoz-collector-agent' | Out-Null
Set-Content -Encoding ascii -Path 'C:\ProgramData\signoz-collector-agent\agent.yaml' -Value @'
receivers:
  otlp/grpc:
    protocols:
      grpc:
        endpoint: 0.0.0.0:4317
        max_recv_msg_size_mib: 16
  otlp/http:
    protocols:
      http:
        endpoint: 0.0.0.0:4318
  hostmetrics:
    collection_interval: 60s
    scrapers:
      cpu: {}
      memory: {}
      disk: {}
      filesystem: {}
      network: {}
      load: {}
      paging: {}
      process:
        mute_process_name_error: true
        mute_process_exe_error: true
        mute_process_io_error: true
        mute_process_user_error: true
      system: {}

processors:
  memory_limiter:
    check_interval: 5s
    limit_mib: 4000
    spike_limit_mib: 800
  resourcedetection:
    detectors: [env, ec2, gcp, azure, system]
    timeout: 2s
    override: false
    system:
      hostname_sources: [os]
      resource_attributes:
        host.id:
          enabled: true
  batch:
    send_batch_size: 1000
    send_batch_max_size: 2048
    timeout: 10s

exporters:
  otlphttp/signoz:
    endpoint: ${env:SIGNOZ_INGESTION_ENDPOINT}

extensions:
  health_check:
    endpoint: 0.0.0.0:13133
    path: /healthz

service:
  extensions: [health_check]
  pipelines:
    traces:
      receivers: [otlp/http, otlp/grpc]
      processors: [memory_limiter, resourcedetection, batch]
      exporters: [otlphttp/signoz]
    metrics:
      receivers: [otlp/http, otlp/grpc, hostmetrics]
      processors: [memory_limiter, resourcedetection, batch]
      exporters: [otlphttp/signoz]
    logs:
      receivers: [otlp/http, otlp/grpc]
      processors: [memory_limiter, resourcedetection, batch]
      exporters: [otlphttp/signoz]
'@
```

<Admonition type="info" title="Using Self-Hosted SigNoz?" defaultCollapsed="true">
Most steps are identical. To adapt this guide, create `custom.yaml` empty, then in Step 3 set `SIGNOZ_INGESTION_ENDPOINT` to `http://<signoz-host>:4318`, where `<signoz-host>` is your self-hosted SigNoz's address, and remove the `SIGNOZ_INGESTION_KEY` line.
</Admonition>

Then create `custom.yaml`. The collector merges it over `agent.yaml`, and it starts with the header that sends your ingestion key:

```powershell
Set-Content -Encoding ascii -Path 'C:\ProgramData\signoz-collector-agent\custom.yaml' -Value @'
exporters:
  otlphttp/signoz:
    headers:
      signoz-ingestion-key: ${env:SIGNOZ_INGESTION_KEY}
'@
```

### Step 3: Create the service

Run this to create the service, set its environment, and register its Event Log source:

```powershell
$service = @{
  Name           = 'signoz-collector-agent'
  DisplayName    = 'SigNoz OpenTelemetry Collector'
  StartupType    = 'Automatic'
  BinaryPathName = '"C:\Program Files\signoz-collector-agent\bin\otelcol-contrib.exe" --config="C:\ProgramData\signoz-collector-agent\agent.yaml" --config="C:\ProgramData\signoz-collector-agent\custom.yaml"'
}
New-Service @service | Out-Null

New-ItemProperty -Path 'HKLM:\SYSTEM\CurrentControlSet\Services\signoz-collector-agent' -Name Environment -PropertyType MultiString -Force -Value @(
  'SIGNOZ_INGESTION_ENDPOINT=https://ingest.<region>.signoz.cloud:443'
  'SIGNOZ_INGESTION_KEY=<your-ingestion-key>'
  'OTEL_RESOURCE_ATTRIBUTES=deployment.environment=<your-environment>'
) | Out-Null

$source = 'HKLM:\SYSTEM\CurrentControlSet\Services\EventLog\Application\signoz-collector-agent'
New-Item -Path $source -Force | Out-Null
New-ItemProperty -Path $source -Name EventMessageFile -PropertyType ExpandString -Value '%SystemRoot%\System32\EventCreate.exe' -Force | Out-Null
```

**Verify these values:**

- `<region>`: Your SigNoz Cloud [region](https://signoz.io/docs/ingestion/signoz-cloud/overview/#endpoint).
- `<your-ingestion-key>`: Your SigNoz Cloud [ingestion key](https://signoz.io/docs/ingestion/signoz-cloud/keys/).
- `<your-environment>`: Your deployment environment, for example `staging` or `production`.

The service runs the collector as LocalSystem with both config files and starts at boot. Its environment lives in the service's `Environment` registry value, one `NAME=value` per line, which Windows passes to the service when it starts (see the <a href="https://github.com/open-telemetry/opentelemetry-dotnet-instrumentation/blob/v1.17.0/docs/windows-service-instrumentation.md#configuration" target="_blank" rel="noopener noreferrer nofollow">OpenTelemetry .NET guide to Windows service environment variables</a>). The collector writes its own logs to the Application event log under the `signoz-collector-agent` source.

### Step 4: Start the agent

Run this to start the service:

```powershell
Start-Service signoz-collector-agent
```

### Step 5: Verify the Collection Agent

Run this to check that the agent started:

```powershell
(Get-Service signoz-collector-agent).Status
Get-WinEvent -FilterHashtable @{ LogName = 'Application'; ProviderName = 'signoz-collector-agent' } -MaxEvents 20 | Select-Object -ExpandProperty Message
```

The first command prints `Running`, and the events should include a message similar to the following:

```output
... Everything is ready. Begin running and processing data.
```

In SigNoz, open **[Infrastructure Monitoring](https://signoz.io/docs/infrastructure-monitoring/overview/)** > **Hosts**: your host appears under its host name as data arrives.

## Customize the Collection Agent

Every change follows the same loop: edit `C:\ProgramData\signoz-collector-agent\custom.yaml`, then restart the agent:

```powershell
Restart-Service signoz-collector-agent
```

- **Collector config** (receivers, processors, pipelines): add it to `custom.yaml`, which the collector merges over `agent.yaml`. Each section of the configure guide shows the YAML to add, under a `collector/agent/agent.yaml: |` line, as [Apply Changes](https://signoz.io/docs/opentelemetry-collection-agents/vm/configure/?os=windows#apply-changes) explains. For example, to collect host metrics every 30s, `custom.yaml` becomes:

  ```yaml:custom.yaml
  exporters:
    otlphttp/signoz:
      headers:
        signoz-ingestion-key: ${env:SIGNOZ_INGESTION_KEY}
  receivers:
    hostmetrics:
      collection_interval: 30s
  ```

- **Environment variables:** run the `New-ItemProperty ... -Name Environment` command from Step 3 again with every variable the agent needs, then restart the agent.

## Troubleshooting
</ToggleHeading>

### The agent logs `at least one endpoint must be specified`

In Step 4, `Start-Service signoz-collector-agent` fails, and the events from Step 5 show `exporters::otlphttp/signoz: at least one endpoint must be specified`.

**Cause:** the service's `Environment` value sets no `SIGNOZ_INGESTION_ENDPOINT`.

**Fix:** run the `New-ItemProperty ... -Name Environment` command from Step 3 again with every variable the agent needs, including `SIGNOZ_INGESTION_ENDPOINT`, then run Step 4 again.

After the fix, Step 5 shows `Running` and `Everything is ready`.

### The agent logs `Only one usage of each socket address`

In Step 4, `Start-Service signoz-collector-agent` fails, and the events from Step 5 show `listen tcp 127.0.0.1:8888: bind: Only one usage of each socket address (protocol/network address/port) is normally permitted.`, or the same error for `0.0.0.0:13133`, `0.0.0.0:4317`, or `0.0.0.0:4318`.

**Cause:** another process on the host holds the port, such as the `otelcol-contrib` service from the OpenTelemetry Collector MSI or a self-hosted SigNoz on the same host.

**Fix:** find the process that holds the port, for example `4317`:

```powershell
Get-Process -Id (Get-NetTCPConnection -LocalPort 4317 -State Listen).OwningProcess
```

Stop it, or uninstall the **OpenTelemetry Collector** app if the MSI installed it, or move the agent's ports as [Run on the same host as self-hosted SigNoz](https://signoz.io/docs/opentelemetry-collection-agents/vm/configure/#run-on-the-same-host-as-self-hosted-signoz) shows, then run Step 4 again.

After the fix, Step 5 shows `Running` and `Everything is ready`.
