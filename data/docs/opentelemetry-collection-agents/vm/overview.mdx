The VM Collection Agent runs one OpenTelemetry Collector as a service on each virtual machine or server: a systemd service on Linux, a launchd daemon on macOS, and a Windows service on Windows. It collects the host's metrics, receives telemetry from your instrumented applications, and sends everything to SigNoz. On Linux, it also collects the warnings and errors in the systemd journal.

[Install it](https://signoz.io/docs/opentelemetry-collection-agents/vm/install/) with Foundry on Linux, or as a service you create on macOS and Windows.

The VM Collection Agent primarily performs the following:

- Collects host metrics such as CPU, memory, disk, filesystem, network, and load from the host.
- Collects the warnings and errors that services write to the systemd journal on Linux hosts.
- Acts as a gateway to send traces, metrics, and logs from your applications to SigNoz.

## How it works

<Figure src="/img/docs/saas-docs/vm-setup-2x.webp" alt="Collecting data from applications deployed in VM" caption="Instrumented applications on a VM send telemetry to the agent on the same VM, which forwards it to SigNoz." />

### Agent (systemd service)

On Linux, the agent runs as the `signoz-collector-agent.service` systemd unit under the `signoz-collector-agent` user. The unit lets it read the journal and any file on the host outside `/tmp` and `/var/tmp`, and gives it no write access to the host's files. It collects:

- **Host metrics:** CPU, memory, disk I/O, filesystem usage, network, load, paging, per-process usage, process counts, and uptime, via `hostmetrics`.
- **Host logs:** Journal entries at priority warning and above, via `journald`. Each record's `service.name` resource attribute is its systemd unit without `.service`, or its program name when it has no unit. The agent leaves out its own entries.
- **OTLP:** Traces, metrics, and logs from instrumented applications, over OTLP/gRPC (4317) and OTLP/HTTP (4318).
- **Resource attributes:** `host.name`, `host.id`, and `os.type` on every signal, and on AWS, GCP, and Azure virtual machines the cloud provider, region, and instance.

### Agent (launchd daemon or Windows service)

On macOS, the agent runs as the `io.signoz.signoz-collector-agent` launchd daemon, as root. On Windows, it runs as the `signoz-collector-agent` Windows service, as LocalSystem. Both use the Linux agent's collector config without the journal:

- **Host metrics:** The same metrics as on Linux, via `hostmetrics`, except that both report fewer disk metrics and Windows reports no process counts.
- **OTLP:** Traces, metrics, and logs from instrumented applications, over OTLP/gRPC (4317) and OTLP/HTTP (4318).
- **Resource attributes:** The same as on Linux.

## Known Limitations

- Foundry installs the agent on Linux hosts with systemd. On macOS and Windows, you create and manage the service yourself.
- On Linux, the agent collects only journal entries that services mark as warnings or errors. Output a service writes without a priority, such as plain standard output and standard error, is stored as info and left out until you [collect more of the journal](https://signoz.io/docs/opentelemetry-collection-agents/vm/configure/#collect-host-logs).
- Journal entries written while the agent is stopped are skipped.
- On macOS and Windows, the agent collects no system logs, such as the macOS unified log or the Windows Event Log.
