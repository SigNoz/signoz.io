The VM Collection Agent runs one OpenTelemetry Collector on each virtual machine or server: as a systemd service on Linux, as a process on macOS, and as a Windows service or a process on Windows. It collects the host's metrics, receives telemetry from your instrumented applications, and sends everything to SigNoz. On Linux, it also collects the warnings and errors in the systemd journal.

The VM Collection Agent primarily performs the following:

- Collects host metrics such as CPU, memory, disk, filesystem, network, and load from the host.
- Collects the warnings and errors that services write to the systemd journal on Linux hosts.
- Acts as a gateway to send traces, metrics, and logs from your applications to SigNoz.

## How it works

<Figure src="/img/docs/saas-docs/vm-setup-2x.webp" alt="Collecting data from applications deployed in VM" caption="Instrumented applications on a VM send telemetry to the agent on the same VM, which forwards it to SigNoz." />

### Agent (systemd service)

On Linux, the agent runs as the `signoz-collector-agent.service` systemd unit under the `signoz-collector-agent` user. The unit lets it read the journal and any file on the host outside `/tmp` and `/var/tmp`, and gives it no write access to the host's files. It collects:

- **Host metrics:** CPU, memory, disk I/O, filesystem usage, network, load, paging, per-process usage, process counts, and uptime, via `hostmetrics`.
- **Host logs:** Journal entries at priority warning and above, via `journald`. Each record's `service.name` resource attribute is its systemd unit without `.service`, or its program name when it has no unit. The agent leaves out its own entries.
- **OTLP:** Traces, metrics, and logs from instrumented applications, over OTLP/gRPC (4317) and OTLP/HTTP (4318).
- **Resource attributes:** `host.name`, `host.id`, and `os.type` on every signal, and on AWS, GCP, and Azure virtual machines the cloud provider, region, and instance.

### Agent (process or Windows service)

On macOS, the agent is the collector process you start from the release tarball. On Windows, it runs as the `otelcol-contrib` Windows service that the OpenTelemetry Collector MSI installs, or as a process you start from the tarball. Both use the Linux agent's collector config without the journal:

- **Host metrics:** The same metrics as on Linux, via `hostmetrics`, apart from a few that only Linux reports, such as two disk metrics. macOS also reports no per-process disk I/O, and Windows no process counts.
- **OTLP:** Traces, metrics, and logs from instrumented applications, over OTLP/gRPC (4317) and OTLP/HTTP (4318).
- **Resource attributes:** The same as on Linux.
