The [install guide](https://signoz.io/docs/opentelemetry-collection-agents/vm/install/) provides a working config: one agent on each host collects host metrics and data from instrumented applications, and on Linux the warnings and errors in the systemd journal. This page explains how to customize it.

## Prerequisites

- The VM Collection Agent installed as the [install guide](https://signoz.io/docs/opentelemetry-collection-agents/vm/install/) shows
- SigNoz Cloud account or self-hosted SigNoz instance
- A shell on the host (with `sudo` on Linux), or PowerShell on Windows (as Administrator for the MSI)
- On Linux, the `casting.yaml` and `foundryctl` you installed with; on macOS and Windows, the `config.yaml` you created

## Apply Changes

<Tabs entityName="os">
<TabItem value="linux" label="Linux" default>

1. Add the section's snippet to `casting.yaml`. Foundry already generates the default receivers and processors, so add only what you change. If `casting.yaml` already has a `collector/agent/agent.yaml` block, as the install guide's does, add the snippet's lines inside that block.

2. Run this from the directory that contains `casting.yaml` to apply the change:

   ```bash
   sudo foundryctl cast -f casting.yaml
   ```

   Foundry reinstalls the agent's files and restarts it.

3. [View the agent's logs](https://signoz.io/docs/opentelemetry-collection-agents/vm/configure/?os=linux#view-the-collectors-logs) to confirm there are no configuration errors.

4. In SigNoz, confirm the data in **[Infrastructure Monitoring](https://signoz.io/docs/infrastructure-monitoring/overview/)** for host metrics, **[Logs Explorer](https://signoz.io/docs/userguide/logs_query_builder/)** for logs, and **[Trace Explorer](https://signoz.io/docs/userguide/traces/)** for application traces.

</TabItem>
<TabItem value="macos" label="macOS">

1. Add the section's snippet to `config.yaml`, merged into the keys the file already has.

2. From the directory that contains `config.yaml`, stop the agent with this, then run [Step 4 of the install guide](https://signoz.io/docs/opentelemetry-collection-agents/vm/install/?os=macos#step-4-run-the-collector) again:

   ```bash
   kill "$(cat otel-pid)"
   ```

3. [View the agent's logs](https://signoz.io/docs/opentelemetry-collection-agents/vm/configure/?os=macos#view-the-collectors-logs) to confirm there are no configuration errors.

4. In SigNoz, confirm the data in **[Infrastructure Monitoring](https://signoz.io/docs/infrastructure-monitoring/overview/)** for host metrics, **[Logs Explorer](https://signoz.io/docs/userguide/logs_query_builder/)** for logs, and **[Trace Explorer](https://signoz.io/docs/userguide/traces/)** for application traces.

</TabItem>
<TabItem value="windows" label="Windows">

1. Add the section's snippet to `config.yaml`, merged into the keys the file already has. With the MSI, the file is `C:\Program Files\OpenTelemetry Collector\config.yaml`; when you run the agent manually, it is the `config.yaml` next to `otelcol-contrib.exe`.

2. Restart the agent. With the MSI, run this in PowerShell as Administrator:

   ```powershell
   Restart-Service otelcol-contrib
   ```

   When you run it manually, stop the agent with this, then run [Step 4 of the manual install](https://signoz.io/docs/opentelemetry-collection-agents/vm/install/?os=windows&windows-method=manual#step-4-run-the-collector-1) again:

   ```powershell

   ```

3. [View the agent's logs](https://signoz.io/docs/opentelemetry-collection-agents/vm/configure/?os=windows#view-the-collectors-logs) to confirm there are no configuration errors.

4. In SigNoz, confirm the data in **[Infrastructure Monitoring](https://signoz.io/docs/infrastructure-monitoring/overview/)** for host metrics, **[Logs Explorer](https://signoz.io/docs/userguide/logs_query_builder/)** for logs, and **[Trace Explorer](https://signoz.io/docs/userguide/traces/)** for application traces.

## Send Data from Applications to Collector on VM

Host metrics, and on Linux the warnings and errors in the systemd journal, flow as soon as the agent is running.

### Where and how to send data from your application

To send traces, metrics, and logs from an application, instrument it with OpenTelemetry ([language guides](https://signoz.io/docs/instrumentation/)), then point it at the agent. For an application on the same host, set these in its environment, for example in the shell that starts it:

```bash
export OTEL_EXPORTER_OTLP_ENDPOINT=http://localhost:4318
export OTEL_EXPORTER_OTLP_PROTOCOL=http/protobuf
export OTEL_SERVICE_NAME="<service-name>"
```

**Verify these values:**

- `<service-name>`: The name your application shows under in SigNoz.

From another host, use the agent host's address in place of `localhost`, with port `4318` open to it. For OTLP over gRPC, set `OTEL_EXPORTER_OTLP_PROTOCOL=grpc` and port `4317`. On Windows, set the same variables in the application's environment.

Restart the application and send it some traffic. Within a minute it shows under **Services** in SigNoz.

## Collect Host Metrics

<Tabs entityName="os">
<TabItem value="linux" label="Linux" default>

To collect host metrics every 30s, add this to `casting.yaml`:

```yaml
spec:
  collector:
    spec:
      config:
        data:
          collector/agent/agent.yaml: |
            receivers:
              hostmetrics:
                collection_interval: 30s
```

To stop a scraper, set it to `null` under `scrapers`, for example `paging: null`. Then [apply the change](https://signoz.io/docs/opentelemetry-collection-agents/vm/configure/#apply-changes).

</TabItem>
<TabItem value="macos" label="macOS">

To collect host metrics every 30s, add this to `config.yaml`:

```yaml:config.yaml
receivers:
  hostmetrics:
    collection_interval: 30s
```

To stop a scraper, remove it from `scrapers`. Then [apply the change](https://signoz.io/docs/opentelemetry-collection-agents/vm/configure/?os=macos#apply-changes).

</TabItem>
<TabItem value="windows" label="Windows">

To collect host metrics every 30s, add this to `config.yaml`:

To stop a scraper, remove it from `scrapers`. Then [apply the change](https://signoz.io/docs/opentelemetry-collection-agents/vm/configure/?os=windows#apply-changes).

### Exclude filesystem mounts

<Tabs entityName="os">
<TabItem value="linux" label="Linux" default>

To stop reporting the filesystem mounted at `/mnt/backup`, add this to `casting.yaml`:

```yaml defaultCollapsed
spec:
  collector:
    spec:
      config:
        data:
          collector/agent/agent.yaml: |
            receivers:
              hostmetrics:
                scrapers:
                  filesystem:
                    exclude_mount_points:
                      mount_points:
                        - /dev/*
                        - /proc/*
                        - /sys/*
                        - /run/credentials/*
                        - /run/k3s/containerd/*
                        - /var/lib/docker/*
                        - /var/lib/containers/storage/*
                        - /var/lib/kubelet/*
                        - /snap/*
                        - ^/mnt/backup$
```

Lists replace, so restate the agent's default entries, the ones above `^/mnt/backup$`. Then [apply the change](https://signoz.io/docs/opentelemetry-collection-agents/vm/configure/#apply-changes).

</TabItem>
<TabItem value="macos" label="macOS">

To stop reporting the filesystem mounted at `/Volumes/Backup`, add this to `config.yaml`:

```yaml:config.yaml
receivers:
  hostmetrics:
    scrapers:
      filesystem:
        exclude_mount_points:
          match_type: regexp
          mount_points:
            - /dev/*
            - ^/System/Volumes/(Preboot|VM|Update|xarts|iSCPreboot|Hardware)$
            - ^/Volumes/Backup$
```

Then [apply the change](https://signoz.io/docs/opentelemetry-collection-agents/vm/configure/?os=macos#apply-changes).

</TabItem>
<TabItem value="windows" label="Windows">

To stop reporting the `D:` drive, add this to `config.yaml`:

```yaml:config.yaml
receivers:
  hostmetrics:
    scrapers:
      filesystem:
        exclude_mount_points:
          match_type: regexp
          mount_points:
            - ^D:$
```

Then [apply the change](https://signoz.io/docs/opentelemetry-collection-agents/vm/configure/?os=windows#apply-changes).

</TabItem>
</Tabs>

## Collect Host Logs

On Linux, to also collect journal entries at priority info, add this to `casting.yaml`:

```yaml
spec:
  collector:
    spec:
      config:
        data:
          collector/agent/agent.yaml: |
            receivers:
              journald:
                priority: info
```

`priority` merges into the agent's `journald` receiver, so its other settings stay. Then [apply the change](https://signoz.io/docs/opentelemetry-collection-agents/vm/configure/#apply-changes).

To collect the journal of only some systemd units, add this to `casting.yaml`:

```yaml
spec:
  collector:
    spec:
      config:
        data:
          collector/agent/agent.yaml: |
            receivers:
              journald:
                units:
                  - nginx.service
                  - postgresql.service
```

Then [apply the change](https://signoz.io/docs/opentelemetry-collection-agents/vm/configure/#apply-changes).

### Disable Logs Collection

On Linux, to stop collecting the journal, add this to `casting.yaml`:

```yaml
spec:
  collector:
    spec:
      config:
        data:
          collector/agent/agent.yaml: |
            receivers:
              journald: null
            service:
              pipelines:
                logs:
                  receivers: [otlp/http, otlp/grpc]
```

Lists replace, so the `logs` pipeline is restated with the agent's two OTLP receivers. Then [apply the change](https://signoz.io/docs/opentelemetry-collection-agents/vm/configure/#apply-changes).

## Collect Application Log Files

<Tabs entityName="os">
<TabItem value="linux" label="Linux" default>

To collect the log files that an application writes, add this to `casting.yaml`:

```yaml
spec:
  collector:
    spec:
      config:
        data:
          collector/agent/agent.yaml: |
            receivers:
              filelog/app:
                include:
                  - /var/log/myapp/*.log
                include_file_path: true
            service:
              pipelines:
                logs:
                  receivers: [otlp/http, otlp/grpc, journald, filelog/app]
```

Lists replace, so the `logs` pipeline restates the agent's receivers with the new one. Then [apply the change](https://signoz.io/docs/opentelemetry-collection-agents/vm/configure/#apply-changes).

</TabItem>
<TabItem value="macos" label="macOS">

```yaml:config.yaml
receivers:

    include_file_path: true
service:
  pipelines:
    logs:

```

Then [apply the change](https://signoz.io/docs/opentelemetry-collection-agents/vm/configure/?os=macos#apply-changes).

</TabItem>

### Other log sources

To receive [syslog](https://signoz.io/docs/userguide/collecting_syslogs/), or logs forwarded from [Fluent Bit](https://signoz.io/docs/userguide/fluentbit_to_signoz/), [Fluentd](https://signoz.io/docs/userguide/fluentd_to_signoz/), or [Logstash](https://signoz.io/docs/userguide/logstash_to_signoz/), take the receiver from its guide, add it the same way, and list it in the `logs` pipeline. On Linux, the agent can listen only on ports 1024 and above. Then [apply the change](https://signoz.io/docs/opentelemetry-collection-agents/vm/configure/#apply-changes).

## Tune Batch and Memory Limiter

For sizing guidance, see [Collector Configuration Best Practices](https://signoz.io/docs/opentelemetry-collection-agents/opentelemetry-collector/configuration/#best-practices).

<Tabs entityName="os">
<TabItem value="linux" label="Linux" default>

To send larger batches, add this to `casting.yaml`:

```yaml
spec:
  collector:
    spec:
      config:
        data:
          collector/agent/agent.yaml: |
            processors:
              batch:
                send_batch_size: 2000
                send_batch_max_size: 4000
```

### Memory limit

<Tabs entityName="os">
<TabItem value="linux" label="Linux" default>

To cap the agent's memory at 1 GiB, add this patch to `casting.yaml`:

```yaml
spec:
  patches:
    - target: collectionagent/collector/agent/signoz-collector-agent.service
      operations:
        - op: add
          path: /Service/MemoryMax
          value: 1G
```

The agent's `memory_limiter` processor uses a fixed `limit_mib: 4000`, so size it to the cap with percentages, in the same document:

```yaml
spec:
  collector:
    spec:
      config:
        data:
          collector/agent/agent.yaml: |
            processors:
              memory_limiter:
                limit_mib: null
                spike_limit_mib: null
                limit_percentage: 80
                spike_limit_percentage: 25
```

Then [apply the change](https://signoz.io/docs/opentelemetry-collection-agents/vm/configure/#apply-changes).

</TabItem>
<TabItem value="macos" label="macOS">

To size the `memory_limiter` processor by the Mac's memory, replace its settings in `config.yaml` with this:

```yaml:config.yaml
processors:
  memory_limiter:
    check_interval: 5s
    limit_percentage: 80
    spike_limit_percentage: 25
```

Then [apply the change](https://signoz.io/docs/opentelemetry-collection-agents/vm/configure/?os=macos#apply-changes).

</TabItem>
<TabItem value="windows" label="Windows">

To size the `memory_limiter` processor by the host's memory, replace its settings in `config.yaml` with this:


Then [apply the change](https://signoz.io/docs/opentelemetry-collection-agents/vm/configure/?os=windows#apply-changes).

## Common Deployment Scenarios

### Run on the same host as self-hosted SigNoz

<Tabs entityName="os">
<TabItem value="linux" label="Linux" default>

To run the agent on the host that runs self-hosted SigNoz, add this to `casting.yaml`:

```yaml defaultCollapsed
spec:
  collector:
    spec:
      env:
        SIGNOZ_INGESTION_ENDPOINT: http://localhost:4318
      config:
        data:
          collector/agent/agent.yaml: |
            receivers:
              otlp/grpc:
                protocols:
                  grpc:
                    endpoint: 0.0.0.0:14317
              otlp/http:
                protocols:
                  http:
                    endpoint: 0.0.0.0:14318
            extensions:
              health_check:
                endpoint: 0.0.0.0:13134
            service:
              telemetry:
                metrics:
                  readers:
                    - pull:
                        exporter:
                          prometheus:
                            host: localhost
                            port: 8889
```

The agent then receives OTLP on `14317` and `14318`, so applications on the host send to `localhost:14318`. Then [apply the change](https://signoz.io/docs/opentelemetry-collection-agents/vm/configure/#apply-changes).

</TabItem>
<TabItem value="macos" label="macOS">

To run the agent on the Mac that runs self-hosted SigNoz, add this to `config.yaml`, and set `SIGNOZ_INGESTION_ENDPOINT` to `http://localhost:4318` in [Step 4 of the install guide](https://signoz.io/docs/opentelemetry-collection-agents/vm/install/?os=macos#step-4-run-the-collector):

```yaml:config.yaml defaultCollapsed
receivers:
  otlp/grpc:
    protocols:
      grpc:
        endpoint: 0.0.0.0:14317
  otlp/http:
    protocols:
      http:
        endpoint: 0.0.0.0:14318
extensions:
  health_check:
    endpoint: 0.0.0.0:13134
service:
  telemetry:
    metrics:
      readers:
        - pull:
            exporter:
              prometheus:
                host: localhost
                port: 8889
```

The agent then receives OTLP on `14317` and `14318`, so applications on the Mac send to `localhost:14318`. Then [apply the change](https://signoz.io/docs/opentelemetry-collection-agents/vm/configure/?os=macos#apply-changes).

</TabItem>

To run the agent on the host that runs self-hosted SigNoz, add this to `config.yaml`, and set `SIGNOZ_INGESTION_ENDPOINT` to `http://localhost:4318` in the agent's environment ([Step 3 of the MSI install](https://signoz.io/docs/opentelemetry-collection-agents/vm/install/?os=windows#step-3-set-the-environment-and-restart), or [Step 4 of the manual install](https://signoz.io/docs/opentelemetry-collection-agents/vm/install/?os=windows&windows-method=manual#step-4-run-the-collector-1)):

```yaml:config.yaml defaultCollapsed
receivers:
  otlp/grpc:
    protocols:
      grpc:

    protocols:
```

The agent then receives OTLP on `14317` and `14318`, so applications on the host send to `localhost:14318`. Then [apply the change](https://signoz.io/docs/opentelemetry-collection-agents/vm/configure/?os=windows#apply-changes).

## Migrate to Foundry

If you run the agent on Linux as the `otelcol-contrib` package, or as an `otelcol-contrib` process you set up yourself, with your own `config.yaml`, move it to Foundry so that `casting.yaml` holds its whole setup and every change follows [Apply Changes](https://signoz.io/docs/opentelemetry-collection-agents/vm/configure/#apply-changes).

1. To describe the agent in Foundry, [install foundryctl](https://signoz.io/docs/opentelemetry-collection-agents/vm/install/#step-1-install-foundryctl), [download the OpenTelemetry Collector](https://signoz.io/docs/opentelemetry-collection-agents/vm/install/#step-2-download-the-opentelemetry-collector), and [create casting.yaml](https://signoz.io/docs/opentelemetry-collection-agents/vm/install/#step-3-create-castingyaml) as the install guide shows. On a host that runs self-hosted SigNoz, also add the change in [Run on the same host as self-hosted SigNoz](https://signoz.io/docs/opentelemetry-collection-agents/vm/configure/#run-on-the-same-host-as-self-hosted-signoz).

2. To keep your `config.yaml` customizations, add them to `casting.yaml` under `spec.collector.spec.config.data`, keyed `collector/agent/agent.yaml`, and your environment variables under `spec.collector.spec.env`. For example, for host metrics every 30s and a `team` resource attribute:

   ```yaml
   spec:
     collector:
       spec:
         env:
           OTEL_RESOURCE_ATTRIBUTES: deployment.environment=<your-environment>,team=backend
         config:
           data:
             collector/agent/agent.yaml: |
               receivers:
                 hostmetrics:
                   collection_interval: 30s
   ```

   **Verify these values:**

   - `<your-environment>`: Your deployment environment, for example `staging` or `production`.

   Foundry merges them over its own config: maps merge and lists replace, so restate whole lists, with Foundry's names `otlp/http` and `otlp/grpc` for your `otlp` receiver and `otlphttp/signoz` for your `otlphttp` exporter, and keep `journald` in the `logs` pipeline. Your exporter's endpoint and key go in `SIGNOZ_INGESTION_ENDPOINT` and `SIGNOZ_INGESTION_KEY`, as in the install guide.

3. To free the host ports the Foundry agent binds, remove the old collector. For the package on Debian and Ubuntu, run this on the host:

   ```bash
   sudo apt-get remove otelcol-contrib
   ```

   On RHEL and Fedora (`yum` on older releases):

   ```bash
   sudo dnf remove otelcol-contrib
   ```

   For an `otelcol-contrib` process you set up yourself, stop it.

4. To start the agent with Foundry, run this from the directory that contains `casting.yaml`:

   ```bash
   sudo foundryctl cast -f casting.yaml
   ```

   Then verify the Collection Agent as [Step 5 of the install guide](https://signoz.io/docs/opentelemetry-collection-agents/vm/install/#step-5-verify-the-collection-agent) shows.

<TabItem value="linux" label="Linux" default>

```bash
sudo journalctl -u signoz-collector-agent -f
```

</TabItem>

```bash
tail -f otelcol-output.log
```

</TabItem>
<TabItem value="windows" label="Windows">

With the MSI, the service writes its logs to the Application event log under the `otelcol-contrib` source, which Event Viewer shows under **Windows Logs** > **Application**. To list the latest, run this in PowerShell:

```powershell
Get-WinEvent -ProviderName otelcol-contrib -MaxEvents 50 | Select-Object TimeCreated, LevelDisplayName, Message
```

When you run the agent manually, it writes its logs to `otelcol-output.log`, in the folder you started it from. To follow them, run this there:

```powershell
Get-Content otelcol-output.log -Wait -Tail 50
```

</TabItem>

## Troubleshooting
</ToggleHeading>

### Metrics or logs stop after adding a receiver

After a change that adds a receiver to the `metrics` or `logs` pipeline, host metrics or host logs stop arriving in SigNoz.

**Cause:** the pipeline's `receivers` list no longer names `hostmetrics` or, on Linux, `journald`. In `casting.yaml`, a list replaces Foundry's whole list.

**Fix:** list every receiver the pipeline still needs, as [Scrape Prometheus Metrics](https://signoz.io/docs/opentelemetry-collection-agents/vm/configure/#scrape-prometheus-metrics) and [Collect Application Log Files](https://signoz.io/docs/opentelemetry-collection-agents/vm/configure/#collect-application-log-files) show, then apply the change as [Apply Changes](https://signoz.io/docs/opentelemetry-collection-agents/vm/configure/#apply-changes) shows.

After the fix, host metrics and host logs arrive in SigNoz again.

### A custom processor has no effect

After a change that adds a processor, its attribute or transformation is missing from the data in SigNoz.

**Cause:** the processor is defined under `processors` but not listed in a pipeline's `processors`.

**Fix:** list it before `batch` as [Add Custom Processors to Pipelines](https://signoz.io/docs/opentelemetry-collection-agents/vm/configure/#add-custom-processors-to-pipelines) shows, then apply the change as [Apply Changes](https://signoz.io/docs/opentelemetry-collection-agents/vm/configure/#apply-changes) shows.

After the fix, the attribute or transformation appears on the signal in SigNoz Explorer.

### A service's logs do not arrive

On Linux, a service's log lines appear in `journalctl -u` for the service's unit, but not in the SigNoz Logs Explorer.

**Cause:** the agent collects journal entries at priority warning and above, and the service writes its lines at a lower priority. Plain standard output and standard error are stored at priority info.

**Fix:** collect entries at priority info as [Collect Host Logs](https://signoz.io/docs/opentelemetry-collection-agents/vm/configure/#collect-host-logs) shows, then apply the change as [Apply Changes](https://signoz.io/docs/opentelemetry-collection-agents/vm/configure/#apply-changes) shows.

After the fix, new log lines from the service arrive in SigNoz.

</details>
