This page documents every column and chart in the **Infrastructure Monitoring > Kubernetes > Pods** view.

## Columns

| Column | Metric | Description |
|--------|--------|-------------|
| **Pod Name** | `k8s.pod.name` resource attribute | Kubernetes pod name. Set by the `k8sattributes` processor. |
| **CPU Req Usage (%)** | `k8s.pod.cpu_request_utilization` | Percentage of CPU request in use. Values above 100% mean the pod exceeds its request. |
| **CPU Limit Usage (%)** | `k8s.pod.cpu_limit_utilization` | Percentage of CPU limit in use. Approaching 100% = throttling risk. |
| **CPU Usage (cores)** | `k8s.pod.cpu.usage` | Actual CPU consumption in cores. |
| **Memory Req Usage (%)** | `k8s.pod.memory_request_utilization` | Percentage of memory request in use. |
| **Memory Limit Usage (%)** | `k8s.pod.memory_limit_utilization` | Percentage of memory limit in use. Near 100% = OOMKill risk. |
| **Memory Usage** | `k8s.pod.memory.usage` | Total memory consumption in bytes. |

### Column Color-Coding

| Color | Range | Meaning |
|-------|-------|---------|
| **Green** | 0 – 60 % | Normal — within limits |
| **Yellow** | 60 – 80 % | Elevated — significant portion used |
| **Red** | 80 – 100 %+ | Critical — throttling (CPU) or OOMKill (memory) risk |

Request-based columns above 100% are normal (pod exceeds request but stays within limit). Limit-based columns near 100% are a concern.

### Metric Sources for Columns

Pod metrics are collected by the <a href="https://github.com/open-telemetry/opentelemetry-collector-contrib/tree/main/receiver/kubeletstatsreceiver" target="_blank" rel="noopener noreferrer nofollow">kubeletstats receiver</a> (`pod` metric group).

See [Kubernetes Metrics Collection Guide](https://signoz.io/docs/infrastructure-monitoring/k8s-metrics/) for setup.

## Widgets (Pod Detail Page)

Click a pod name to open the detail page. Header shows **Namespace**, **Cluster Name**, and **Node**.

### CPU Usage (Cores)

| Property | Value |
|----------|-------|
| **Metric** | `k8s.pod.cpu.usage` |
| **Unit** | Cores |
| **Breakdown** | Avg, Max, Min |
| **What it indicates** | Actual CPU consumption. Compare against requests/limits for right-sizing. |

**Alerting:** Alert when CPU > **80% of limit** for **5 min** (throttling risk). Alert when CPU < **10% of request** for **1 hr** (over-provisioned).

### CPU Request, Limit Utilization (%)

| Property | Value |
|----------|-------|
| **Metrics** | `k8s.pod.cpu_request_utilization`, `k8s.pod.cpu_limit_utilization` |
| **Unit** | Percentage |
| **What it indicates** | Request util > 100% is normal. Limit util near 100% = CPU throttling. |

**Alerting:** Alert when limit util > **90%** for **5 min**.

### Memory Usage (Bytes)

| Property | Value |
|----------|-------|
| **Metric** | `k8s.pod.memory.usage` |
| **Unit** | Bytes |
| **What it indicates** | Total memory including cache. |

**Alerting:** Alert when > **85% of memory limit** for **5 min** (OOMKill risk).

### Memory Request, Limit Utilization (%)

| Property | Value |
|----------|-------|
| **Metrics** | `k8s.pod.memory_request_utilization`, `k8s.pod.memory_limit_utilization` |
| **Unit** | Percentage |
| **What it indicates** | Unlike CPU, exceeding memory limit causes OOMKill — the pod is terminated. |

**Alerting:** Alert when limit util > **90%** for **2 min** (OOMKill imminent).

### Memory by State

| Property | Value |
|----------|-------|
| **Metrics** | `k8s.pod.memory.rss`, `k8s.pod.memory.working_set`, `k8s.pod.memory.usage` |
| **Breakdown** | RSS, working set, cache |
| **What it indicates** | RSS = non-swappable physical memory. Working set = actively used. Cache = reclaimable. Kubernetes uses working set for OOMKill decisions. |

### Memory Major Page Faults

| Property | Value |
|----------|-------|
| **Metric** | `k8s.pod.memory.major_page_faults` |
| **Unit** | Count/s |
| **What it indicates** | Requires reading from disk instead of memory. Sustained high values = severe performance degradation. |

**Alerting:** Alert when > **10/s** for **5 min**.

### CPU Usage by Container

| Property | Value |
|----------|-------|
| **Metric** | `container.cpu.usage` |
| **Unit** | Cores |
| **Breakdown** | Per container |
| **What it indicates** | Identifies which container (init, sidecar, main app) consumes the most CPU. |

### CPU Request, Limit Utilization by Container

| Property | Value |
|----------|-------|
| **Metrics** | `k8s.container.cpu_request_utilization`, `k8s.container.cpu_limit_utilization` |
| **What it indicates** | Per-container CPU utilization vs requests/limits. |

### Memory Usage by Container

| Property | Value |
|----------|-------|
| **Metric** | `container.memory.usage` |
| **Breakdown** | Per container |

### Memory Request, Limit Utilization by Container

| Property | Value |
|----------|-------|
| **Metrics** | `k8s.container.memory_request_utilization`, `k8s.container.memory_limit_utilization` |

### Network Rate (Bytes/s)

| Property | Value |
|----------|-------|
| **Metric** | `k8s.pod.network.io` |
| **Unit** | Bytes/s |
| **Breakdown** | `transmit`, `receive` |

**Alerting:** Alert based on expected traffic patterns — sudden spikes may indicate a surge or leak.

### Network Errors

| Property | Value |
|----------|-------|
| **Metric** | `k8s.pod.network.errors` |
| **Unit** | Count/s |

**Alerting:** Alert on any sustained non-zero rate for **5 min**.

### File System Usage (Bytes)

| Property | Value |
|----------|-------|
| **Metric** | `k8s.pod.filesystem.usage` |
| **Unit** | Bytes |
| **What it indicates** | Disk consumed by pod containers. Monitor to prevent eviction due to disk pressure. |

**Alerting:** Alert when > **80%** of ephemeral storage limit for **5 min**.
