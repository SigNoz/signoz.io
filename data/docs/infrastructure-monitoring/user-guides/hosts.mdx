This page documents every column and chart in the **Infrastructure Monitoring > Hosts** view. For each item you will find the underlying OpenTelemetry metric, what it indicates, color-coding behavior, and recommended alert thresholds.

## Columns

| Column | Metric | Description |
|--------|--------|-------------|
| **Hostname** | `host.name` resource attribute | System hostname or cloud instance identifier. Set by the `resourcedetection` processor. |
| **Status** | Derived from metric availability | `ACTIVE` when metrics are received within the selected time window, `INACTIVE` otherwise. |
| **CPU Usage** | `system.cpu.time` | Overall CPU utilization percentage, calculated from the rate of `system.cpu.time` across all CPU states. |
| **Memory Usage** | `system.memory.usage` | Physical memory consumption as a percentage of total. |
| **IOWait** | `system.cpu.time` (state = `wait`) | Percentage of CPU time spent waiting for I/O. High IOWait indicates a disk or network bottleneck. |
| **Load Avg** | `system.cpu.load_average.15m` | 15-minute system load average. Values above the CPU core count indicate overload. |

### Column Color-Coding

**CPU Usage** and **Memory Usage** show color-coded progress bars:

| Color | Range | Meaning |
|-------|-------|---------|
| **Green** | 0 – 60 % | Normal utilization |
| **Yellow** | 60 – 80 % | Elevated — worth monitoring |
| **Red** | 80 – 100 % | Critical — may cause degraded performance |

**Status** badge: Green `ACTIVE` / Grey `INACTIVE`.

### Metric Sources for Columns

All host metrics are collected by the <a href="https://github.com/open-telemetry/opentelemetry-collector-contrib/tree/main/receiver/hostmetricsreceiver" target="_blank" rel="noopener noreferrer nofollow">OpenTelemetry hostmetrics receiver</a>. Required scrapers: `cpu`, `memory`, `load`.

See [Host Metrics Collection Guide](https://signoz.io/docs/infrastructure-monitoring/hostmetrics/) for setup.

## Widgets (Host Detail Page)

Click a hostname to open the detail page. The header shows **Status**, **Operating System** (`os.type`), **CPU Usage**, and **Memory Usage** at a glance.

### CPU Usage

| Property | Value |
|----------|-------|
| **Metric** | `system.cpu.time` |
| **Unit** | Percentage (%) |
| **Breakdown** | `idle`, `user`, `system`, `wait`, `softirq`, `steal`, `interrupt` |
| **What it indicates** | CPU time distribution. High `user`/`system` = application/kernel load. High `wait` = I/O bottleneck. High `steal` = hypervisor contention. |

**Alerting:** Alert when total CPU > **85%** for **5 min**. Alert when `steal` > **10%**. Alert when `wait` > **20%**.

### Memory Usage

| Property | Value |
|----------|-------|
| **Metric** | `system.memory.usage` |
| **Unit** | Bytes (displayed as GB) |
| **Breakdown** | `free`, `used`, `cached`, `slab_reclaimable`, `slab_unreclaimable` |
| **What it indicates** | Physical memory allocation. `cached` is available for reuse. Growing `slab_unreclaimable` may indicate a kernel memory leak. |

**Alerting:** Alert when available memory (`free` + `cached` + `slab_reclaimable`) < **10%** of total for **5 min**.

### System Load Average

| Property | Value |
|----------|-------|
| **Metrics** | `system.cpu.load_average.1m`, `.5m`, `.15m` |
| **Unit** | Unitless (process count) |
| **What it indicates** | Average processes waiting for CPU. Compare against CPU core count — above core count = overloaded. |

**Alerting:** Alert when 5-min load > **2x CPU cores** for **10 min**.

### Queue Size

| Property | Value |
|----------|-------|
| **Metric** | `system.disk.pending_operations` |
| **Unit** | Count |
| **What it indicates** | I/O operations waiting in disk queue. Sustained high values = disk saturation. |

**Alerting:** Alert when queue > **32** for **5 min**.

### Network Usage (Bytes)

| Property | Value |
|----------|-------|
| **Metric** | `system.network.io` |
| **Unit** | Bytes/s |
| **Breakdown** | `transmit`, `receive` |
| **What it indicates** | Network throughput. Sustained values near interface capacity = saturation. |

**Alerting:** Alert when throughput > **80%** of NIC capacity for **5 min**.

### Network Usage (Packets/s)

| Property | Value |
|----------|-------|
| **Metric** | `system.network.packets` |
| **Unit** | Packets/s |
| **Breakdown** | `transmit`, `receive` |
| **What it indicates** | Packet rate. High packets with low bytes = many small requests. |

### Network Errors

| Property | Value |
|----------|-------|
| **Metric** | `system.network.errors` |
| **Unit** | Count/s |
| **What it indicates** | Network interface errors. Any sustained non-zero value indicates hardware or config issues. |

**Alerting:** Alert on any sustained non-zero rate for **5 min**.

### Network Drops

| Property | Value |
|----------|-------|
| **Metric** | `system.network.dropped` |
| **Unit** | Count/s |
| **What it indicates** | Dropped packets — typically buffer overflows or firewall rules. |

**Alerting:** Alert when drops > **100/s** for **5 min**.

### Network Connections

| Property | Value |
|----------|-------|
| **Metric** | `system.network.connections` |
| **Unit** | Count |
| **What it indicates** | Active connections by protocol and state. High `TIME_WAIT` = connection churn. |

### System Disk I/O (Bytes)

| Property | Value |
|----------|-------|
| **Metric** | `system.disk.io` |
| **Unit** | Bytes/s |
| **Breakdown** | `read`, `write` |
| **What it indicates** | Disk throughput. Compare with rated throughput to assess saturation. |

### System Disk Operations/s

| Property | Value |
|----------|-------|
| **Metric** | `system.disk.operations` |
| **Unit** | IOPS |
| **Breakdown** | `read`, `write` |
| **What it indicates** | IOPS. Typical SSDs: 10K–100K IOPS. HDDs: 100–200 IOPS. |

**Alerting:** Alert when IOPS > **80%** of disk-rated capacity for **5 min**.

### Disk Operations Time

| Property | Value |
|----------|-------|
| **Metric** | `system.disk.operation_time` |
| **Unit** | Milliseconds |
| **What it indicates** | Average latency per disk operation. High latency = congestion or failing hardware. |

**Alerting:** Alert when avg > **20ms** (SSD) or **100ms** (HDD) for **5 min**.
