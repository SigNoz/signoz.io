Most instrumentation steps are the same for SigNoz Cloud and Self-Hosted SigNoz. The endpoint, authentication, TLS, and network owner differ. This page explains ingestion configuration only; it does not claim feature, pricing, or support parity.

## Quick Differences

- Endpoint
  - Cloud: `https://ingest.<region>.signoz.cloud:443` (single port for OTLP/HTTP and OTLP/gRPC)
  - Self-Hosted SigNoz: `http(s)://<signoz-host>:4318` (HTTP) or `http(s)://<signoz-host>:4317` (gRPC)
- Authentication
  - Cloud: Add header `signoz-ingestion-key: <your-ingestion-key>` (or basic auth)
  - Self-Hosted SigNoz: No ingestion key by default; add auth and TLS at your proxy or ingress if needed
- TLS
  - Cloud: Always TLS on `443`
  - Self-Hosted SigNoz: Plain HTTP by default; enable TLS through your ingress or reverse proxy for production
- Paths (OTLP/HTTP)
  - Both: SDKs and collectors append `/v1/traces`, `/v1/metrics`, or `/v1/logs` when configured with a signal-agnostic endpoint
- CORS
  - Cloud: Enabled on all endpoints
  - Self-Hosted SigNoz: Enable CORS explicitly on the OTLP HTTP receiver if needed

## Cloud to Self-Hosted

Using a guide that only shows SigNoz Cloud steps? Apply the following minimal changes to send data to Self-Hosted SigNoz:

### Language SDKs

```diff
- OTEL_EXPORTER_OTLP_ENDPOINT=https://ingest.<region>.signoz.cloud:443
- OTEL_EXPORTER_OTLP_HEADERS=signoz-ingestion-key=<your-ingestion-key>
+ OTEL_EXPORTER_OTLP_PROTOCOL=http/protobuf
+ OTEL_EXPORTER_OTLP_ENDPOINT=http://<signoz-host>:4318
+ # No ingestion key header needed
```

Notes:

- If you enable TLS through an ingress or reverse proxy, use its `https://` endpoint and configure the client to trust the certificate.
- OTLP/HTTP appends `/v1/traces`, `/v1/metrics`, or `/v1/logs` automatically when you use the signal-agnostic endpoint variable `OTEL_EXPORTER_OTLP_ENDPOINT`.

### OpenTelemetry Collector (gateway/agent)

```diff
 exporters:
-  otlphttp:
-    endpoint: https://ingest.<region>.signoz.cloud:443
-    headers:
-      signoz-ingestion-key: <KEY>
+  otlphttp:
+    endpoint: http://<signoz-host>:4318
```

If Self-Hosted SigNoz exposes OTLP/HTTP through HTTPS, use the `https://` endpoint. Add a `tls` block only when the client must trust a custom CA.

## Self-Hosted to Cloud

Using a guide that only shows Self-Hosted steps? Apply the following minimal changes to send data to SigNoz Cloud:

### Language SDKs

```diff
  OTEL_EXPORTER_OTLP_PROTOCOL=http/protobuf
- OTEL_EXPORTER_OTLP_ENDPOINT=http://<signoz-host>:4318
+ OTEL_EXPORTER_OTLP_ENDPOINT=https://ingest.<region>.signoz.cloud:443
+ OTEL_EXPORTER_OTLP_HEADERS=signoz-ingestion-key=<your-ingestion-key>
```

Notes:

- Keep your current protocol; Cloud supports both OTLP/gRPC and OTLP/HTTP on 443.

### OpenTelemetry Collector (gateway/agent)

```diff
 exporters:
-  otlp:                       # gRPC to self-hosted
-    endpoint: '<signoz-host>:4317'
-    tls:
-      insecure: true
+  otlphttp:
+    endpoint: https://ingest.<region>.signoz.cloud:443
+    headers:
+      signoz-ingestion-key: <your-ingestion-key>
```

Alternative (gRPC): you can also keep `otlp` and set `endpoint: ingest.<region>.signoz.cloud:443` with `headers: { signoz-ingestion-key: <your-ingestion-key> }` and no `tls.insecure`.
