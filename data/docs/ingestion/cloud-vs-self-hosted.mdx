Most ingestion steps are identical for SigNoz Cloud and Self-Hosted SigNoz. The main differences are endpoint, authentication, and TLS. Use this page when a doc only shows one environment and you want to adapt it to the other.

Review the [OpenTelemetry environment variables reference](https://signoz.io/docs/ingestion/opentelemetry-environment-variables/) for endpoint paths, protocols, headers, and signal-specific overrides.

## Quick Differences

- Endpoint
  - Cloud: `https://ingest.<region>.signoz.cloud:443` (single port for OTLP/HTTP and OTLP/gRPC)
  - Self-Host: `http(s)://<signoz-host>:4317` (gRPC) or `http(s)://<signoz-host>:4318` (HTTP)
- Authentication
  - Cloud: Add header `signoz-ingestion-key: <key>` (or basic auth)
  - Self-Host: No <Tooltip text="ingestion key" content="The credential a Collector or SDK uses to send data to a SigNoz Cloud workspace." link="https://signoz.io/docs/glossary/#ingestion-key" />; add auth/TLS at your proxy/ingress if you need it
- TLS
  - Cloud: Always TLS on `443`
  - Self-Host: Plain HTTP by default; enable TLS via ingress/reverse proxy for production
- Paths (OTLP/HTTP)
  - Both: SDKs/collectors append `/v1/{traces|metrics|logs}` automatically
- CORS
  - Cloud: Enabled on all endpoints
  - Self-Host: Enable CORS explicitly on the OTLP HTTP receiver if needed

## Cloud to Self-Hosted

Using a guide that only shows SigNoz Cloud steps? Apply the following minimal changes to send data to Self-Hosted SigNoz:

<Tabs entityName="ingestion-client">
<TabItem value="sdk" label="Language SDKs" default>

### Language SDKs

```diff
- OTEL_EXPORTER_OTLP_ENDPOINT=https://ingest.<region>.signoz.cloud:443
- OTEL_EXPORTER_OTLP_HEADERS=signoz-ingestion-key=<KEY>
+ OTEL_EXPORTER_OTLP_ENDPOINT=http://<signoz-host>:4317   # or :4318 for HTTP
+ OTEL_EXPORTER_OTLP_INSECURE=true                       # set to false when using TLS
+ # No ingestion key header needed
```

Notes:

- If you enable TLS for self-hosted (via ingress/reverse proxy), use `https://<host>:443` and set `OTEL_EXPORTER_OTLP_INSECURE=false` (or omit it) and trust the certificates as needed.
- OTLP/HTTP appends `/v1/{traces|metrics|logs}` automatically when you use the signal-agnostic endpoint variable `OTEL_EXPORTER_OTLP_ENDPOINT`.

</TabItem>
<TabItem value="collector" label="OpenTelemetry Collector">

### OpenTelemetry Collector (gateway/agent)

```diff
 exporters:
-  otlphttp:
-    endpoint: https://ingest.<region>.signoz.cloud:443
-    headers:
-      signoz-ingestion-key: <KEY>
+  otlp:                       # gRPC (use otlphttp on :4318 if you prefer HTTP)
+    endpoint: <signoz-host>:4317
+    tls:
+      insecure: true         # set to false when you enable TLS/HTTPS
```

If you switch to HTTPS on self-hosted, change the endpoint to `https://<host>:443`, remove `tls.insecure: true`, and add a `tls` block only if you need to trust custom CAs.

</TabItem>

### Collection Agent

<Tabs entityName="collection-agent">
<TabItem value="k8s-infra" label="K8s-infra Chart" default>

The SigNoz `k8s-infra` Helm chart sends to SigNoz Cloud through `otelCollectorEndpoint`, `otelInsecure`, and `signozApiKey` in `override-values.yaml`:

```diff
 global:
   clusterName: <CLUSTER_NAME>
   deploymentEnvironment: <DEPLOYMENT_ENVIRONMENT>
-otelCollectorEndpoint: https://ingest.<region>.signoz.cloud:443
-otelInsecure: false
-signozApiKey: <your-ingestion-key>
+otelCollectorEndpoint: http://<signoz-host>:4318
+otelInsecure: true
```

Apply the same change to the values for your platform, then install or upgrade the release with `override-values.yaml`.

**Verify these values:**

- `<signoz-host>`: The host of your Self-Hosted SigNoz OTLP/HTTP endpoint. For SigNoz installed with Foundry in the same Kubernetes cluster, use `signoz-ingester.signoz.svc.cluster.local`. For SigNoz installed with the Helm chart in the same cluster, use `signoz-otel-collector.signoz.svc.cluster.local`. The second `signoz` in each address is the namespace SigNoz runs in. For a SigNoz outside the cluster, see the [self-hosted ingestion guide](https://signoz.io/docs/ingestion/self-hosted/overview/).

If your SigNoz endpoint uses TLS, use its `https://` address, set `otelInsecure: false`, and add the TLS certificate settings the endpoint needs.

</TabItem>
<TabItem value="foundry" label="Foundry">

A Foundry Collection Agent casting sends to SigNoz Cloud through `SIGNOZ_INGESTION_ENDPOINT`, `SIGNOZ_INGESTION_KEY`, and a `config.data` entry that adds the `signoz-ingestion-key` header.

To send to Self-Hosted SigNoz, in every document of `casting.yaml`:

- Set `SIGNOZ_INGESTION_ENDPOINT` to `http://<signoz-host>:4318`.
- Remove `SIGNOZ_INGESTION_KEY`.
- Remove the `config.data` lines that add the `signoz-ingestion-key` header, or the whole entry if that is all it holds.

Then run `foundryctl cast -f casting.yaml` again from the directory that contains it.

**Verify these values:**

- `<signoz-host>`: The host of your Self-Hosted SigNoz OTLP/HTTP endpoint. For SigNoz installed with Foundry in the same Kubernetes cluster, use `signoz-ingester.signoz.svc.cluster.local`. For SigNoz installed with the Helm chart in the same cluster, use `signoz-otel-collector.signoz.svc.cluster.local`. The second `signoz` in each address is the namespace SigNoz runs in. For a SigNoz outside the cluster, see the [self-hosted ingestion guide](https://signoz.io/docs/ingestion/self-hosted/overview/).

## Self-Hosted to Cloud

Using a guide that only shows Self-Hosted steps? Apply the following minimal changes to send data to SigNoz Cloud:

### Language SDKs

```diff
- OTEL_EXPORTER_OTLP_ENDPOINT=http://<signoz-host>:4317   # or :4318 for HTTP
- OTEL_EXPORTER_OTLP_INSECURE=true                       # when not using TLS
+ OTEL_EXPORTER_OTLP_ENDPOINT=https://ingest.<region>.signoz.cloud:443
+ OTEL_EXPORTER_OTLP_HEADERS=signoz-ingestion-key=<KEY>
+ # Keep your protocol (grpc or http/protobuf); both work on 443
+ # Remove OTEL_EXPORTER_OTLP_INSECURE if previously set
```

Notes:

- Keep your current protocol; Cloud supports both OTLP/gRPC and OTLP/HTTP on 443.

### OpenTelemetry Collector (gateway/agent)

```diff
 exporters:
-  otlp:                       # gRPC to self-hosted
-    endpoint: '<signoz-host>:4317'
-    tls:
-      insecure: true
+  otlphttp:
+    endpoint: https://ingest.<region>.signoz.cloud:443
+    headers:
+      signoz-ingestion-key: <KEY>
```

Alternative (gRPC): you can also keep `otlp` and set `endpoint: ingest.<region>.signoz.cloud:443` with `headers: { signoz-ingestion-key: <KEY> }` and no `tls.insecure`.
