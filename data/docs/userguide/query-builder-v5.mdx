## Overview

The Query Builder is SigNoz's structured query interface for logs, traces, and metrics. It combines expression-based querying with intelligent auto-completion so you can filter, aggregate, and visualize telemetry data without writing raw SQL or PromQL.

Key capabilities:
- **Filter** data using logical expressions with auto-completed attribute names, values, and [operators](https://signoz.io/docs/userguide/operators-reference/)
- **Aggregate** results with functions like count, sum, avg, percentiles, and rate variants
- **Group by** any attribute to segment results by service, endpoint, region, or custom dimensions
- **Manipulate results** with ordering, limits, and having clauses to surface the most relevant data


## Quick Start

### Your First Query

Let's start with a practical example. Suppose you want to find all error spans from your recommendationservice service in the last 6 hours:

1. **Navigate** to Traces → Explorer
2. **Write filter expression**: `service.name = 'recommendationservice' AND has_error = true`
3. **Set time range**: Last 6 hours
4. **Run query** to see results instantly

## Filtering (Logs & Traces)

The Query Builder allows you to apply filtering based on various attributes of logs or traces.

### Using the Filtering Feature

- **Access**: Navigate to the Query Builder.
- **Open Filter Options**: Click on the Search Filter field to open a dropdown list of available attributes.
- **Select Attributes**: Choose the attribute you want to filter by (e.g., `service.name`, `level`, `status`). Start typing to filter the list.
- **Apply Operators**: Choose the operator (e.g., `=`, `!=`, `IN`, `NOT_IN`) for the selected attribute. See the [Operators Reference](https://signoz.io/docs/userguide/operators-reference/) for the full list of supported operators.
- **Input Values**: Input the value(s) you want to filter by.
- **Combine Filters**: You can add multiple filters by repeating the above steps. Multiple filters are combined with `AND`.
- **View Results**: Click the Stage & Run Query button to display the logs or traces that match the applied filters.

### Example

Suppose you want to filter logs from a specific service with a particular severity level. You can achieve this using the following filters:
- selecting the service name: `service.name = demo-app`
- selecting the severity text: `severity_text = DEBUG`

## Metrics Query Builder

The Metrics Query Builder supports all the features described above — filtering, aggregation, ordering, and multiple queries — along with additional controls for temporal and spatial aggregation that are specific to metric data. For a deeper understanding of how these aggregation layers work, see [Metric Types and Aggregation](https://signoz.io/docs/metrics-management/types-and-aggregation/).

### Spatial and Temporal Aggregations

Metrics in SigNoz go through two aggregation layers before being displayed.

#### Temporal Aggregation

Temporal aggregation consolidates data points within each time series over the selected time interval. It reduces many raw data points into one value per interval, making long time ranges practical to visualize.

Available temporal aggregation functions: `Latest`, `Sum`, `Avg`, `Min`, `Max`, `Count`, `Count Distinct`.

#### Spatial Aggregation

Spatial aggregation merges multiple time series into fewer series by combining values across dimensions such as container name, service name, or region.

Available spatial aggregation functions: `Sum`, `Avg`, `Min`, `Max`.

#### Example

If you select a counter metric called `signoz_calls_total`, you can apply temporal aggregations like `Rate` and `Increase` on it. Similarly, you can apply spatial aggregations across many dimensions, such as `service_name`, `operation`, `deployment_environment`, etc.
