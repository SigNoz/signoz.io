A trace is a recording of the path a request takes through your system — from the first service it hits to every downstream call it makes. Each trace is made up of spans, where each span represents a single unit of work in one service.

The Trace Explorer is the central interface for searching, filtering, and analyzing traces in SigNoz. It offers four views — **List View**, **Trace View**, **Time Series**, and **Table** — each suited to different analysis tasks. See the [Trace Explorer reference](https://signoz.io/docs/product-features/trace-explorer/) for a full walkthrough of every view and feature.

## How the Trace Explorer is organized

The Trace Explorer surfaces spans from your instrumented services. Two filtering mechanisms are available:

- **Quick Filters** — the panel on the left lets you narrow spans by duration, status, service name, HTTP method, and more. See the [quick filters reference](https://signoz.io/docs/product-features/trace-explorer/#quick-filters) for all available options.

- **Query Builder** — the search bar at the top accepts attribute-based filters (key, operator, value). You can combine multiple conditions and run ad-hoc queries. See the [Query Builder docs](https://signoz.io/docs/userguide/query-builder/#using-the-filtering-feature) for more details.

## Aggregate metrics from traces

In Time Series and Table views, SigNoz can aggregate filtered trace data using functions like `count`, `avg`, `p99`, and more. This lets you chart request rates or latency percentiles directly from trace data without needing a separate metrics pipeline. See the [query builder aggregation docs](https://signoz.io/docs/userguide/query-builder/#aggregation) for details.
