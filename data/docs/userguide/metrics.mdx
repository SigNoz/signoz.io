## What is the Services view?

The **Services** view in SigNoz shows every instrumented application sending data to your account — web servers, message brokers, mobile clients, cron jobs, and more. For each service it surfaces RED metrics (Rate, Errors, Duration) derived from trace data, so you can spot performance bottlenecks or failures across your entire fleet at a glance.

<UseHotRod />

## What you can do with Services

- See P99 latency, error rate, and requests per second for every service in one table
- Sort and filter services by any RED metric or resource attribute
- Drill into a service to see application metrics, database call performance, and external dependency health
- Adjust the global time window to compare any historical period

## How it works

### RED metrics

<MetricsDefinition />

Each service row shows the following metrics, all computed from trace data:

| Metric | Description |
|---|---|
| **P99 Latency** | Time taken by the fastest 99% of requests. If P99 = 760 ms, then 99% of requests complete in ≤ 760 ms. |
| **Error Rate** | Percentage of failing requests: error spans ÷ total spans × 100. |
| **Requests per Second** | Number of entry-point spans (operations) processed per second. |
| **Key Operations** | Top APIs and operations served by the service, sortable by latency or error rate. |
| **Apdex** | User satisfaction score from 0 (least satisfied) to 1 (most satisfied). Threshold defaults to 0.5 — configurable in **Settings**. |

### How services and metrics are determined

SigNoz relies on OpenTelemetry semantic conventions. Every unique `service.name` attribute received becomes a row in the Services table.

In a distributed trace, each service has an **entry-point span** — the sub-root span representing work entering that service from an upstream caller. RED metrics are computed from these entry-point spans:

- **Operations/s** — number of entry-point spans seen per second
- **PXX latencies** — quantile of entry-point span duration
- **Error rate** — entry-point spans with `STATUS_CODE_ERROR` ÷ total entry-point spans

### Filtering by resource attribute

Add attributes such as `service.namespace` or `deployment.environment` to your application using the `OTEL_RESOURCE_ATTRIBUTES` flag:

```bash
OTEL_RESOURCE_ATTRIBUTES="service.name=flaskApp,service.namespace=sampleapps,deployment.environment=play" \
OTEL_EXPORTER_OTLP_ENDPOINT="http://3.11.144.34:4317" \
OTEL_EXPORTER_OTLP_PROTOCOL=grpc opentelemetry-instrument python3 app.py
```

<figure data-zoomable align='center'>
    <img src="/img/docs/resource-attribute-filtering.webp" alt="SigNoz UI showing how to filter your application using attributes"/>
    <figcaption><i>Filter services by resource attributes</i></figcaption>
</figure>

By default you can filter on `service.namespace` and `deployment.environment`. To add a custom dimension, update the `dimension` fields in [config.yaml](https://github.com/SigNoz/signoz/blob/main/deploy/docker/otel-collector-config.yaml#L107) and redeploy.

### Service detail view

Click any service row to open the application details page. It has three sections:

**Application Metrics**

| Graph | What it shows |
|---|---|
| Application Latency | P99, P95, and P50 latencies for the selected period |
| Operations per Second | Request throughput |
| Error Percentage | Percentage of errors over total requests |
| Key Operations | Slowest operations, sortable by latency, error rate, or call count |
| Apdex | User satisfaction score; threshold configurable in Settings |

<figure data-zoomable align='center'>
    <img src="/img/docs/application-details-page.webp" alt="SigNoz UI showing the three panes on Applications details"/>
    <figcaption><i>Application detail view — Application Metrics, Database Calls, External Calls</i></figcaption>
</figure>

**Database Calls**

Shows calls per second and average duration for database operations. Requires spans with:
- `span.kind != 2` (not a SERVER span)
- `db.system` span attribute present

If DB call panels appear empty, verify your instrumentation libraries emit these attributes. See [SpanKind reference](https://github.com/open-telemetry/opentelemetry-specification/blob/main/specification/trace/api.md#spankind).

**External Calls**

Tracks calls to external services your application depends on. Requires CLIENT spans (`span.kind = 3`) with at least one of:
- `rpc.system` + `rpc.service` / `rpc.method`
- `http.host` / `http.url` / `url.full`
- `net.peer.name` / `net.peer.ip` + `net.peer.port`
- `peer.service`

### Magnified graph view

Hover over any metric name, open the dropdown, and select **View** to expand that graph. Inside the expanded view, use **Filter Series** to show only specific labels — for example, search `p9` in the latency graph to isolate `p90` and `p99`. Click **Save** to persist the filter.
