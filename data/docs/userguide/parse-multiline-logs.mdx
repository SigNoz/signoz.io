## Overview

By default, the filelog receiver treats each newline as the end of a log record. Stack traces, exception logs, and other multiline output get split into dozens of individual records, making them hard to read and correlate.

This guide covers two approaches to fix that:
1. **Receiver-level** — configure `multiline` in the filelog receiver (simplest)
2. **Processor-level** — use the `recombine` operator in logstransform (more flexible)

:::info Prerequisites
- You are collecting logs with the [filelog receiver](https://github.com/open-telemetry/opentelemetry-collector-contrib/blob/main/receiver/filelogreceiver/README.md).
- You have access to your OpenTelemetry Collector `config.yaml`.
:::

## The problem

Consider this Python traceback spread across multiple lines:

```
2024-20-06 18:58:05,898 ERROR:Exception on main handler
Traceback (most recent call last):
  File "python-logger.py", line 9, in make_log
    return area[10]
IndexError: string index out of range
2024-20-06 18:58:05,898 DEBUG:Query Started
```

Without multiline handling, the collector creates one log record per line:

## Approach 1: Receiver-level multiline (recommended)

Configure the `multiline` option directly on the filelog receiver. This is the simplest approach — the receiver combines lines before passing them to processors.

### Step 1: Identify the boundary pattern

Determine what marks the start (or end) of each log entry. In the Python example, each new log starts with a date in `YYYY-DD-MM` format.

```
line_start_pattern: ^\d{4}-\d{2}-\d{2}
```

### Step 2: Add the multiline configuration

```yaml
receivers:
  filelog:
    include:
      - /var/log/example/app.log
    multiline:
      line_start_pattern: ^\d{4}-\d{2}-\d{2}
```

Use `line_end_pattern` instead if it's easier to match the end of an entry.

### Step 3: Restart the collector

After restarting, each multiline entry appears as a single log record:

## Approach 2: Processor-level recombine

Use the [recombine operator](https://github.com/open-telemetry/opentelemetry-collector-contrib/blob/main/pkg/stanza/docs/operators/recombine.md) in `logstransform` when you cannot change the receiver configuration, or when you need more control over how lines are combined.

### Step 1: Add the recombine processor

```yaml
processors:
  logstransform/multiline:
    operators:
      - type: recombine
        combine_field: body
        is_first_entry: body matches "^\\d{4}-\\d{2}-\\d{2}"
        source_identifier: attributes["log.file.path"]
```

- `combine_field: body` — join lines into the `body` field
- `is_first_entry` — regex that identifies the first line of each entry
- `source_identifier` — groups lines from the same source file

### Step 2: Add the processor to your pipeline

```yaml
service:
  pipelines:
    logs:
      receivers: [filelog]
      processors: [logstransform/multiline, batch]
      exporters: [otlp]
```

### Step 3: Restart the collector

The recombine operator joins matching lines into a single log record, identical in appearance to the receiver-level approach.
