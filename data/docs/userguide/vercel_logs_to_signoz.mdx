If you are running your applications on <a href="https://vercel.com/" target="_blank" rel="noopener noreferrer nofollow">Vercel</a>, you can stream logs from Vercel to SigNoz using <a href="https://vercel.com/docs/drains" target="_blank" rel="noopener noreferrer nofollow">log drains</a>.

## Prerequisites

- A <a href="https://vercel.com/docs/plans" target="_blank" rel="noopener noreferrer nofollow">Vercel Pro or Enterprise</a> account
- An instance of [SigNoz Cloud](https://signoz.io/teams/)

## Configure Vercel Log Drains

Follow the steps below to send your logs from Vercel to SigNoz Cloud:

### Step 1: Create a New Log Drain

1. Navigate to **Team Settings** > **Drains** and click **Add Drain**. This opens a dialog to configure your new log drain.
2. Select the type of observability data you want to drain. In this case, choose **Logs**. The configuration options for Log drains will appear.
3. Provide a name for your drain, select which projects should send data to your endpoint, and configure the log source, environment, and sampling rate.
4. After configuring these settings, click the **Next** button to proceed. The destination configuration panel will appear.

<Figure
  src="/img/logs/vercel/sources.webp"
  caption="Vercel Drain Sources, and Environment"
  alt="Vercel Drain Sources, and Environment"
/>

### Step 2: Configure Destination

Choose how you want to receive your drain data. Under the **Custom Endpoint** tab, set the delivery format to `JSON`. Vercel will now be configured to send JSON payloads to your endpoint.

1. Enter the SigNoz logs ingestion **endpoint**:

```
https://ingest.<region>.signoz.cloud:443/logs/json
```

Replace `<region>` with your [SigNoz Cloud region](https://signoz.io/docs/ingestion/signoz-cloud/overview/#endpoint).

2. Add Custom Headers

Enable **Custom Headers** and add the following header:

```
signoz-ingestion-key: <your-ingestion-key>
```

Replace `<your-ingestion-key>` with the [ingestion key](https://signoz.io/docs/ingestion/signoz-cloud/keys/) from your SigNoz Cloud account. You can find your ingestion key under **Settings > Ingestion Settings** in SigNoz.

<Figure
  src="/img/logs/vercel/headers.webp"
  caption="Vercel Custom Headers"
  alt="Vercel Custom Headers"
/>

### Step 3: Test and Create the Drain

Click on **Test** to ensure your endpoint receives the data correctly. If successful, you will start to see sample logs on the SigNoz UI. After verifying the test results, click **Create Drain** in your Vercel dashboard.

Your Vercel logs will now be streamed to SigNoz Cloud.

  It might take some time for the logs to appear.
</Admonition>

## Validate

After creating the drain, verify that logs are flowing into SigNoz:

1. Open **Logs Explorer** in your SigNoz Cloud dashboard.
2. Wait a few minutes for logs to arrive — there may be a short delay.
3. Look for log entries with Vercel-specific attributes such as `source`, `projectName`, and `deploymentId`.
4. If you see log entries from your Vercel projects, the integration is working correctly.

## Troubleshooting
</ToggleHeading>


### No logs appearing in SigNoz

- **Incorrect region**: Verify that `<region>` in the endpoint URL matches your [SigNoz Cloud region](https://signoz.io/docs/ingestion/signoz-cloud/overview/#endpoint).
- **Invalid ingestion key**: Confirm the `signoz-ingestion-key` header value matches the key shown in your [SigNoz Cloud settings](https://signoz.io/docs/ingestion/signoz-cloud/keys/).
- **Drain not active**: Check the drain status in **Team Settings > Drains** in Vercel. If it shows an error, click the drain to see details.
- **Verification**: After applying fixes, click **Test** in your Vercel drain config and check the SigNoz Logs Explorer again.

### Drain creation or test fails

- **Endpoint URL format**: Ensure the URL is exactly `https://ingest.<region>.signoz.cloud:443/logs/json` with no trailing slash or extra path segments.
- **Missing headers**: Confirm the `signoz-ingestion-key` custom header is set and the value does not contain leading/trailing whitespace.
- **Verification**: Once corrected, the **Test** button in Vercel should return a successful response.
