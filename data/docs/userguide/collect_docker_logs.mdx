## Overview

Docker writes container output to JSON log files on the host and daemon events to `journald` or syslog. This guide covers collecting both with an OpenTelemetry Collector.

## Prerequisites

- Docker Engine 20.10+ installed and running
- Administrative access to the Docker host
- OpenTelemetry Collector installed and sending logs to SigNoz

If you haven't installed the Collector yet, follow the [Docker collection agent guide](https://signoz.io/docs/opentelemetry-collection-agents/docker/install/).

## Setup

<Tabs>
<TabItem value="container-logs" label="Container Logs" default>

### Step 1. Update Collector configuration

Append the <a href="https://github.com/open-telemetry/opentelemetry-collector-contrib/blob/main/receiver/filelogreceiver/README.md" target="_blank" rel="noopener noreferrer nofollow">filelog receiver</a> to your existing `config.yaml`:

```yaml:config.yaml
receivers:
  filelog:
    include: [/var/lib/docker/containers/*/*-json.log]
    poll_interval: 200ms
    start_at: end
    include_file_name: false
    include_file_path: false
    operators:
      - id: container-parser
        type: container
        format: docker
        add_metadata_from_filepath: false
      - id: extract-service-name
        type: regex_parser
        parse_from: body
        regex: 'service.name":\s*"(?P<svc>[^"]+)"'
      - id: set-service-name
        type: move
        from: attributes.svc
        to: resource["service.name"]
        if: 'attributes.svc != nil'

service:
  pipelines:
    logs:
      receivers: [otlp, filelog]
      processors: [batch]
      exporters: [otlp]
```

The <a href="https://github.com/open-telemetry/opentelemetry-collector-contrib/blob/main/pkg/stanza/docs/operators/container.md" target="_blank" rel="noopener noreferrer nofollow">container operator</a> parses Docker's JSON log format. The `extract-service-name` and `set-service-name` operators pull `service.name` out of structured JSON log bodies and promote it to the resource level. If the field is absent, those operators are skipped.

<Admonition type="note">
  `format: docker` is set explicitly here because these files come from Docker's JSON log driver. The <a href="https://github.com/open-telemetry/opentelemetry-collector-contrib/blob/main/pkg/stanza/docs/operators/container.md" target="_blank" rel="noopener noreferrer nofollow">container operator</a> also supports `cri-o` and `containerd` formats if you need them later.
</Admonition>

<KeyPointCallout title="Collecting from Kubernetes pod log paths?" defaultCollapsed="true">
  If your logs are at `/var/log/pods/...` or `/var/log/containers/...` rather than Docker host paths, set both `include_file_path: true` and `add_metadata_from_filepath: true` in the container parser operator. The <a href="https://github.com/open-telemetry/opentelemetry-collector-contrib/blob/main/pkg/stanza/docs/operators/container.md" target="_blank" rel="noopener noreferrer nofollow">container operator</a> requires `log.file.path` to be present before it can extract Kubernetes metadata from the file path.
</KeyPointCallout>

### Step 2. Restart the Collector with Docker log access

If you run the Collector in Docker, give it read access to the container log directory:

```bash
docker stop opentelemetry-collector
docker rm opentelemetry-collector

docker run --name opentelemetry-collector \
  --restart unless-stopped \
  --detach \
  --user 0:0 \
  --pid host \
  --network host \
  -v /var/lib/docker/containers:/var/lib/docker/containers:ro \
  -v /var/run/docker.sock:/var/run/docker.sock:ro \
  -v /proc:/hostfs/proc:ro \
  -v /sys:/hostfs/sys:ro \
  -v /:/hostfs:ro \
  -v "$(pwd)/config.yaml":/etc/otelcol-contrib/config.yaml \
  -e HOST_PROC=/hostfs/proc \
  -e HOST_SYS=/hostfs/sys \
  -e HOST_ROOT=/hostfs \
  otel/opentelemetry-collector-contrib:0.130.1
```

Docker daemon logs are separate from container stdout/stderr. On Linux, they land in `journald` or syslog depending on your distribution.

Run this on the Docker host to check which applies:

```bash
sudo journalctl -u docker.service -n 20
```

If you see output like this, your daemon uses journald:

```
-- Journal begins at Mon 2025-01-13 08:00:01 UTC. --
Apr 23 12:01:05 myhost dockerd[1234]: time="2025-04-23T12:01:05Z" level=info msg="Container started" container=abc123
Apr 23 12:01:06 myhost dockerd[1234]: time="2025-04-23T12:01:06Z" level=info msg="attach stdout" container=abc123
```

If the command returns no output or an error, your daemon uses syslog instead. Use the matching tab below.

### Step 1. Add the journald receiver

Append the <a href="https://github.com/open-telemetry/opentelemetry-collector-contrib/blob/main/receiver/journaldreceiver/README.md" target="_blank" rel="noopener noreferrer nofollow">journald receiver</a> to your existing `config.yaml`:

```yaml:config.yaml
receivers:
  journald/docker-daemon:
    root_path: /hostfs
    journalctl_path: /usr/bin/journalctl
    start_at: end
    units:
      - docker.service

service:
  pipelines:
    logs:
      receivers: [otlp, journald/docker-daemon]
      processors: [batch]
      exporters: [otlp]
```

`root_path` tells the receiver to chroot into `/hostfs` (the mounted host filesystem) before running journalctl. `journalctl_path` is the path to the binary inside that chroot. This works with the standard OTel collector contrib image — no custom image needed.

<Admonition type="note">
  The journal directory defaults to `/run/log/journal` relative to `root_path`. On systems with persistent journal storage, add `directory: /var/log/journal` to the receiver config.
</Admonition>

### Step 2. Restart the Collector with journal access

The receiver needs two Linux capabilities to read the host journal. Stop the existing Collector and restart it with the capabilities added:

```bash
docker stop opentelemetry-collector
docker rm opentelemetry-collector

docker run --name opentelemetry-collector \
  --restart unless-stopped \
  --detach \
  --user 0:0 \
  --pid host \
  --network host \
  -v /var/lib/docker/containers:/var/lib/docker/containers:ro \
  -v /var/run/docker.sock:/var/run/docker.sock:ro \
  -v /proc:/hostfs/proc:ro \
  -v /sys:/hostfs/sys:ro \
  -v /:/hostfs:ro \
  -v "$(pwd)/config.yaml":/etc/otelcol-contrib/config.yaml \
  --cap-add CAP_DAC_READ_SEARCH \
  --cap-add CAP_SYS_PTRACE \
  -e HOST_PROC=/hostfs/proc \
  -e HOST_SYS=/hostfs/sys \
  -e HOST_ROOT=/hostfs \
  otel/opentelemetry-collector-contrib:0.130.1
```

## Validate

Open **Logs Explorer** in SigNoz and search for `_SYSTEMD_UNIT = docker.service` or filter the message body for `dockerd`. You should see Docker daemon startup messages, warnings, and runtime errors.

For advanced configuration, see [Collecting systemd logs (journald)](https://signoz.io/docs/logs-management/send-logs/collect-systemd-logs/) and the <a href="https://github.com/open-telemetry/opentelemetry-collector-contrib/blob/main/receiver/journaldreceiver/README.md" target="_blank" rel="noopener noreferrer nofollow">journald receiver documentation</a>.

### Step 1. Add the filelog receiver for syslog files

Append the <a href="https://github.com/open-telemetry/opentelemetry-collector-contrib/blob/main/receiver/filelogreceiver/README.md" target="_blank" rel="noopener noreferrer nofollow">filelog receiver</a> to your existing `config.yaml` to tail the syslog file directly:

```yaml:config.yaml
receivers:
  filelog/docker-daemon-syslog:
    include:
      - /var/log/syslog
      - /var/log/messages
    start_at: end
    include_file_name: false

service:
  pipelines:
    logs:
      receivers: [otlp, filelog/docker-daemon-syslog]
      processors: [batch]
      exporters: [otlp]
```

<Admonition type="note">
  Both paths are listed so the config works across distributions. The receiver skips paths that don't exist on the host.
</Admonition>

<Admonition type="warning">
  This config sends every line in syslog to SigNoz, including entries from unrelated processes. On a busy host, this increases ingestion costs. Add a filter operator to keep only Docker lines:

  ```yaml
  operators:
    - type: filter
      expr: 'not (body matches "dockerd")'
  ```
</Admonition>

### Step 2. Restart the Collector with syslog access

Stop the existing Collector and restart it with `/var/log` mounted read-only:

```bash
docker stop opentelemetry-collector
docker rm opentelemetry-collector

docker run --name opentelemetry-collector \
  --restart unless-stopped \
  --detach \
  --user 0:0 \
  --pid host \
  --network host \
  -v /var/lib/docker/containers:/var/lib/docker/containers:ro \
  -v /var/run/docker.sock:/var/run/docker.sock:ro \
  -v /var/log:/var/log:ro \
  -v /proc:/hostfs/proc:ro \
  -v /sys:/hostfs/sys:ro \
  -v /:/hostfs:ro \
  -v "$(pwd)/config.yaml":/etc/otelcol-contrib/config.yaml \
  -e HOST_PROC=/hostfs/proc \
  -e HOST_SYS=/hostfs/sys \
  -e HOST_ROOT=/hostfs \
  otel/opentelemetry-collector-contrib:0.130.1
```

## Validate

Open **Logs Explorer** in SigNoz and filter the message body for `dockerd`. You should see Docker daemon events mixed in with other syslog entries.

For forwarding syslog over the network instead of tailing files directly, see [Collecting Syslogs via OpenTelemetry Collector](https://signoz.io/docs/userguide/collecting_syslogs/).

## Next Steps

- **Parse log fields**: `dockerd` writes structured log format (`level=info msg="..."`). Use the [Logs Pipeline](https://signoz.io/docs/logs-pipelines/introduction/) to extract fields like `level`, `msg`, and `container` into attributes for filtering and alerting.
- **Set up alerts**: Create [log-based alerts](https://signoz.io/docs/alerts-management/log-based-alerts/) to catch errors from `dockerd`.
- **Explore dashboards**: View container metrics alongside these logs with the [Docker metrics dashboard](https://signoz.io/docs/dashboards/dashboard-templates/docker-container-metrics/).

## Troubleshooting

</ToggleHeading>

### No container logs appearing

1. Check that Docker container log files exist and are readable:

  ```bash
  ls -la /var/lib/docker/containers/
  ```

2. Verify the Collector container can read the mounted log directory:

  ```bash
  docker run --rm \
    -v /var/lib/docker/containers:/var/lib/docker/containers:ro \
    alpine ls /var/lib/docker/containers/
  ```

3. Check the Collector logs for errors:

  ```bash
  docker logs opentelemetry-collector | grep -i error
  ```

### No Docker daemon logs appearing

1. Confirm where Docker stores daemon logs on your host:

  ```bash
  sudo journalctl -u docker.service -n 20
  sudo tail -n 20 /var/log/syslog
  sudo tail -n 20 /var/log/messages
  ```

2. For the `journald` receiver: verify the Collector can access `journalctl` and the journal directory. See [Collecting systemd logs (journald)](https://signoz.io/docs/logs-management/send-logs/collect-systemd-logs/) for container requirements.

3. For the syslog path: check your syslog forwarder configuration in [Collecting Syslogs via OpenTelemetry Collector](https://signoz.io/docs/userguide/collecting_syslogs/).
