The **SigNoz GCP Integration** brings metrics and logs from your Google Cloud services into SigNoz. Each supported service comes with a ready-made dashboard.

You can connect GCP in two ways:

- **One-Click Integration (recommended):** you run a few setup commands that SigNoz gives you. SigNoz then sets up and manages the rest, for both metrics and logs.
- **Manual Setup:** you create and run the GCP resources yourself. You get full control, but it collects metrics only.

<Admonition type="info">
The GCP integration is available on **SigNoz Cloud** and **SigNoz Enterprise (Self-Hosted)**. Logs are collected with **One-Click Integration** only. Traces are **not** part of this integration. Send traces by [instrumenting your applications](https://signoz.io/docs/instrumentation/) directly.
</Admonition>

## How it works

GCP does not send your data to outside tools on its own. So SigNoz uses an **OpenTelemetry Collector**, a small program that runs **inside your GCP project**, to gather the data and send it to SigNoz over OTLP.

- **Metrics** live in **Cloud Monitoring**. Every few minutes, the Collector reads them with the <a href="https://github.com/open-telemetry/opentelemetry-collector-contrib/tree/main/receiver/googlecloudmonitoringreceiver" target="_blank" rel="noopener noreferrer nofollow">`googlecloudmonitoring`</a> receiver.
- **Logs** live in **Cloud Logging**. A **log sink** (a rule that picks which logs to forward) sends matching logs to a **Pub/Sub topic** (a message queue). Pub/Sub then pushes them to the Collector. This part is set up by One-Click Integration only.

The integration runs the Collector inside your GCP project. There, it signs in to Google Cloud with a service account in your project, so you never share GCP credentials with SigNoz. It also keeps your data inside GCP until it leaves for SigNoz.

<Admonition type="info">
With Manual Setup, the Collector doesn't have to run on Cloud Run or even inside GCP. The `googlecloudmonitoring` receiver works anywhere it can find Google Cloud credentials through <a href="https://cloud.google.com/docs/authentication/application-default-credentials" target="_blank" rel="noopener noreferrer nofollow">Application Default Credentials</a>, such as a Compute Engine VM, GKE, or an existing Kubernetes cluster. One-Click Integration always deploys it on Cloud Run in your project.
</Admonition>

The two setup methods differ in who runs and updates the Collector:

- **One-Click Integration:** SigNoz also deploys a **SigNoz agent** next to the Collector. The agent checks in with SigNoz every 30 seconds. When you turn a service on or off in SigNoz, the agent updates the Collector and the log sink for you.
- **Manual Setup:** you deploy the Collector yourself, and you edit its config each time you add a service.

## Choose a setup method

Start with **One-Click Integration** unless you need one of the things only Manual Setup offers, such as watching many projects from one Collector.

|  | One-Click Integration | Manual Setup |
| --- | --- | --- |
| **Who sets up the Collector** | SigNoz, through setup commands you run | You |
| **Adding a service** | Turn on a toggle in SigNoz | Turn on a toggle in SigNoz, then add the service's metrics to your Collector config |
| **Data collected** | Metrics and logs | Metrics only |
| **Projects per connected account** | One (the project the agent runs in) | One or more |
| **Where the Collector runs** | Cloud Run, set up for you | Cloud Run or any compute you choose |
| **Best for** | Getting started fast and hands-off upkeep | Many projects from one Collector, or custom setups |

## Costs to expect

Both methods run resources in your GCP project, so GCP bills you for them, not SigNoz. Plan for:

- **Cloud Run, Collector (both methods):** roughly **~$110/month** for a Collector sized at 2 vCPU and 4 GiB running all the time. One-Click Integration starts the Collector at this size. With Manual Setup you pick the size, so for low volumes you can choose something smaller (for example, 1 vCPU and 1 to 2 GiB). See <a href="https://cloud.google.com/run#pricing" target="_blank" rel="noopener noreferrer nofollow">Cloud Run pricing</a>.
- **Cloud Run, SigNoz agent (One-Click only):** roughly **~$50/month** for the agent, which runs all the time at 1 vCPU and 512 MiB.
- **Pub/Sub, logs (One-Click only):** roughly **$80 per TiB** of logs. Pub/Sub charges $40 per TiB each time data passes through it, and every log passes through twice: once on the way in and once on the way out to the Collector. The first 10 GiB each month are free. See <a href="https://cloud.google.com/pubsub/pricing" target="_blank" rel="noopener noreferrer nofollow">Pub/Sub pricing</a>.
- **Monitoring API, metrics (both methods):** **$0.01 per 1,000 read calls**, with the first 1 million read calls free per billing account each month. Write calls are free. See <a href="https://cloud.google.com/stackdriver/pricing" target="_blank" rel="noopener noreferrer nofollow">Cloud Monitoring pricing</a>.

<Admonition type="info">
One-Click Integration sends a **copy** of your logs to SigNoz. Your logs still land in GCP's built-in `_Default` log bucket, which Cloud Logging bills as before. If you don't need to keep those logs in GCP too, you can add an exclusion filter to the `_Default` sink. See <a href="https://cloud.google.com/logging/docs/routing/overview" target="_blank" rel="noopener noreferrer nofollow">Cloud Logging routing</a>.
</Admonition>
