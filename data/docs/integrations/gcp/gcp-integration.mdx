The **SigNoz GCP Integration** brings metrics and logs from your Google Cloud services into SigNoz. Each supported service comes with a ready-made dashboard.

This release uses a **manual flow**: you create and own the GCP resources (a service account, an OpenTelemetry Collector, and, for logs, a Pub/Sub topic and log sinks). SigNoz guides you through each resource with the docs in this section. The **SigNoz agent** setup is coming soon.

<Admonition type="info">
The GCP integration is available on **SigNoz Cloud** and **SigNoz Enterprise (Self-Hosted)**. Traces are **not** part of this integration. Send traces by [instrumenting your applications](https://signoz.io/docs/instrumentation/) directly.
</Admonition>

<Admonition type="info">
In SigNoz, only the **Admin** role can connect, update, or disconnect a cloud account by default. Editors and Viewers can view connected accounts and their services. See the [Transactions Reference](https://signoz.io/docs/manage/administrator-guide/iam/reference/transactions/#cloud-integration) for the exact scopes.
</Admonition>

## How it works

GCP does not send your data to outside tools on its own. So SigNoz uses an **OpenTelemetry Collector**, a small program that runs **inside your GCP project**, to gather the data and send it to SigNoz over OTLP.

- **Metrics** live in **Cloud Monitoring**. Every few minutes, the Collector reads them with the <a href="https://github.com/open-telemetry/opentelemetry-collector-contrib/tree/main/receiver/googlecloudmonitoringreceiver" target="_blank" rel="noopener noreferrer nofollow">`googlecloudmonitoring`</a> receiver.
- **Logs** live in **Cloud Logging**. A **log sink** (a rule that picks which logs to forward) sends matching logs to a **Pub/Sub topic** (a message queue). Pub/Sub then pushes them to the Collector. Create this pipeline by following [Collect logs](https://signoz.io/docs/integrations/gcp/collect-logs/).

The integration runs the Collector inside your GCP project. There, it signs in to Google Cloud with a service account in your project, so you never share GCP credentials with SigNoz. It also keeps your data inside GCP until it leaves for SigNoz.

<Admonition type="info">
These guides use **Cloud Run** for the Collector, but it is **not required**. The `googlecloudmonitoring` receiver works anywhere it can find Google Cloud credentials through <a href="https://cloud.google.com/docs/authentication/application-default-credentials" target="_blank" rel="noopener noreferrer nofollow">Application Default Credentials</a>, such as a Compute Engine VM, GKE, or an existing Kubernetes cluster. For logs, Pub/Sub must also be able to reach the Collector over HTTPS.
</Admonition>

You deploy the Collector yourself and edit its config each time you add a service. For logs, you also create the Pub/Sub topic and log sinks, and update the sink filter when you add a service.

## Costs to expect

The manual flow runs resources in your GCP project, so GCP bills you for them, not SigNoz. Plan for:

- **Cloud Run (Collector):** roughly **~$110/month** for a Collector sized at 2 vCPU and 4 GiB running all the time. You pick the size, so for low volumes you can choose something smaller (for example, 1 vCPU and 1 to 2 GiB). See <a href="https://cloud.google.com/run#pricing" target="_blank" rel="noopener noreferrer nofollow">Cloud Run pricing</a>.
- **Pub/Sub (logs):** roughly **$80 per TiB** of logs. Pub/Sub charges $40 per TiB each time data passes through it, and every log passes through twice: once on the way in and once on the way out to the Collector. The first 10 GiB each month are free. See <a href="https://cloud.google.com/pubsub/pricing" target="_blank" rel="noopener noreferrer nofollow">Pub/Sub pricing</a>.
- **Monitoring API (metrics):** **$0.01 per 1,000 read calls**, with the first 1 million read calls free per billing account each month. Write calls are free. See <a href="https://cloud.google.com/stackdriver/pricing" target="_blank" rel="noopener noreferrer nofollow">Cloud Monitoring pricing</a>.

<Admonition type="info">
Your log sink sends a **copy** of your logs to SigNoz. Your logs still land in GCP's built-in `_Default` log bucket, which Cloud Logging bills as before. If you don't need to keep those logs in GCP too, you can add an exclusion filter to the `_Default` sink. See [Avoid paying twice for logs](https://signoz.io/docs/integrations/gcp/collect-logs/#step-8-avoid-paying-twice-for-logs).
</Admonition>
